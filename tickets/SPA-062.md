# SPA-062: Model seam for a review - cached context, token budget, recording wrapper

**Goal.** G-006 deliverable 1 and criteria 9, 10: "A request can carry a shared, cacheable context block placed before the agent's own instructions, so the seven analysts share one cached pool bundle. A budget wraps any `ModelClient` and enforces token caps. A recording wrapper writes every exchange as a `Recording` file so a live run becomes a test fixture."

## Scope

- Files or modules expected to change: `agent/src/main/kotlin/spa/agent/model/` (`ModelMessages.kt`, `AnthropicModelClient.kt`; new `BudgetedModelClient.kt`, `RecordingModelClient.kt`, `TokenEstimate.kt`); tests in `agent/src/test/kotlin/spa/agent/model/`.
- Not in scope: anything under `spa.agent.review`, the CLI, `core`, prompts, config files, the README.
- Dependencies this ticket may add: none (the Anthropic SDK 3.0.0 is already in `agent/build.gradle.kts`).

## Background the Developer needs

- Files to read: `agent/src/main/kotlin/spa/agent/model/ModelClient.kt`, `ModelMessages.kt`, `AnthropicModelClient.kt`, `ReplayModelClient.kt`, `agent/src/main/kotlin/spa/agent/ApiKey.kt`, and their tests under `agent/src/test/kotlin/spa/agent/model/` and `ApiKeyTest.kt`. JDK 21 is at `C:\Program Files\Eclipse Adoptium\jdk-21.0.13.9-hotspot`; set `JAVA_HOME` to it if the gate cannot find a JDK.
- From the goal: "Model calls happen only in the agent layer"; "The key is read from `ANTHROPIC_API_KEY` by `ApiKey` and nowhere else; nothing is stored, logged, recorded or printed. A recording holds the request and response only." "Tests never use the network. Fake client or `ReplayModelClient` only."
- From the goal (the plan this seam serves): seven analyst requests share one pool bundle text as the first, cacheable system block, then each has its own instructions. The first analyst is sent and answered alone (writing the cache), then six more are sent in parallel from several threads. Token caps are per review: 300,000 input (cache reads counted in full) and 60,000 output.
- Current state: `ModelRequest(model, maxTokens, system, userMessage)` is the replay key (all fields equal); `ModelUsage` already has `cacheReadInputTokens` and `cacheCreationInputTokens`; `AnthropicModelClient.toParams` builds `MessageCreateParams` with `.system(request.system)`.
- Design this ticket fixes (do not redesign):
  - `ModelRequest` gains `cachedContext: String? = null` and `label: String = ""` (both after the existing fields, with defaults, so every existing call and every existing recording file still works). `cachedContext` is shared text sent as the first system block with ephemeral cache control; `system` stays the agent's own instructions and follows it as a second block with no cache control. `label` names the caller (an agent id such as `curve`, or `curve-retry1`); it is never sent to the API and it is part of equality like every field.
  - With `cachedContext == null`, `toParams` must produce exactly what it produces today.
  - `TokenEstimate.of(request): Long` is `ceil(characters of cachedContext + system + userMessage, divided by 4)`, documented as a rough estimate.
  - `BudgetedModelClient(inner, maxInputTokens, maxOutputTokens)` is a `ModelClient`. Before sending it reserves, atomically, `TokenEstimate.of(request)` input tokens and `request.maxTokens` output tokens; if either reservation would pass its cap, it sends nothing and throws `BudgetExceededException` (a plain exception, not an `AssertionError`) whose message is one line: `budget: input cap would be passed (<used + needed> of <cap>)` or `budget: output cap would be passed (<used + needed> of <cap>)`. After the response it replaces the reservation by the actual usage: input counts `inputTokens + cacheReadInputTokens + cacheCreationInputTokens`, output counts `outputTokens`. If the inner client throws, the reservation is released. It exposes `totals: UsageTotals` (calls sent, input, output, cache read, cache write, as separate numbers; `input` here is the API's `inputTokens`, the cache numbers are separate) and is safe to call from several threads: two parallel calls can never both pass a cap that only one fits.
  - `RecordingModelClient(inner, directory)` is a `ModelClient` that sends through `inner` and, after each successful response, writes a `Recording(request, response)` as JSON to `<directory>/<label>.json` (or `<NN>.json`, two digits counting calls, when the label is empty); it creates the directory; a failed send writes nothing; two sends with the same label overwrite nothing: the second fails with an `IllegalStateException` naming the file. `ReplayModelClient.fromDirectory` must read what it writes.

## Acceptance criteria

1. `ModelRequest` has `cachedContext: String? = null` and `label: String = ""`; a recording file written before this ticket (the files under `agent/src/test/resources/spa/agent/replay/`) still decodes and replays; two requests that differ only in `cachedContext` or only in `label` are different replay keys.
2. `AnthropicModelClient.toParams` for a request with `cachedContext` has two system text blocks, the first the context with ephemeral cache control, the second `system` with none; for a request without it, the params equal what the existing test pins; `label` appears nowhere in the params.
3. `TokenEstimate.of` follows the rule above on a request of known lengths, including the `cachedContext == null` case.
4. `BudgetedModelClient` refuses (no inner call) when the input reservation would pass the cap, with the exact message above; likewise for output; and sends when the reservation exactly equals the cap.
5. After a response, `totals` holds the sum of the actual usage of the calls sent, and the reservation is replaced by actual usage (a call estimated at 1,000 input tokens that used 200 leaves room for a later 800).
6. A failing inner call releases its reservation and is counted in no total.
7. With 8 threads calling a fake inner client against a cap that fits 3 calls, exactly 3 are sent and 5 throw `BudgetExceededException`, on every one of 20 repeated runs.
8. `RecordingModelClient` writes `<label>.json` that decodes to the same `Recording` that was exchanged and replays through `ReplayModelClient.fromDirectory`; an empty label gives `01.json`, `02.json`; a failed send writes nothing; a repeated label throws as above; the file holds only the request and response (a test decodes it and checks the JSON keys are exactly `request` and `response`).
9. The gate is green: format, lint, compile, unit tests, coverage 80 or more on the touched files, no new dependency.
