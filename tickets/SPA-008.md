# SPA-008: Build the seeded set baseline so every metric has a typical value

**Goal.** G-001 deliverable 5's last clause: "a set baseline computed by simulating kits from the set's rarity and slot distribution, so every count is reported beside the typical value for a pool from this set." Goal-level criterion 6: "The set baseline for the target set is reproducible: the simulation is seeded, and its output is pinned by a golden file."

## Dispatch precondition (Architect checks before dispatch)

`fixtures/briefs/trk.json` exists on `main` and loads (same as SPA-007).

## Scope

- Files or modules expected to change:
  - `core/src/main/kotlin/spa/core/baseline/**` (`MetricFlattener`, `Stat`, `Baseline`, `BaselineBuilder`, `BuildBaselineMain`), a `buildBaseline` task in `core/build.gradle.kts`
  - `core/src/test/kotlin/spa/core/baseline/**`
  - `fixtures/baselines/trk.json`, `fixtures/baselines/syn.json`, `fixtures/baselines/README.md`
- Not in scope:
  - Printing the baseline beside a pool's metrics (SPA-009 does that in the CLI output).
  - Changing `PoolMetrics` or the sampler. If a field cannot be flattened, that is a bounce.
- Dependencies this ticket may add (none unless listed):
  - (none)

## Definitions

- JDK: if `java -version` does not report 21 in your shell, run `export JAVA_HOME="/c/Program Files/Eclipse Adoptium/jdk-21.0.13.9-hotspot"; export PATH="$JAVA_HOME/bin:$PATH"` first. The gate is `pipeline/gate/run.sh`; see the README's Toolchain section. A new or scratch file must also pass detekt's default rules.
- Rarity of a bonus-sheet card: an `sds` card counts by its own printed rarity in every metric, as SPA-006 already does (they are mythic printings). The baseline needs no special case. Note in `fixtures/baselines/README.md` that a trk pool's typical rare-plus-mythic count includes bonus-sheet cards.
- The baseline uses the brief only through `KitSampler`, which reads only its kit template. It never reads archetypes or card names (G-001 human decision, 2026-11-03).
- Flattening: `MetricFlattener.flatten(metrics: PoolMetrics): Map<String, Double>` encodes the metrics to JSON and walks it, producing one entry per numeric leaf keyed by its JSON pointer (for example `/pairs/WU/curve/buckets/2/creatures` or `/byColor/R/cards/common`, following the JSON exactly as SPA-006 serializes it). Non-numeric leaves (names in splash candidates, fixing source names) are dropped; list lengths of dropped lists are kept as `<pointer>/count`.
- `Stat(median, p10, p90, mean)` over the sampled kits, percentiles by the nearest-rank method, values rounded to 4 decimals.
- `Baseline(setCode, briefVersion, cacheFetchedAt, seed, kits, stats: Map<String, Stat>)`.

## Acceptance criteria

1. `BaselineBuilder(index, brief).build(seed, kits): Baseline` samples `kits` pools with `KitSampler` using seeds `seed, seed + 1, ..., seed + kits - 1`, computes `PoolMetrics` for each, flattens, and aggregates every pointer that appears in any kit (missing values count as 0). `kits` must be at least 100, else an `IllegalArgumentException`.
2. The same `seed` and `kits` give a `Baseline` equal field for field; a different seed gives a different `stats` map. Proven on `syn` with 100 kits.
3. `./gradlew :core:buildBaseline -Pset=trk -Pseed=20261106 -Pkits=2000` writes `fixtures/baselines/trk.json`; the same for `syn` with seed 1 and 500 kits writes `syn.json`. Both are committed. The JSON is pretty-printed with keys sorted, so a diff is readable.
4. A golden test rebuilds each committed baseline with the parameters stored inside the file and asserts byte-for-byte equality with the file after normalizing line endings. The `trk` rebuild takes under 60 seconds on CI.
5. Every pointer present in `MetricFlattener.flatten` of any kit is present in `stats`; in particular all ten pairs, all seven color buckets, and every curve bucket appear in `trk.json`. Pinned sanity values in a test on `trk.json`: `/totalCards` median is 85, the kit template's card total (6 boosters of 14 plus the promo). `/basicLands` has median 5, p10 4, p90 6, and mean 4.8 within 0.05. That is exact for this template, because only the Land slot can yield a basic, at 4 in 5, so basics per kit follow Binomial(6, 4/5); computed with exact fractions. Every pair's `/cards` median is between 15 and 45. `basicLandsSupplied` means basics are also handed out at the event, and has no effect on the basics sampled inside boosters.
6. `fixtures/baselines/README.md` states the seed and kit count per set, that a baseline is rebuilt only by a ticket (because refreshing the Scryfall cache or the brief changes it), and what the fields mean.

## Change note

- Added `spa.core.baseline`: `MetricFlattener` (JSON pointer per numeric leaf; a list holding any non-numeric leaf, or empty, is kept only as `<pointer>/count`, so `/fixingSources/count` and `/pairs/*/splashCandidates/count`, never index-keyed entries), `Stat` (nearest rank, 4 decimals), `Baseline` (sorted-key pretty JSON), `BaselineBuilder` (plus `load(scryfallDir, briefsDir, set)`, which sets `cacheFetchedAt` to the latest fetch time of the set's caches, trk and sds for trk), `BuildBaselineMain`, the `buildBaseline` task, and `spa.baseline.fixtures` on the test task.
- Committed `trk.json` (seed 20261106, 2000 kits) and `syn.json` (seed 1, 500 kits), 448 pointers each. The trk golden rebuild takes about 11 s locally. Every pair's `/cards` median is 29; `/basicLands` is median 5, p10 4, p90 6, mean 4.8.
- Chose not to add a constructor parameter beyond the ticket's `(index, brief)`, except an optional `cacheFetchedAt` (default empty), which the builder cannot derive from the index.
- For SPA-009: read a baseline with `Baseline.decode` and look up the same pointers `MetricFlattener.flatten` gives for the user's pool; a pointer missing from a pool means 0.
