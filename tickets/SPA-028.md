# SPA-028: Declare README.md as an input of the app's unit tests

**Goal.** G-002 deliverable 6 and spec item B1: the About screen's attribution must match the README's "Card data" section word for word. SPA-020's test `theAttributionIsTheReadmesFirstTwoCardDataSentencesWordForWord` reads `README.md` at run time, but `app/build.gradle.kts` (lines 40 to 41) declares only `fixtures/` as an input of the unit-test tasks. So a change to README.md alone leaves `:app:testDebugUnitTest` UP-TO-DATE in a local build directory, and the local gate can pass without re-checking B1. CI is unaffected (build cache off, fresh checkout). The SPA-020 Test Inspector found this.

## Scope

- Files or modules expected to change:
  - `app/build.gradle.kts`: inside the existing `all { }` block for unit tests, declare `rootProject.file("README.md")` as a task input, beside the `fixtures` input, with a property name and relative path sensitivity
- Not in scope:
  - `README.md` itself, any test source, any other input or build setting
  - The `spa.fixtures` system property and the Robolectric arguments
- Dependencies this ticket may add (none unless listed):
  - (none)

## Background the Developer needs

- JDK and Android SDK exports as in `tickets/SPA-026.md`'s Background. The gate is `pipeline/gate/run.sh`.
- Work on a local branch named exactly `SPA-028` (the pre-push hook reads the ticket from the branch name).
- This PC runs one Developer at a time.

## Acceptance criteria

1. After a successful `./gradlew :app:testDebugUnitTest`, appending a character to README.md and running the same command again re-runs the task: it is not reported UP-TO-DATE, and `--info` names README.md as the changed input. Restore README.md afterwards.
2. With README.md unchanged, a second run of `./gradlew :app:testDebugUnitTest` is UP-TO-DATE, so the input adds no needless re-runs.
3. `git diff origin/main --stat` lists only `app/build.gradle.kts` and this ticket.
4. The gate is green.

## Test plan

Criteria 1 and 2 concern Gradle's task-input bookkeeping, which a unit test inside the task cannot observe; the build scenario is the proof.

## Change note

- `app/build.gradle.kts`: the unit-test `all { }` block now declares `rootProject.file("README.md")` as an input file, property name `readme`, `PathSensitivity.RELATIVE`, beside the `fixtures` input. Nothing else changed: no test source, no README edit, no other input.
- Criterion 2, run by the Developer: two runs of `./gradlew :app:testDebugUnitTest` with no change; the second printed `> Task :app:testDebugUnitTest UP-TO-DATE`.
- Criterion 1, run by the Developer: appended `x` to README.md and ran with `--info`; it printed `Task ':app:testDebugUnitTest' is not up-to-date because:` then `Input property 'readme' file ...\README.md has changed.` and re-ran the tests (BUILD SUCCESSFUL; the trailing `x` sits outside the Card data sentences, so B1 still passed). README.md restored with `git checkout`; `git status` then showed it clean.
- No unit test: the criteria concern Gradle's input bookkeeping, which a test running inside the task cannot observe, as the test plan says.
