# SPA-021: Accept CSV files shared to the app or opened with it

**Goal.** G-002 deliverable 3, second bullet: "Share a CSV to the app from another app (ManaBox, Files, Drive, Gmail), as the design brief requires: the app registers as a share target and as an 'Open with' handler for CSV files." Also goal criterion 6.

The design sections this ticket implements: Navigation flow (the "share / Open with" lines and the rules for a share arriving while the app is open, latest import wins), and Decision 5.

## Scope

- Files or modules expected to change:
  - `app/src/main/AndroidManifest.xml`: intent filters on `MainActivity`, and its launch mode if needed
  - `app/src/main/kotlin/spa/app/MainActivity.kt`: reading `ACTION_SEND` and `ACTION_VIEW` intents at launch and in `onNewIntent`
  - `app/src/main/kotlin/spa/app/PoolViewModel.kt`, only to add an entry point for an incoming URI, if `analyzeFile(uri)` from SPA-017 does not already serve
  - `app/src/main/kotlin/spa/app/nav/SpaNavHost.kt`, only if the navigation rules for an import that arrives by share or Open with (from any screen, Pair detail and About included) need it, and only for that
  - `app/src/test/kotlin/spa/app/share/**`
- Not in scope:
  - Shared plain text (`EXTRA_TEXT`) and any MIME type not listed in criterion 1.
  - Backup rules and the remembered pool (SPA-022), even though it edits the same manifest.
  - Any screen's layout, any error card's copy (SPA-017's), and any change in `core/`, `cli/`, `fixtures/`, `importing/`, or `data/`.
- Dependencies this ticket may add (none unless listed):
  - (none)

## Acceptance criteria

1. The merged manifest gives `MainActivity` two intent filters with category `DEFAULT`: `android.intent.action.SEND` and `android.intent.action.VIEW`, each for the MIME types `text/csv`, `text/comma-separated-values`, and `application/csv`. `"$ANDROID_HOME"/build-tools/*/aapt2 dump xmltree --file AndroidManifest.xml app/build/outputs/apk/debug/app-debug.apk` shows both.
2. Launching `MainActivity` with an `ACTION_SEND` intent whose `EXTRA_STREAM` is a content URI for `trk-manabox-01.csv` lands on Results, with the source "trk-manabox-01.csv" and the card and entry counts read from its golden, and the back stack holds Results only. The same holds for an `ACTION_VIEW` intent with that URI as its data. Robolectric tests.
3. A share that arrives while the app is open (through `onNewIntent`), on any screen and during another import, starts a new import and replaces the stack. Only the newest import's result is shown. Robolectric test: share `trk-manabox-01.csv`, then before it completes share `trk-manabox-02.csv`; Results shows `trk-manabox-02.csv`.
4. A shared file that fails to import (a 0-byte CSV) lands on Pool with SPA-017's "This file is empty" card, and the back stack holds Pool only. A share or view intent with no URI, or a URI that cannot be opened, shows "Couldn't read this file", not a crash. Robolectric tests.
5. On `spa-test`, with `trk-manabox-01.csv` pushed to `/sdcard/Download/`: sharing it from the Files app to Sealed Pool Analyzer, and separately choosing Sealed Pool Analyzer from Files' "Open with", each lands on Results with the total cards, entries, unresolved count, removal total, and interaction total that `spa analyze fixtures/pools/trk-manabox-01.csv --set trk` prints. Sharing a second file while Results is open replaces it. `adb logcat -d` holds no `FATAL EXCEPTION` for `spa.app`.

## Change note

- `MainActivity` has SEND and VIEW filters for the three CSV types and `launchMode="singleTask"`, so a share while the app is open reaches `onNewIntent` instead of stacking a second copy in the sender's task. It reads `EXTRA_STREAM` (then the first clip) or the data, at launch only when not re-created (rotation does not re-import), and on every new intent; `PoolViewModel` is now taken with `by viewModels` so the Activity can hand it the URI.
- `PoolViewModel.importIncoming(uri)` reuses `analyzeFile` (latest import wins) and marks the import in `incomingImport`; `SpaNavHost` consumes the mark and navigates to a fresh Results entry with the whole stack popped (not single-top, so a Results entry that already handled a failure cannot swallow the next one). Failure routing is SPA-017's unchanged: Pool only when no pool is current, Pool on top of Results when one is (decision 5).
- An intent with no URI has no file name; the card says "The shared file couldn't be opened as text." (`NO_FILE_NAME`, a Kotlin constant, because string resources are outside scope).
- Not done: a URI with no provider behind it is not tested under Robolectric, whose resolver returns a stream that throws `UnsupportedOperationException` instead of the device's `FileNotFoundException`; the unreadable case is covered by a provider that has no such document. Criterion 1 and 5 are device checks; `ShareFiltersTest` additionally proves the filters through the PackageManager.
