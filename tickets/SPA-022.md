# SPA-022: Remember the last pool across launches, and add Clear pool

**Goal.** G-002 deliverable 7: "The app keeps exactly one pool, the last one imported, across launches ... in one file in the app's private storage (`Context.filesDir`). Nothing else is stored, and the metrics are computed again from that text on launch ... The owner clears it with a 'Clear pool' action ... the app opts its data out of Android's cloud backup and device-to-device transfer." Also goal criterion 16.

The design sections this ticket implements: Decisions 1, 5, and 7, Navigation flow (launch with a remembered pool, Clear pool), Pool screen state "Error: saved pool unreadable", Results screen state "Clear pool dialog open" and the header's Clear pool button, Component map (`ClearPoolButton`, `ClearPoolDialog`), and the accessibility items A1, A4, A5, C1, and C2.

## Acceptance criteria

1. After a successful import, `filesDir/last-pool.json` holds exactly the keys `text`, `format`, and `source`, with the imported text, the format it was read as, and the source. After a failed import, the file is unchanged, byte for byte (decision 5). Importing a new pool replaces it. Unit tests on `PoolStore` and the ViewModel.
2. At launch with the file present, the app opens Results in Loading, re-imports the stored text with the stored format through `PoolImporter`, and shows the same Results as the original import (the same `ResultsUi`). A Robolectric test: import `trk-manabox-01.csv`, recreate the Activity and ViewModel over the same `filesDir`, and compare the two `ResultsUi`. At launch with no file, Pool shows its empty state.
3. A stored file that cannot be re-imported (a test seam: corrupt JSON, or text that now resolves no entries) opens Pool with the card "Your last pool couldn't be read" and the body "<source> was saved, but the app can't read it now.", plus a "Clear pool" button that deletes the file with no further confirmation. Compose UI test.
4. Clear pool. The header's "Clear pool" button opens the dialog titled "Clear this pool?", body "The app will forget <source>. To see it again you'll need to import it again.", with the buttons "Keep pool" and "Clear pool", and no "OK" or "Cancel" (C1). "Keep pool", back, and a tap outside close it with the file untouched. "Clear pool" deletes the file and shows Pool's empty state, with the back stack holding Pool only and the snackbar "Pool cleared". Compose UI tests.
5. The merged manifest sets `android:allowBackup="false"` and `android:dataExtractionRules` to `@xml/data_extraction_rules`, whose `cloud-backup` and `device-transfer` sections each exclude every domain the app has (at least `file`, `database`, `sharedpref`, and `root`). `"$ANDROID_HOME"/build-tools/*/aapt2 dump xmltree --file AndroidManifest.xml app/build/outputs/apk/debug/app-debug.apk` shows both attributes. A unit test parses `data_extraction_rules.xml` and asserts the exclusions.
6. Snapshots from the spec's list, with A1, A4, and A5 run on the same state: `pool_errorSavedPoolUnreadable` and `results_clearPoolDialog` (`trk-manabox-01.csv`, dialog open). Baselines committed. `results_loading` uses a remembered pool, as in the background.
7. Goal criterion 16 on `spa-test`:
   - Import `trk-manabox-01.csv` with "Open file", run `adb shell am force-stop spa.app`, and relaunch. The same pool and results show without re-importing, with the total cards, entries, unresolved count, removal total, and interaction total that `spa analyze fixtures/pools/trk-manabox-01.csv --set trk` prints.
   - The same after `adb reboot`.

   - "Clear pool", then "Clear pool" in the dialog, then force-stop and relaunch: the empty Pool screen shows, and `adb shell run-as spa.app ls files` does not list `last-pool.json`.
   - C2: with TalkBack on and the dialog open, swiping never reaches Results content.

## Change note

- `PoolStore` (new, `store/`) writes `filesDir/last-pool.json` with exactly `text`, `format`, `source` (`pasted` or the file name), using a temp file and then an atomic move. `PoolViewModel` saves `Success.text` synchronously after each successful import (the file is small, and it is on disk before Loaded shows). At construction it re-imports the saved file through the same `Importer`, and `PoolViewModel.factory` builds the store from `APPLICATION_KEY`. `SpaNavHost` starts on Results when `startsWithSavedPool` is true. A re-read that fails becomes `ImportFailed(SAVED_POOL_UNREADABLE, source)` and moves to Pool alone, as other failed imports do. A file too damaged to name a source goes straight to Pool, with the source `PoolViewModel.UNNAMED_SAVED_POOL` (`File("")`), and the card reads "Your pool was saved, but…" (re-plan 2).
- Clear pool: the header's outlined pill opens `ClearPoolDialog` (M3 `AlertDialog`; it stays open across rotation through `rememberSaveable`). Confirming clears the file, the pool, the paste box and the format, replaces the stack with Pool, and shows the "Pool cleared" snackbar. The `SnackbarHost` lives in `SpaNavHost`. The unreadable card's "Clear pool" deletes the file with no dialog. A pasted pool is "the pasted text" in the dialog body and "The pasted text" at the start of the card body.
- Baselines re-recorded as authorized: `results_clean`, `results_clean_fontScale200`, `results_problems`, `results_problems_fontScale200`, and `results_wrongSetLines` gain only the "Clear pool" pill beside "New pool". `results_loading` now shows the source "trk-manabox-01.csv" instead of "Pasted". New baselines: `pool_errorSavedPoolUnreadable` and `results_clearPoolDialog`; the dialog is captured with `captureScreenRoboImage`, because it is a separate window. No other baseline changed.
- Not done: no I/O dispatcher for the file (it is read and written on the main thread). The intent filters, `MainActivity`, `SpaApplication` and `PoolUiState.kt` are unchanged. Criterion 7 (spa-test, TalkBack C2) is for the Acceptance Tester. The backup exclusion can only be checked on the device with `aapt2` and `adb shell bmgr`, not in a unit test.
