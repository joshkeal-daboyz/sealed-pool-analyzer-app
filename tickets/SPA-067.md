# SPA-067: Archetype Matcher and Synergy Detector

**Goal.** G-006 deliverable 4, analysts six and seven: "Archetype Matcher: which of the set's designed archetypes the pool supports, signposts present, pieces missing. Synergy Detector: which of the set's synergy axes (G-005's tags) have enablers and payoffs in the pool, and the strongest partners." And, from "Where this departs from the design brief": the Synergy Detector "reads G-005's tag file (axes, roles, pair scores) and says nothing about a set with no tag file (it goes on the Missing line)".

- Files or modules expected to change: new `agent/src/main/kotlin/spa/agent/review/agents/ArchetypeAgent.kt` and `SynergyAgent.kt`; `review/ReviewInput.kt` (one new optional field and the `SynergyView` class, new file `SynergyView.kt`); `AnalysisAgents.kt`; resources `archetypes-v1.md` and `synergy-v1.md` under `agent/src/main/resources/spa/agent/review/`; `fixtures/agents/review.json` (two entries added); tests in `agent/src/test/kotlin/spa/agent/review/agents/`.

- Dependencies this ticket may add: none.

- From the design brief, the two questions (use these sentences as the first paragraph of each prompt file, word for word):
  - Archetype Matcher (`archetypes`, title `Archetypes`): "Which of the set's designed archetypes does this pool support? Say, for each of the ten color pairs, how well the pool fits the pair's designed archetype, which signpost uncommons and key commons are present, and what is missing."
  - Synergy Detector (`synergy`, title `Synergy`): "Which mechanics and tribes have both enablers and payoffs here? Say which of the set's synergy axes the pool supports, with how many enablers and payoffs, and which cards work best together."
- Design this ticket fixes (do not redesign). Each agent is an `object` implementing `AnalysisAgent`:
  - **archetypes** `unavailable`: null. `numbers`: for each of the brief's archetypes, its pair is the `ColorPair` of its two colour letters in either order; the entries, in `ColorPair` order, are `/archetypes/<pair>/signpostsPresent`, `/archetypes/<pair>/signpostsTotal`, `/archetypes/<pair>/keyCommonsPresent`, `/archetypes/<pair>/keyCommonsTotal` (a signpost or key common is present when a pool card's full name, or the front-face name of a multi-face card, equals it exactly; each name counts once whatever its copies; the totals are the list lengths), none with `typical`; then the entries `NumberTables.fromMetrics` gives for `/pairs/*/cards` and `/pairs/*/creatures`. `facts`: for each archetype in `ColorPair` order, `<pair> <archetype name>: signposts present: <names or none>; missing: <names or none>. Key commons present: <names or none>; missing: <names or none>.`
  - **synergy** gets its data from a new optional `ReviewInput` field `synergy: SynergyView? = null`. `SynergyView(tags: TagFile, table: SynergyTable, idOf: (Printing) -> String)` is a plain holder (the caller passes `GradingPool::id`). `unavailable` is `no synergy tags for this set` when `synergy` is null. A pool card is matched to its tag card by `idOf(printing)`; a pool card with no tag card is left out. An axis is in play when at least one pool card (by copies) has a role on it. `numbers`: for each axis in play, in the tag file's axis order, `/axes/<axis id>/enablers` and `/axes/<axis id>/payoffs`, the pool copies whose tag card has that role on the axis (a card with both roles counts in both); no `typical`. `facts`: `Axes in play:` then `<axis id> (<name>): <definition>` per axis in play; then `Strongest pairs in the pool:` and up to 10 lines `<score> <name> with <name>` over pairs of distinct tagged pool cards (and `<score> <name> with itself` for a card with two or more copies, its diagonal score) whose `table.score` is 1 or more, highest score first, ties by the two names in order; `none` when there are no such pairs.
  - **Prompt files**: at most 30 lines; the question above as the first paragraph; then, in your own words, what the table and facts hold, how to read enablers against payoffs (an axis with payoffs and no enablers is a trap; the reverse is wasted), and the findings a player acts on. No card name, set name or set code, and no digit.
  - `AnalysisAgents.ALL` becomes the SPA-066 list followed by `ArchetypeAgent`, `SynergyAgent`. Add to `fixtures/agents/review.json` `agents`, after the existing five, `{ "id": "archetypes", "enabled": true, "maxTokens": 3000, "prompt": "v1" }` and the same for `synergy`.

## Acceptance criteria

1. Each agent has the id and title above; `ArchetypeAgent.unavailable` is null; `SynergyAgent.unavailable` is `no synergy tags for this set` for an input with no `synergy` and null with one.
2. `ArchetypeAgent.numbers` on a hand-built brief and pool: signposts and key commons present are counted by name once per name (a signpost held twice counts once), a front-face name counts for a multi-face card, an archetype written `UW` and one written `WU` both map to the pair `WU`, the totals are the list lengths (0 for an archetype with no key commons), and the `/pairs/*` entries equal the metrics' values worked out by hand.
3. `ArchetypeAgent.facts` equals the specified lines for those archetypes, including `none` in each of the four places.
4. `SynergyAgent.numbers` on a hand-built tag file, table and pool: only axes in play appear, in the tag file's order; a card with both roles on an axis counts in both numbers; copies count; an untagged pool card is left out; values worked out by hand.
5. `SynergyAgent.facts` equals the specified lines, including a card with two copies paired with itself, a pair scoring 0 left out, ties broken by names, the cap of 10, and `none` when no pair scores.
6. Each prompt file exists, is at most 30 lines, begins with its question sentence exactly, and contains no digit.
7. `AnalysisAgents.ALL` lists the seven ids in the order `colour-depth`, `curve`, `mana`, `interaction`, `bombs`, `archetypes`, `synergy`.
8. `fixtures/agents/review.json` stays valid JSON and its `agents` array holds the seven entries in order (Acceptance Tester scenario below).
9. The gate is green: format, lint, compile, unit tests, coverage 80 or more on the touched files, no new dependency.

## Change note

Added `ArchetypeAgent` and `SynergyAgent` (both `object`s), `SynergyView` (plain class), the optional `ReviewInput.synergy` field, the two v1 prompt files, and the two `review.json` entries; `AnalysisAgents.ALL` now lists seven ids. Criteria 1 to 7 are covered by unit tests (red commit first, compile-only red since the classes did not exist); 8 is the Acceptance Tester scenario; 9 is the gate.
Choices the ticket left open: a name in a pair line is ordered alphabetically (first, then second), and a card with itself sorts as the pair (name, name); an archetype whose colours map to no `ColorPair` is left out of numbers and facts; `SynergyAgent.numbers` is empty and `facts` is empty when `synergy` is null (the agent is then reported unavailable and not run); with no axis in play `facts` is `Axes in play:` followed straight by `Strongest pairs in the pool:`.
The pool is matched to tag cards through `synergy.idOf`, copies of printings sharing a tag id are summed. Nothing here builds a `SynergyView` from disk (SPA-069).
