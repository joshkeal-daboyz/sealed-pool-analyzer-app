# SPA-054: Scryfall oracle tags as facts, cares tags, and a cares term in the pair score

**Goal.** The owner said on 2026-11-05: "Cares about legendary is different from legendary itself", the tags carry plain names, and "Yes, don't reinvent the wheel". Scryfall publishes its community Tagger tags as a bulk file, Oracle Tags. This ticket:
- turns each card's Scryfall oracle tags into facts (`otag:<slug>`);
- turns Scryfall's "cares about" tags into `cares:<fact>` tags, through a curated table;
- adds a pluggable cares term to the pair score: one card's fact times the other card's cares strength for that fact.

Fable filling the gaps where Scryfall has no tag is the next ticket.

## Background the Developer needs

- Read the G-005 Architect notes from "Owner, on tags" onward, SPA-051 (`FactRule`, `FactSupplyTerm`), SPA-048 (`PairTerm`, `SynergyTable`) and SPA-053 (frozen test data). Scryfall's bulk index is `https://api.scryfall.com/bulk-data`; its `oracle_tags` entry gives a `jsonl_download_uri`. Each line is one tag: `slug`, `type` (`oracle`), `parent_ids`, `taggings` (`oracle_id`, `weight`).
- **`spa fetch-tags --set <code> [--bulk <file.jsonl or .jsonl.gz>]`.**
  - Without `--bulk`, it downloads the current Oracle Tags file to a cache folder outside `fixtures` (not committed, like other downloads). The network is used only here, never in tests.
  - It writes `fixtures/otags/<code>.json`: `{ "set", "source", "updatedAt", "attribution": "Card tags from Scryfall Tagger (tagger.scryfall.com)", "cards": [ { "id", "otags": [slugs] } ] }`.
  - Cards are the set's sealed pool (`GradingPool`) in collector order. Each card's `otags` are its own tags plus every ancestor through `parent_ids`, oracle tags only, sorted.
- **Generate the committed files** with `--bulk C:/Users/Josh/AppData/Local/Temp/claude/4def206f97af6599/efe9e1ff-6a68-481a-b5ce-0fb70c6c96d9/scratchpad/otag-bulk/oracle-tags.jsonl`, the 2026-11-05T22:00 file. The pinned numbers come from it. Scryfall updates the file daily, so a fresh download gives other numbers.
- **Facts.** `OtagFactRule` adds `otag:<slug>` for each of a card's tags, read from `fixtures/otags/<code>.json` (or `--otags <file>`). A set with no otags file gets no otag facts, and everything else works as before.
- **Cares.** For each of a card's otags that is a key in `fixtures/otags/cares.json`, the card gets `cares:<fact>` at the listed strength for each listed fact, keeping the largest strength when two tags give the same fact. A fact named in the table must be a known fact name: a code fact family, or `otag:<slug>` of a tag that exists in the bulk file. `fetch-tags` checks this and names every unknown one.
- **The cares term**, for cards a and b: Σ over a's facts f of `cares(b, f)` + Σ over b's facts f of `cares(a, f)`. A fact counts once, at strength 1. With a = b, the same formula applies, so it counts twice. It lives in `PairTerms.ALL`, and a set without an otags file scores exactly as before. `spa synergy-table` lines show the new `cares` part beside `axis`, `partner` and `fact` when it is nonzero.
- **Alterable.** The cares table is data. A new Scryfall tag is a new line in `cares.json`, with no code change.
- **Pinned numbers** come from an independent script (scratchpad `tools/cares.js`, with `tools/facts.js` for code facts, 2026-11-05).
- Work on a local branch named exactly `SPA-054`. One Developer at a time. Never rewrite a pushed branch; keep scratch files out of the repository. JDK: README, Toolchain section. On Windows Git Bash, pass `C:/...` paths to the JVM.
