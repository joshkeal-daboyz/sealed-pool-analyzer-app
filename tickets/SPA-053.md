# SPA-053: Freeze the v1 tag files for tests, so the live tag files can change

**Goal.** The v2 tags are ready (tags prompt v2 plus the Fable review, for `trk`, `msh`, `hob` and `fra`), but committing them turns the gate red. Tests from SPA-048, SPA-050, SPA-051 and SPA-052 pin numbers computed from the live `fixtures/tags/<code>.json` files: 12 failures, listed in History. The Architect's error: those pins were scripted on data meant to be replaced. This ticket:
- moves every such test onto frozen copies of the v1 files;
- adds a `--tags <file>` option to the synergy commands;
- proves the gate passes with the v2 files in place.

The Architect then commits the v2 files.

## Scope

- Files or modules expected to change:
  - `fixtures/tags/v1/trk.json`, `msh.json`, `hob.json`, `fra.json` (new): byte-for-byte copies of the current committed `fixtures/tags/<code>.json`, plus `fixtures/tags/v1/README.md` saying they are frozen test data, never edited
  - `cli/src/main/kotlin/spa/cli/`: `--tags <file>` on `synergy-table`, `synergy` and `synergy-check` (default `<data>/tags/<code>.json`), with help text
  - `cli/src/test/kotlin/spa/cli/**` and `agent/src/test/kotlin/**`: tests that read the content of a committed tag file switch to the frozen copies
  - `README.md`
- Not in scope:
  - Changing any pinned number, or any scoring or tagging behaviour. Committing the v2 files: the Architect does that after merge. `core`.
- Dependencies this ticket may add (none unless listed):
  - (none)
