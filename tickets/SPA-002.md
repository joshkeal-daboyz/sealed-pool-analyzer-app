# SPA-002: Load a set from Scryfall into a cached, normalized card index

**Goal.** G-001 deliverable 2: "A loader that fetches one set's cards from Scryfall by set code (the paginated search endpoint, cached locally as JSON), a normalized card model that handles double-faced, adventure, and split cards, and a `getSet(setCode)` query returning every card legal in that set's sealed pool. Scryfall attribution in the README." Goal-level criterion 2.

## Scope

- Files or modules expected to change:
  - `core/src/main/kotlin/spa/core/cards/**` (models, Scryfall DTOs, transport interface, fetcher, cache, normalizer, `CardIndex`)
  - `core/src/main/kotlin/spa/core/cards/FetchSetMain.kt` and a `fetchSet` task in `core/build.gradle.kts`
  - `core/src/test/kotlin/spa/core/cards/**`, `core/src/test/resources/scryfall/cards/*.json`
  - `fixtures/scryfall/trk/`, `fixtures/scryfall/sds/`, `fixtures/scryfall/syn/`, `fixtures/scryfall/README.md`
  - `README.md` (Scryfall attribution paragraph only)
- Not in scope:
  - Fuzzy or approximate name matching. Lookups are exact.
  - Parsing pool files (SPA-005), rules-text tagging (SPA-004), metrics (SPA-006).
  - Deciding sealed legality from Scryfall's `booster` flag; it is false for every `trk` card before release.
  - Any HTTP library. Use `java.net.http.HttpClient` behind an interface.
- Dependencies this ticket may add (none unless listed):
  - (none; `kotlinx-serialization-json` is already in the catalog from SPA-001)

## Background the Developer needs

- JDK: if `java -version` does not report 21 in your shell, run `export JAVA_HOME="/c/Program Files/Eclipse Adoptium/jdk-21.0.13.9-hotspot"; export PATH="$JAVA_HOME/bin:$PATH"` first. The gate is `pipeline/gate/run.sh`; see the README's Toolchain section. A new or scratch file must also pass detekt's default rules.
- Target set `trk` (Star Trek, expansion, `card_count` 581 on 2026-11-03). Companion set `sds` (Stardates, `set_type` `masterpiece`, `parent_set_code` `trk`, 30 cards) is part of the sealed pool. Do not include `trc`, `ttrk`, or `atrk`.
- Scryfall endpoints: `GET https://api.scryfall.com/sets/{code}` returns the set object including `card_count` and `search_uri`. Follow `search_uri` as given (it already carries `include_extras`, `include_variations`, `unique=prints`, `order=set`) and page through `next_page` while `has_more` is true.
- Scryfall requires a `User-Agent` header (`SealedPoolAnalyzer/<version> (https://github.com/joshkeal-daboyz/sealed-pool-analyzer-app)`) and `Accept: application/json`, and asks for at most 10 requests per second; wait at least 100 ms between requests.
- Package `spa.core`. The cache is the source of truth for tests; tests never reach the network.
- `trk` has no double-faced, adventure, or split cards. The layout tests use a synthetic set `syn` built from real Scryfall card objects of other sets.
- `Color` (the enum `W, U, B, R, G`) is defined by SPA-004 in `spa.core.text`. If SPA-004 has merged, use it; if not, define it in `spa.core.cards` with the same shape and say so in the change note so the Architect can reconcile.

## Acceptance criteria

1. `ScryfallTransport` is an interface with one JDK `HttpClient` implementation. `ScryfallSetFetcher(transport).fetch(code)` requests the set object, follows every search page, sends both headers above on every request, waits at least 100 ms between requests, and on HTTP 429 waits one second and retries that request up to three times before failing. Proven with a recording fake transport.
2. The cache for a set is `fixtures/scryfall/<code>/set.json` (the set object verbatim), `fixtures/scryfall/<code>/cards.json` (a JSON array of the card objects verbatim, in search order), and `fixtures/scryfall/<code>/fetched-at.txt` (ISO-8601 UTC timestamp). `ScryfallCache.load(dataDir, code)` reads those files and makes no network call, proven with a transport that throws.
3. `./gradlew :core:fetchSet -Pset=<code> [-PdataDir=<dir>]` writes that cache. The committed caches for `trk` and `sds` were produced by it, and a unit test asserts for each that `cards.json` has exactly `set.json`'s `card_count` entries.
4. `fixtures/scryfall/<code>/companions.json` lists companion set codes; `trk`'s is `["sds"]`, `sds`'s and `syn`'s are `[]`. `CardIndex.load(dataDir, "trk")` holds every printing of `trk` and of each companion; its printing count equals the sum of the cached `card_count` values, and `index.setCodes` is `[trk, sds]`.
5. The normalized model is: `Printing(scryfallId, setCode, collectorNumber, rarity, promoTypes, card)`, `Card(oracleId, name, layout, faces, colors, colorIdentity, manaValue, typeLine, isCreature, isLand, isBasicLand, rarity)`, `Face(name, manaCost, manaValue, colors, typeLine, oracleText, power, toughness)`. `name` is Scryfall's full name (with ` // ` for multi-face cards). Rules: for `transform`, `flip`, and `meld`, `colors`, `manaValue`, `typeLine`, and `isCreature` come from the front face; for `modal_dfc` and `adventure`, `manaValue`, `typeLine`, and `isCreature` come from the front face and `colors` is the union of the faces' colors; for `split`, `colors` is the union, `manaValue` is the smaller face's, `typeLine` is the faces' type lines joined with ` // `, and `isCreature` is false; for all other layouts the top-level Scryfall fields are used. `isLand` and `isBasicLand` follow the front face's type line. Printings of the same card share one `Card` instance by `oracleId`.
6. Unit tests cover, each from a real Scryfall card object stored under `core/src/test/resources/scryfall/cards/`: a normal creature, a transform card, a modal double-faced card, an adventure, a split card, a basic land, a nonbasic land, a colorless artifact, a hybrid-mana card, and a two-color card. Each test asserts the fields in criterion 5 that the layout rule affects.
7. The synthetic set `syn` is a committed cache (`set.json`, `cards.json`, `companions.json`, `fetched-at.txt`) whose `cards.json` holds at least 24 real Scryfall card objects from any sets, with `set` rewritten to `syn`, `set_name` to `Synthetic Test Set`, collector numbers renumbered 1 to N, and every other field (including `id` and `oracle_id`) unchanged. It contains at least 2 transform cards, 1 modal double-faced card, 2 adventures, 2 split cards, the 5 basic lands, 2 nonbasic lands, and at least 3 cards of each color. `set.json` has `code` `syn`, `card_count` N, and `set_type` `expansion`. `CardIndex.load(dataDir, "syn")` loads it; a unit test pins N and the layout counts.
8. `CardIndex` lookups are exact: `byScryfallId(id)` returns the printing or null; `byName(name)` matches the full name or any single face name, case-insensitively, after trimming and after mapping curly apostrophes to `'`, and returns the `Card` or null; `byCollectorNumber(setCode, number)` returns the printing or null; `cards` is the distinct `Card` list; `printings(setCode)` lists one set's printings. A misspelled name returns null. Unit tests for each, including a front-face name of a `syn` double-faced card.
9. `README.md` gains a Scryfall attribution paragraph: card data comes from Scryfall, the project is unofficial and not endorsed by Scryfall or Wizards of the Coast, a link to scryfall.com, and a note that the cache is a snapshot refreshed deliberately. `fixtures/scryfall/README.md` records the fetch date per set and the refresh command, and states that refreshing changes golden files and is done only by a ticket.
10. Live fetch: `./gradlew :core:fetchSet -Pset=sds -PdataDir=<temp dir>` against the real API produces a cache whose `cards.json` count equals `card_count`. This needs the network, so it is an Acceptance Tester scenario, skipped with a note if the network is unavailable.
