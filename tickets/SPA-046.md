# SPA-046: Measure the deck builder on 17Lands Sealed builds with spa deck-backtest

**Goal.** G-005 deliverable 6 and the measuring half of criteria 6 to 8. SPA-044 and SPA-045 build and rank decks. This ticket adds `spa deck-backtest`: it runs the builder on the pool of every strong player's build in a 17Lands Sealed file, of any colour count, and reports how often the builder agrees with the player. SPA-060 then tunes the weights with it. The same command measures the held-out set and the synergy part on against off.

- **Deck shape.** Two colours: `main_colors` has 2 letters and `splash_colors` is empty. Two plus a splash: 2 letters and a non-empty splash. Three or more main colours: 3 or 4 letters, splash or not. A build with 1 or 5 main colours is skipped, as is a build with an unresolved card name (a deck or sideboard name above 0 that resolves to no card of the set) or with no choice (no nonland candidate copies).
- **Quoted from the goal (G-005), deliverable 6:** "**The deck backtest: `spa deck-backtest --set <code>`.** For each strong player's build in a 17Lands Sealed file (G-004 Decided 2), of any colour count, the builder runs on that player's pool and reports these numbers, overall and by the player's deck shape (two colours, two plus a splash, three or more main colours):
  - **Colour agreement:** the top deck's main colours are the player's main colours.
  - **Top-three rate:** the player's main colours are among the top three decks'.
  - **Splash agreement:** the top deck splashes exactly when the player did.
  - **Main-deck overlap:** how many of the player's registered nonland cards the builder's deck in the player's colours also plays.
  - **Land count:** the builder's land count is within one of the player's.

  It also reports the same numbers for a baseline builder that uses set grades alone and two-colour pairs only."
- **The pool and the decks.** The player's pool is every deck and sideboard copy that is not a basic land (`Build.pool()` in `SealedBuilds` does this for its own type). For each build: run `DeckRanking` over all configurations (SPA-045) for the ranked list; and build the deck for the player's own configuration (`BuildConfig` of `main_colors` and `splash_colors`) with `session.builder.build(session.setup(pool, config))`, which is null when the pool cannot fill it (counted as unbuildable, left out of overlap and land count, still counted in the colour measures).
- **The five measures, exactly.**
  - Colour agreement: the top-ranked deck's main colours, as a set, equal the player's. Top-three: the player's main colours as a set equal those of one of the first three ranked decks. Splash agreement: the top-ranked deck has a splash if and only if the player's `splash_colors` is non-empty.
  - Main-deck overlap: for the builder's deck in the player's configuration, the sum over cards of the smaller of the builder's copies and the player's registered deck copies, counting nonland cards only. Report its mean, and the mean number of nonland cards the players registered.
  - Land count: the builder's land count in the player's configuration is within 1 of the player's registered land count (every deck copy of a land card, basics included).
  - A group's rate is the share of its builds the measure applies to; a build with no ranked deck at all counts as a miss for the first three.
- **The baseline.** The same builder with `fixtures/weights/deck-baseline.json`, a deck weights file (SPA-044's format) with `grades` 1 and every other weight 0, and `configs` holding `pairs` enabled and the other rules off. Its measures use its own top-ranked deck: colour agreement and top-three as above over its ranked pair decks; splash agreement as above (it never splashes); main-deck overlap and land count measured on its top-ranked deck against the player's registered cards and lands.
- **`spa deck-backtest <sealed-file> --set <code> [--limit <n>] [--threads <t>] [--weights <file>] [--baseline <file>] [--tags <file>] [--otags <file>] [--data <dir>]`.** `--weights` defaults to `fixtures/weights/deck-default.json`, `--baseline` to `fixtures/weights/deck-baseline.json`. `--limit n` keeps n builds spread evenly through the kept builds in file order (build i is the one at position `i * kept / n`); without it all are used. `--threads` defaults to 2 and must not change any number. Output, in this order, one line each, numbers as plain text:
  - `read <strong> strong builds: two <a>, splash <b>, multi <c>; skipped one-colour <x>, five-colour <y>, unresolved <z>, no-choice <w>`
  - `used <n> builds, unbuildable <u>`
  - for the builder, then for the baseline, four lines `<name> overall`, `<name> two`, `<name> splash`, `<name> multi`, each `n <count> colour <pct> top3 <pct> splash <pct> overlap <mean> of <mean registered> lands <pct>` (percent with one decimal, means with two)
  - `time <seconds> s, <builds per second> builds/s`

  A group with no builds prints `n 0` and dashes. A missing file, an unknown set, a bad number or a bad weights file is one line, exit 1.
- **Alterable.** The measures are a list of small objects, one file each, so a sixth measure adds a file and one list entry. The command runs any deck weights file.

## Acceptance criteria

1. **Reading.** Hand-built Sealed files on the synthetic set `syn` prove each case on its own: a bucket of 0.60 kept and 0.59 skipped; one build per `(draft_id, build_index)` from its first row; shapes two, splash and multi; a one-colour and a five-colour build skipped; an unresolved name skipped; no choice skipped; a plain and a gzipped file read the same.
2. **Measures.** Hand-built per-build data, with no builder in the loop, pins each measure and its edge: colour agreement is set equality (`WU` equals `UW`); top-three counts the player's colours at rank 3 but not rank 4; splash agreement both ways; overlap sums the smaller copy counts and ignores lands; land count within 1 (equal, 1 off, 2 off); an unbuildable build is left out of overlap and land count; the groups' counts add up to overall.
3. **The command.** On `syn` with a hand-built file, `spa deck-backtest` prints the lines of Background in order; `--limit` takes evenly spread builds and the same ones on every run; `--threads 1` and `--threads 2` print identical numbers; bad inputs are one line, exit 1.
4. **Baseline file.** `fixtures/weights/deck-baseline.json` loads as deck weights; a test shows the baseline's ranked decks are all two-colour pairs with no splash, and that its score equals the sum of the grades of the spells.
5. **Real data (Acceptance Tester).** The `read` line equals the table above for each of the three files; `--limit 60` on `hob` finishes and prints the 8 group lines.
6. **The seam, and no change elsewhere.** `git diff 2962b0f -- core/src/main fixtures/golden` lists no file. A test adds a test-only measure to the list and sees it in the output with no other code change. Every SPA-044 and SPA-045 test passes unchanged. The gate is green.
7. **Speed.** The change note records the builds per second for `--limit 200` on `hob` with the default weights, with 1 and with 2 threads.
