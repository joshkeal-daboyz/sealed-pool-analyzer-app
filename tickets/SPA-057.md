# SPA-057: Run only the gate a change needs locally; CI still runs it all

**Goal.** G-005's pace. The local gate builds and lints the Android app and runs every Roborazzi snapshot on every push, including pushes to `main` that change only ticket files. The owner approved three changes (2026-11-05): skip the gate for documentation-only pushes; skip the app's build, lint and ui-tests when no `app/` file changed, and run only the JVM modules a change can affect; keep the full gate on CI for every pull request and every push to `main`.

## Scope

- Files or modules expected to change:
  - `build-logic/src/main/kotlin/spa/gate/`: a new pure `GateScope` (which modules a change runs), `GatePlugin` (wire only those modules), `GateTasks` (the ui-tests skip note, the unit-tests note), `Git` if needed
  - `build-logic/src/test/kotlin/spa/gate/`: `GateScopeTest` and any test the wiring changes
  - `pipeline/gate/run.sh` (the docs-only skip and `--full`), `.githooks/pre-push` only if needed
  - `.github/workflows/gate.yml` (pass `--full`)
  - `pipeline/gate/README.md` (describe the scoping)
- Not in scope:
  - Any `core`, `agent`, `cli` or `app` source. Any step's pass or fail logic other than which modules feed it. Test-result or coverage formats. The tests-first order check (a later ticket).
- Dependencies this ticket may add (none unless listed):
  - (none)

## Background the Developer needs

- Read `pipeline/gate/README.md` and `build-logic/src/main/kotlin/spa/gate/` (GatePlugin, GateTasks, Git, UiTests).
- Module graph: `agent`, `cli` and `app` depend on `core`; `cli` depends on `agent`. `app`'s tests read `fixtures/` (an input of its test task).
- **Changed files** are what the coverage step already uses: `Git.changedSince(Git.mergeBase())`, the working tree against `merge-base origin/main HEAD` (falling back to `main`) plus untracked files. A push to `main` from `main` therefore sees only the commits being pushed.
- **Documentation paths:** a path under `tickets/` or `design/`, or any path ending in `.md`. These never select a module.
- **Scope rules**, applied to the changed files that are not documentation paths:
  - **Full gate** (every module, `app` and the `build-logic` tests included) when: `--full` / `-Pgate.full=true` is given; or the merge-base cannot be found; or any path is outside `app/`, `core/`, `agent/`, `cli/` and `fixtures/` (this covers `build-logic/`, `gradle/`, `config/`, `pipeline/gate/`, `.githooks/`, `.github/`, root build files, and anything new).
  - Otherwise, the JVM modules: `core/` or `fixtures/` changed gives `core`, `agent`, `cli`; else `agent/` gives `agent`, `cli`; else `cli/` gives `cli`.
  - `app` is in scope only when an `app/` path changed (or the gate is full). This is the owner's rule as approved: a `core` or `fixtures` change that breaks the app is caught by CI's full run before merge, not locally. Say so in the README.
  - No non-documentation change at all (an empty list) is the full gate, so a gate run directly through `./gradlew check` on an unchanged tree still checks everything.
- **Skipped modules** are not wired: none of their format, lint, compile, test or coverage tasks enter the task graph. The unit-tests step must read results only from the test tasks it ran (today it lists every project's test task and would report "No test results" for a skipped one). When `app` is out of scope the ui-tests step passes with the note `skipped: no app changes`, the way it already passes with `skipped: no app module`. No verdict `result` value is added.
- **Docs-only skip** belongs in `run.sh`, before Gradle starts, so it costs a second: if every changed file is a documentation path and `--full` was not given, `run.sh` writes `gate-verdict.json` with `"result": "pass"`, no failures, and each of the seven steps `"not_run"` with the note `skipped: docs-only change`, prints `Gate: skipped, only tickets, design or Markdown files changed.`, and exits 0. Its classification must match `GateScope`'s documentation paths.
- The reproduce commands in failures are unchanged (lesson SPA-013: they must run as printed).
- This branch changes `build-logic/`, so its own gate runs full.
- Work on a local branch named exactly `SPA-057`. One Developer at a time, never two gates at once. Never rewrite a pushed branch; keep scratch files out of the repository. JDK: README, Toolchain section. detekt runs on new files. The Gradle daemon is fine; never run `./gradlew --stop`.

## Acceptance criteria

1. `GateScopeTest` covers, each as its own case, with the module set it expects:
   - only documentation paths (`tickets/SPA-001.md`, `design/x.png`, `README.md`, `pipeline/roles/developer.md`): docs-only;
   - `cli/src/main/kotlin/A.kt` gives `{cli}`; `agent/...` gives `{agent, cli}`; `core/...` gives `{core, agent, cli}`; `fixtures/tags/trk.json` gives `{core, agent, cli}`;
   - `app/...` alone gives `{app}`; `app/...` with `cli/...` gives `{app, cli}`;
   - each full trigger alone gives the full gate: `build-logic/...`, `gradle/libs.versions.toml`, `pipeline/gate/run.sh`, `.github/workflows/gate.yml`, `settings.gradle.kts`, an unknown top-level folder, the full flag with only a `cli/` change, no merge-base, and an empty list;
   - documentation paths mixed with `cli/...` give `{cli}`.
2. On a scratch branch from this branch's head that changes one `cli/src/main` file, `./gradlew check -m` lists no `:app:`, `:core:` or `:agent:` task and no `build-logic` `test` task; a real run's verdict passes with ui-tests note `skipped: no app changes` and a unit-tests note that names the modules run (`modules: cli`).
3. The same with one `agent/src/main` file lists `:agent:` and `:cli:` tasks but no `:app:` or `:core:` task. With one `app/src/main` file, `:app:` tasks are listed.
4. `pipeline/gate/run.sh --full` and `./gradlew check -m -Pgate.full=true` run every module, the same task list as `main` today for `check -m`.
5. On a scratch branch that changes only `tickets/` and a `.md` file, `pipeline/gate/run.sh` exits 0 in under 5 seconds without starting Gradle, prints the skip line, and writes the verdict described in the Background. `run.sh --full` on the same branch runs the full gate. A push of that branch through the pre-push hook is not refused and does not start Gradle.
6. `.github/workflows/gate.yml` runs `pipeline/gate/run.sh --full`, so CI's gate on a pull request and on `main` runs every module. CI is green on this ticket's pull request.
7. `pipeline/gate/README.md` describes the documentation paths, the scope rules, the skip notes, `--full`, and that CI always runs full.
8. Every existing gate test passes unchanged, and the gate is green.
