## Output contract (the Acceptance Tester reads this)

`analyze` prints one JSON document to stdout and nothing else; diagnostics go to stderr. The document is:

```json
{
  "tool": { "name": "spa", "version": "<from gradle>" },
  "set": "trk",
  "pool": {
    "file": "<path as given>",
    "format": "MANABOX",
    "entries": 91,
    "skippedLines": 0,
    "unresolved": [ { "line": 12, "text": "...", "reason": "unknown-name" } ],
    "kitWarnings": [ { "code": "card-count", "expected": { "min": 85, "max": 85 }, "actual": 84, "message": "..." } ]
  },
  "metrics": { "...PoolMetrics as SPA-006 serializes it..." },
  "baseline": { "setCode": "trk", "seed": 20261106, "kits": 2000, "stats": { "/totalCards": { "median": 85.0, "p10": 85.0, "p90": 85.0, "mean": 85.0 } } }
}
```

`baseline` is `null` with `--no-baseline` or when no baseline file exists for the set, and stderr then says so. The numbers in the example are illustrative, not pins. `KitWarning.expected` is a range (SPA-005), written as `min` and `max`. `entries` counts resolved pool entries, so it is not the card total.

## Acceptance criteria

1. `./gradlew :cli:installDist` produces `cli/build/install/spa/bin/spa` and `spa.bat`. `spa --help` exits 0 and lists the commands; `spa` with no arguments or an unknown command prints usage to stderr and exits 2.
2. `spa analyze <pool-file> --set <code> [--format manabox|text|collector] [--data <dir>] [--no-baseline] [--brief <file>]` loads the card index from `<data>/scryfall` (default `fixtures`), the brief from `--brief` or `<data>/briefs/<code>.json`, the baseline from `<data>/baselines/<code>.json`, parses the pool (detecting the format unless given), and prints the output contract. Exit 0 when the file parsed, even with unresolved lines or kit warnings; exit 1 with a one-line stderr message when the file, set cache, or brief is missing or unreadable, or `--set` is absent; exit 2 for bad flags.
3. `spa validate-brief <file> --set <code> [--data <dir>]` exits 0 and prints `OK <file>` plus one `warning:` line per signpost or key-common name that `CardIndex.byName` cannot find in the set; exits 1 and prints every `BriefValidationException` error with its pointer when the brief is invalid.
4. `spa fetch-set <code> [--data <dir>] [--companions a,b]` refreshes the cache through SPA-002's fetcher and writes `companions.json`, printing the card count; exit 1 on a network or API error. (Network; Acceptance Tester scenario.)
5. Every fixture pool in `fixtures/pools/manifest.json`, run through `spa analyze` with its declared set, exits 0 and prints JSON that parses and has non-null `metrics` with ten pairs. Proven by a test in `cli/src/test` that invokes `Main.run(args, stdout, stderr)` in-process for each fixture.
6. For `trk-text-misspelled-01.txt`, the output's `pool.unresolved` lists exactly the manifest's expected lines, and `metrics.totalCards` equals the resolved count.
7. The JSON is produced by `kotlinx.serialization` with `prettyPrint = true` and stable key order (declaration order of the classes), so two runs on the same input are byte-identical.
8. `README.md`'s "Command line" section shows the install command and one example per command, and the Test Inspector finds it matches the behavior above.
