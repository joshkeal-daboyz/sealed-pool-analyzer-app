## Acceptance criteria

1. About shows, in this order: "Sealed Pool Analyzer"; "Version <versionName>"; "Card data snapshot: <date>"; the heading "Card data" (A6); and the two attribution sentences. The top bar has a back arrow described "Back" (A2) and the title "About".
2. B1: a test reads `README.md` at test time, takes the Card data section's first two sentences, reduces the Markdown link to its label, and asserts the About screen's attribution text equals that string exactly.
3. B2: the word "Scryfall" in the first sentence carries a link annotation to `https://scryfall.com`. Activating it starts an `ACTION_VIEW` intent for that URL (a Robolectric test checks the next started activity). Either the link meets A1's 48 dp target, or the whole sentence is the target.
4. The version line equals `BuildConfig.VERSION_NAME` (or the package's `versionName`), and the snapshot line's date equals the date part of the bundled `fetched-at.txt`. A test reads the expected date from `fixtures/scryfall/trk/fetched-at.txt`.
5. B3: from Pool with no pool, and from Results after a pasted `trk-manabox-01.csv` import, one click on the node described "About" shows the About screen. Back returns to the screen it came from. Compose UI tests.
6. Snapshots from the spec's list, with A1, A4, and A5 run on the same state: `about` and `about_fontScale200`. Baselines committed.
7. On `spa-test`, tapping About on the first screen shows the screen with "Version 0.1.0" and "Card data snapshot: 2026-11-03". Tapping "Scryfall" hands off to another app (a browser, or Android's app chooser), and `adb logcat -d` holds no `FATAL EXCEPTION` for `spa.app`.

## Change note

- `AboutScreen` now shows the name, `Version <versionName>` (read from the package, since `buildConfig` is off and the build script is out of scope), `Card data snapshot: <date>` (UTC date of the bundled `setdata/scryfall/trk/fetched-at.txt`, via `SetData.ASSET_DIR`/`SET`), the "Card data" heading, and `AttributionText`. `AboutInfo` and `snapshotDateOf` sit in `about/AboutInfo.kt` (detekt's MatchingDeclarationName wanted their own file).
- B2: the word alone is one line tall, so the whole two-sentence text is the target: it is `clickable`, and `clearAndSetSemantics` sets its text (link annotation included), click action and text layout once, which drops the word's own undersized link node. Tapping the word or anywhere in the text opens `https://scryfall.com` through `LocalUriHandler`; a phone with nothing to open it swallows the error rather than crashing.
- Visual choices the spec leaves open: content on `ground` with no card, app name at section-heading size (22 bold), version and date lines `onSurfaceVariant` 16, attribution `onSurface` 16, link `accentText` underlined. Captures are the 411 x 914 dp viewport; the whole content fits in it even at font scale 2.
- B1's test reads `README.md` beside `fixtures/` at test time; the build declares only `fixtures/` as a test input, so a README-only edit can reuse a cached test result until the next code change. Baselines `about` and `about_fontScale200` are new; no other baseline changed.
