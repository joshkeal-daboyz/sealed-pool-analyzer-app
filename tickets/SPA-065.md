# SPA-065: Colour Depth, Curve and Mana Engineer analysts

**Goal.** G-006 deliverable 4, the first three analysts: "Colour Depth Analyst: which colours are deep enough to play, thin-colour warnings, each against the set baseline. Curve Analyst: per colour pair, curve shape, creature count, two-drops, top end, gaps. Mana Engineer: land count, colour source counts, fixing, which splashes are safe. Each agent is a thin interpreter of its number table."

## Scope

- Files or modules expected to change: new `agent/src/main/kotlin/spa/agent/review/agents/` (`ColourDepthAgent.kt`, `CurveAgent.kt`, `ManaAgent.kt`); `AnalysisAgents.kt` (the list); resources `agent/src/main/resources/spa/agent/review/colour-depth-v1.md`, `curve-v1.md`, `mana-v1.md`; `fixtures/agents/review.json` (three entries added to `agents`); tests in `agent/src/test/kotlin/spa/agent/review/agents/`.
- Not in scope: the framework (SPA-064, do not change its interface or runner), other agents, the CLI, `core`.
- Dependencies this ticket may add: none.

- From the design brief, the three agents' questions (use these sentences as the first paragraph of each prompt file, word for word):
  - Colour Depth (`colour-depth`, title `Colour depth`): "Which colors are deep enough to play? Say, per color, how many playables the pool has and how good they are, and warn where a color is thin, each compared with the set baseline."
  - Curve (`curve`, title `Curve`): "Does each color pair have a playable curve and enough creatures? Say, per pair, how the curve is shaped, how many creatures and two-drops it has, how heavy the top end is, and flag the gaps."
  - Mana Engineer (`mana`, title `Mana and fixing`): "How many lands, and is a splash safe? Say what land count and color source counts the pool supports, which fixing it has, and which splash cards are castable on curve."
- Metric pointers (JSON pointers as `MetricFlattener` makes them; `ColorBucket` values are `W U B R G MULTI COLORLESS`; pairs are the ten `ColorPair`s such as `WU`): `/byColor/W/cards/total`, `/byColor/W/creatures`, `/byColor/W/interaction`, `/byColor/W/playables/common` (and the other rarities), `/pairs/WU/cards`, `/pairs/WU/creatures`, `/pairs/WU/noncreatures`, `/pairs/WU/curve/buckets/2/creatures` (buckets 0 to 7), `/pairs/WU/fixingSources`, `/pairs/WU/splashCandidates/count`, `/pairs/WU/landRecommendation/W`, `/pairs/WU/castProbability/W`, `/fixingSources/count`, `/basicLands`, `/nonbasicLands`, `/totalCards`, `/nonlandCards`.
- Design this ticket fixes (do not redesign). Each agent is an `object` implementing `AnalysisAgent`, `unavailable` returns null, and:
  - **colour-depth** `numbers`: `NumberTables.fromMetrics` with patterns `/totalCards`, `/nonlandCards`, `/byColor/`. `facts`: the line `Best cards by colour (grade):` then one line per bucket in the order W, U, B, R, G, MULTI, COLORLESS: `<bucket>: <name> <grade>, <name> <grade>` for the bucket's nonland cards (`ColorBucket.holds` on the card's colours; a card counts once per bucket it is in), best grade first, ties by name, at most 5, grade to one decimal; a card with no grade is left out; a bucket with none prints `<bucket>: none`.
  - **curve** `numbers`: patterns `/pairs/*/cards`, `/pairs/*/creatures`, `/pairs/*/noncreatures`, `/pairs/*/curve/`. `facts`: for each pair in `ColorPair` order, one line `<pair> creatures at mana value 2 or less: <names>; cards at mana value 5 or more: <names>` over the pair's castable nonland cards (colours a subset of the pair's, colourless included), names sorted, distinct, at most 8 each then ` (+<n> more)`, `none` for an empty list.
  - **mana** `numbers`: patterns `/basicLands`, `/nonbasicLands`, `/fixingSources/count`, `/pairs/*/fixingSources`, `/pairs/*/splashCandidates/count`, `/pairs/*/landRecommendation/`, `/pairs/*/castProbability/`. `facts`: `Fixing sources: <name> x<copies>, ...` (or `none`), then for each pair that has splash candidates `Splash candidates <pair>: <name> (<colour>), ...`, names as the metrics hold them.
  - **Prompt files** (`<id>-v1.md`): at most 30 lines; the question above as the first paragraph; then, in your own words, what the number table and facts hold for this agent, what to compare with the baseline, and the kinds of finding a player acts on (thin colours and what to do; a pair with too few creatures or no two-drops; whether a splash is safe and what it costs). No card name, set name or set code, no number.
  - `AnalysisAgents.ALL` becomes `listOf(ColourDepthAgent, CurveAgent, ManaAgent)` in that order (the first runs alone and writes the cache). Add to `fixtures/agents/review.json` `agents`, in the same order, `{ "id": "colour-depth", "enabled": true, "maxTokens": 3000, "prompt": "v1" }` and the same for `curve` and `mana`.

## Acceptance criteria

1. Each agent has the id and title above and `unavailable(input)` is null for any input.
2. For a hand-built input with a baseline, `ColourDepthAgent.numbers` holds exactly the entries `NumberTables.fromMetrics` gives for its three patterns (keys, values, `typical`), checked against values worked out by hand for at least `/totalCards`, `/nonlandCards`, `/byColor/R/cards/total` and `/byColor/R/creatures`.
3. `ColourDepthAgent.facts` equals the specified lines on a hand-built pool with: a bucket with more than 5 cards (only the best 5, a tie broken by name), an empty bucket, a gold card in two colour buckets and MULTI, a card with no grade (left out) and a land (left out).
4. `CurveAgent.numbers` holds exactly the entries for its patterns, checked by hand for `/pairs/WU/cards`, `/pairs/WU/creatures` and one `/pairs/WU/curve/buckets/2/creatures`; `facts` equals the specified lines on a hand-built pool with a colourless card, a card outside the pair, more than 8 two-drops, and an empty list.
5. `ManaAgent.numbers` holds exactly the entries for its patterns, checked by hand for `/basicLands`, `/fixingSources/count` and `/pairs/WU/fixingSources`; `facts` equals the specified lines on a hand-built pool with two fixing sources, one pair with a splash candidate and one without, and again with no fixing at all (`Fixing sources: none`).
6. Each prompt file exists, is at most 30 lines, begins with its question sentence exactly, and contains no digit (a test reads the three files).
7. `AnalysisAgents.ALL` lists the three ids in the order `colour-depth`, `curve`, `mana`; each request `AgentRequests.of` builds for each agent carries the agent's prompt text in `system` (a test checks for the first sentence of the prompt).
8. `fixtures/agents/review.json` stays valid JSON and its `agents` array holds, in order, the three entries above (Acceptance Tester scenario below).
9. The gate is green: format, lint, compile, unit tests, coverage 80 or more on the touched files, no new dependency.
