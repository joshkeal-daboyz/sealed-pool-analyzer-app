# SPA-025: Keep the baseline rebuild's 60-second budget on CI only

**Goal.** CLAUDE.md: "A flaky test is a ticket." `BaselineGoldenTest`'s `trk json is rebuilt byte for byte in under 60 seconds` asserts wall-clock time on every run, so it fails whenever this PC is busy. On 2026-11-03 the pre-push gate on `main` failed with "trk rebuild took 1m 14.770629200s" while four tester agents were running Gradle at the same time. The same test took 11.681 s on the idle PC minutes later, and passes on CI. SPA-008's criterion 4, which this test proves, says "The `trk` rebuild takes under 60 seconds on CI." This ticket makes the test assert exactly that, and supports G-002 deliverable 1 (a gate a Developer can trust locally).

## Acceptance criteria

1. The `trk` golden test always rebuilds `fixtures/baselines/trk.json` from its stored seed and kit count and asserts byte-for-byte equality with the committed file, as it does today.
2. The rebuild's duration is asserted against 60 seconds only when the environment variable `CI` equals `true`. Otherwise the test passes whatever the duration, and prints it to the test output as `trk rebuild took <duration>`. The rule lives in one function that takes the duration and the value of `CI`, and unit tests pin all four cases: 61 s with `CI=true` fails, 59 s with `CI=true` passes, 61 s with `CI` unset passes, and 61 s with `CI=false` passes.
3. With `CI=true` set in the shell (as GitHub Actions sets it), `./gradlew :core:test --tests spa.core.baseline.BaselineGoldenTest` passes, and the test's report `core/build/test-results/test/TEST-spa.core.baseline.BaselineGoldenTest.xml` holds the line `trk rebuild took <duration>` in its system-out. This ticket's pull request shows CI green. (Re-plan 1 of 2: CI uploads only `gate-verdict.json`, so the CI run's test output cannot be read, as the Developer found.)
