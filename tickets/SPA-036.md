# SPA-036: Add synergy counts to the grading packet and let it take a prompt file

**Goal.** G-004 layer 1's input: the grading packet can carry SPA-035's theme counts, and can be built with a given prompt file, so the Architect can grade candidate prompts on `msh`, `hob` and `fra` and pick prompt v2.

## Scope

- Files or modules expected to change:
  - `agent/src/main/kotlin/spa/agent/grader/**` and tests
  - `cli/src/main/kotlin/spa/cli/`: new options on `spa grade-packet`: `--prompt <file>` and `--themes`, with tests and help text
  - `README.md`, `fixtures/grades/README.md`
- Not in scope:
  - Any prompt text (the Architect writes candidates; SPA-037 commits v2). Any grade file. `core`.
- Dependencies this ticket may add (none unless listed):
  - (none)

## Background the Developer needs

- Read G-004 (layer 1, deliverable 2, criterion 4) and SPA-033's change note.
- `--prompt <file>`: use that file's text in place of `prompt-v1.md` at the top of `instructions.md`. Without it, the packet is byte-identical to SPA-033's (prompt v1, no themes).
- `--themes`: add a section `## Themes in this set` to `instructions.md`, after the format brief: one line per kept theme with its kind and its has, refers and colour counts, as SPA-035 computes them. Add each card's themes to its entry in the card files as `"themes": [{ "name": ..., "role": "has" | "refers" }]`. Without `--themes`, no theme appears anywhere.
- The response format and `grade-import` are unchanged.
- The blind check (SPA-033 criterion 2, as ruled) must hold for a packet built with both options.
- Work on a local branch named exactly `SPA-036`. One Developer at a time. Never rewrite a pushed branch; keep scratch files out of the repository.

## Acceptance criteria

1. Without the new options, `spa grade-packet trk` writes files byte-identical to SPA-033's (a test compares against a packet built by the existing code path).
2. With `--prompt <file>`, `instructions.md` starts with that file's text, and the rest is unchanged.
3. With `--themes`, `instructions.md` holds the themes section, and each card entry lists its themes with roles. For `trk`, the Spacecraft line shows has 17, refers 11 (SPA-035 criterion 2), and a Spacecraft card lists `{"name":"Spacecraft","role":"has"}`.
4. The blind check passes on a `trk` packet built with both options. `grade-import` accepts responses to such a packet. The gate is green.

## Change note

- Added `PacketThemes` and `PacketTheme` in `spa.agent.grader`; `GradingPackets.build` takes `prompt` (default prompt v1) and `themes` (default none); `PacketCard.themes` defaults to null, which kotlinx leaves out, so the default bytes are unchanged. `spa grade-packet` takes `--prompt <file>` and `--themes`. Criterion 1 is pinned by the SHA-256 of every `trk` and `syn` file as SPA-033's code wrote them at 1725a50; that test, the "no theme without `--themes`" test and the grade-import test passed on the red commit too, since they guard behaviour that already existed.
- The themes line is `- Spacecraft (type): has 17, refers 11; colours W= U= B= R= G= M= C=`, colours being the either count, as `spa themes` prints. The section has one legend sentence saying what the numbers and each card's `themes` mean; it is packet structure like the files description, not grading guidance, and the Architect may reword it. A card that has a theme and also refers to it (a Spacecraft whose text names Spacecraft) lists it once, as `has`; the counts still count it in both. Cards with no kept theme get `"themes": []`.
- The prompt file is read with CRLF turned to LF and trailing whitespace trimmed, the same as prompt v1. A missing or blank prompt file is one line and exit 1.
- The blind check moved into the test helper `BlindCheck`, so `BlindPacketTest` (syn) and the new `trk` test share it; no check was removed. The criterion 4 import test calls `GradeImport.run` directly, so nothing is written to `fixtures/grades`.
