- Design this ticket fixes (do not redesign):
  - Usage: `spa review <pool-file> --set <code> [--data <dir>] [--format manabox|text|collector] [--brief <file>] [--weights <file>] [--tags <file>] [--otags <file>|none] [--config <file>] [--model <id>] [--max-input-tokens <n>] [--max-output-tokens <n>] [--json] [--dry-run] [--show-input] [--record <dir>] [--replay <dir>]`. A cap that is not a positive whole number is one line and exit 2. `--replay` with `--record`, and `--dry-run` or `--show-input` with either, are exit 2. Add the command to `Main.kt`'s table and usage text.
  - Pipeline: parse the pool as `analyze` does; `MetricEngine.compute`; baseline and grades as `analyze` and `pool-grades` load them; decks = `BuildSession.open(data, set, weights, tags, otags).rank(pool)`, the first three as `DeckSummary.of(rank, ranked)`; a `SynergyView(tags, table, GradingPool::id)` when the set's tag file exists (`--tags`, else `<data>/tags/<code>.json`), none when it does not; config from `--config` or `<data>/agents/review.json` parsed with the ids of `AnalysisAgents.ALL`; `--model`, `--max-input-tokens` and `--max-output-tokens` replace the config's values; then `ReviewRun`, printed with `ReviewText` (or `ReviewJson` with `--json`).
  - Client chain: the base is `AnthropicModelClient.fromEnvironment()` (closed when done), or `ReplayModelClient.fromDirectory(--replay)`; `--record` wraps the base in `RecordingModelClient`; `BudgetedModelClient` with the caps is outermost; its `totals` are the review's usage. Tests inject a client through an internal overload of the command's `run` (a function from the environment to a `ModelClient`), never the real one.
  - `--show-input` prints no model call's result and needs no key: the bundle text, then for each enabled agent a line `=== <id> (<title>) ===` followed by that agent's request `userMessage` (its number table and facts), or `=== <id> (<title>) === not run: <reason>` for an unavailable agent. It exists so the owner can read what the agents are given.
  - `--dry-run` prints, with no key and no call: `Dry run: review of <pool-file> (<set>), no calls made.`; `Model: <model>`; `Cached bundle: ~<n> tokens (estimated)` (`TokenEstimate` of the bundle text); one line per runnable agent `Call <k>: <id>, ~<n> input tokens, up to <maxTokens> output tokens` (`TokenEstimate.of` the request, which includes the bundle), `Not run: <id> (<reason>)` per unavailable agent, then `Call <k>: explainer, ~<n> input tokens, up to <maxTokens> output tokens (after the analysts; estimated)` where n is the bundle estimate plus one quarter of the characters of the decks' text plus 60 times `maxFindings` times the number of runnable agents; then `Total: ~<N> input tokens of <cap> allowed, up to <M> output tokens of <cap> allowed` and either `Within the caps.` or `Over the input cap by ~<n> tokens.` / `Over the output cap by <n> tokens.` (both lines when both). It writes nothing to disk.
  - **Canned recordings.** Commit `fixtures/recordings/review-canned-trk-manabox-01/`: the `Recording` files (`colour-depth.json`, ..., `explainer.json`) of a review of `fixtures/pools/trk-manabox-01.csv --set trk` answered by a test-only fake client that returns, for each agent, a valid hand-written answer citing real cards of that pool and keys of that agent's table (values as the table holds them), and for the Explainer a valid answer with one disagreement. A `README.md` in that directory says they are canned, not a model's output, and how to regenerate them. A test regenerates them in memory and fails if a committed file differs (with a system property that rewrites the files instead of failing, named in the README). They exist so `--replay` can run end to end offline; a change to a prompt, the config's model, the weights file or the pool changes the requests and so needs a regeneration.

## Acceptance criteria

1. With no key in the environment, `spa review <pool> --set trk` (no `--dry-run`, `--show-input` or `--replay`) prints exactly `ANTHROPIC_API_KEY is not set` on stderr, nothing on stdout, exits 1, and has read no file (a test gives it a pool path that does not exist and still gets that message).
2. `--dry-run` on the trk sample pool, with an environment with no key, prints the lines specified: eight `Call` lines in order `colour-depth`, `curve`, `mana`, `interaction`, `bombs`, `archetypes`, `synergy`, `explainer`, the model `claude-sonnet-5-5`, a `Total:` line naming 300000 and 60000, and `Within the caps.`; with `--max-input-tokens 1000` it prints `Over the input cap by ~<n> tokens.`; exit 0; the test's client factory is never called.
3. `--show-input` on the trk sample pool prints the bundle and the eight sections, containing these lines exactly: `/totalCards = 85 (typical: median 85, p10 85, p90 85)`, `/nonlandCards = 71 (typical: median 71, p10 67, p90 74)`, `/basicLands = 5 (typical: median 5, p10 4, p90 6)`, `/removalTotal = 9 (typical: median 8, p10 5, p90 11)`, `/interactionTotal = 1 (typical: median 3, p10 1, p90 6)`, `/fixingSources/count = 6 (typical: median 10, p10 7, p90 13)`, `/pairs/WU/cards = 33 (typical: median 29, p10 24, p90 35)`, `/pairs/WU/creatures = 19 (typical: median 15, p10 11, p90 20)`, `/pairs/WU/removal = 2 (typical: median 2, p10 1, p90 4)`, `/pairs/WU/fixingSources = 4 (typical: median 10, p10 7, p90 13)`, and the bundle's first line `# Pool bundle` and `Set: trk (Star Trek), format speed:`.
4. With the test client factory answering every agent and the Explainer validly, `spa review` on the trk sample pool prints the review of SPA-069 with all eight sections in order, `Missing: none` and `Usage: 8 calls`; two runs print the same bytes; `--json` prints JSON that parses and whose `agents` array has seven `answered` entries.
5. 6. `--replay fixtures/recordings/review-canned-trk-manabox-01` prints a complete review with no key and no client factory; the committed recordings equal the regenerated ones; the review's `Usage:` line has 8 calls.
7. `--record <dir>` with the test client writes eight files whose names are the agent ids and `explainer`, that `ReplayModelClient.fromDirectory` replays to the same review, and none of them contains the test's fake key string (the test sets an environment key `test-key-1234` for the fake factory).

9.
