# SPA-016: Build the app shell and the first end-to-end import, from pasted text to the Results header

**Goal.** G-002's technical risk "The first end-to-end import (a file in, numbers on screen) should land as early as the dependencies allow" (`tickets/lessons.md`, SPA-009), and the shell every later screen ticket builds on: theme, fonts, navigation, top bar, the ViewModel and its states, the timing log lines (goal criterion 13), and the shared accessibility test helper (goal criterion 12). The Pool screen here is minimal (paste and analyze only). SPA-017 completes it.

The design sections this ticket implements: Visual direction (all of it), Decisions 1 to 5, Navigation flow, Component map ("App shell", `PoolHeaderCard` without its Clear pool button, and `LoadingState`), Results screen (top bar, the pool header card, and the Loading state), and the accessibility items A1, A2 (for Pool and Results), A3, A4, A5, P1, P3, and R5.

## Acceptance criteria

1. `SpaTheme` applies one dark `SpaColors` scheme holding exactly the eleven tokens and values in the spec's Visual direction, with no dynamic colour, and the system's light setting changes nothing. A3: a JVM unit test computes each of the twelve token pairs in Visual direction's contrast table with the WCAG formula, asserts it equals the table's ratio to two decimals, and asserts it meets its threshold (4.5 for the ten text pairs, 3.0 for the two outline pairs).
2. The three fonts are bundled under `res/font`, and the type scale uses Atkinson Hyperlegible at the spec's sizes, all in `sp`. A unit test asserts that the typography's font family resolves to the bundled resources and that no text style sets its size in `dp`. `app/fonts/OFL.txt` holds the licence.
3. Navigation follows the spec's Navigation flow for what exists in this ticket. With no pool, launch shows Pool. The routes `pool`, `results`, `pair/{pair}`, and `about` are registered. After a successful import the back stack is Results only, so system back finishes the Activity. "New pool" on Results opens Pool with a back arrow ("Back"), and back returns to the same Results. A2: the About icon, described "About", is on Pool and Results, and opens the `about` route. Compose UI tests for each.
4. `PoolViewModel` exposes `PoolUiState`: `NoPool`, `Loading(source)`, `Loaded(result, source, format)`, `ImportFailed(kind, source, lines)`, and `DataMissing`. `analyze(text, format)` moves to `Loading`, then to `Loaded` or `ImportFailed` through `PoolImporter`, or to `DataMissing` when SPA-015 reports it. The latest import wins: with a test importer that suspends, start import A, start import B, complete A, then complete B. The state is B's result, and A's result is never emitted. Unit tests with `kotlinx-coroutines-test`.
5. Minimal Pool screen. P1: a text field whose accessible label (not placeholder) is "Paste your pool". P3: "Analyze pool" is not enabled when the field is empty or only spaces and blank lines, and is enabled with any other text. Tapping it imports the text with format auto-detected and source "pasted". Compose UI tests.
6. Results, this ticket's part, in the Visual direction's style. The top bar has the title "Your pool" and the About icon. `PoolHeaderCard` shows the source ("<file name>" or "Pasted"), "Read as <format name>", "<totalCards> cards in <entries> entries", and "<n> blank or header lines skipped" only when that count is above 0, and the "New pool" button. Loading shows the header with the source and "Reading your pool…", and a progress indicator described "Reading your pool" (R5). The indicator appears only once loading has lasted 300 ms. Compose UI tests: pasting `trk-manabox-01.csv`'s text shows "Pasted", "Read as ManaBox CSV", and "85 cards in 71 entries", with the expected numbers read from its golden file. A test clock holds Loading at 299 ms (no indicator) and 300 ms (indicator).
7. `A11yChecks` in `app/src/test/kotlin/spa/app/testing/` gives every screen ticket three checks. `assertTouchTargets` is A1: every node with a click action is at least 48 × 48 dp. `assertClickablesLabelled` is A4: every node with a click action has text or a content description in the merged semantics tree, built on the semantics helper SPA-013 proved (ATF is not used; it does not evaluate Compose content under Robolectric). `assertNoTextOverflowAtFontScale2` is A5: at font scale 2.0, no `Text` reports visual overflow. Each has a test that fails on a deliberately bad composable (a 40 dp clickable, an unlabelled clickable, and a fixed-width `Text` that overflows) and passes on this ticket's Pool screen and on Results in Loading and loaded states.
8. Snapshot `results_loading` from the spec's list: launch held in Loading for a pasted `trk-manabox-01.csv`, at 411 × 914 dp, with its baseline committed. The spec's setup says "remembered" pool, which SPA-022 adds; this ticket holds Loading on a pasted import. The `shell_placeholder` snapshot and baseline are deleted.
9. Timing (goal criterion 13). `SpaTiming` writes `Log.i("SpaTiming", "<event> <SystemClock.elapsedRealtime()>")` for four events, once each per occurrence: `app-created` in `SpaApplication.onCreate`, `first-screen-shown` when the first screen of the process has drawn its first frame, `import-confirmed` when "Analyze pool" is tapped, and `results-shown` when Results first draws in its loaded state for an import. A unit test with a fake log sink asserts the order and the event names for a paste import. SPA-017 adds `import-confirmed` for the file picker.
10. On `spa-test`, with the APK installed, pasting each of `trk-text-01.txt`, `trk-collector-01.txt`, and a single line `TRK 1701d` and tapping "Analyze pool" shows Results with the header values `spa analyze <file> --set trk` gives for that text: format name, total cards, and entries. `adb logcat -s SpaTiming` shows `import-confirmed` then `results-shown` for each.
