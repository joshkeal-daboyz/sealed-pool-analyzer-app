- Design this ticket fixes (do not redesign): `spa packet <pool-file> --set <code> [--data <dir>] [--format manabox|text|collector] [--brief <file>] [--weights <file>] [--tags <file>] [--otags <file>|none] [--top <n>] [--out <file>]`. The packet is one UTF-8 text file (Markdown-flavoured, line feeds only) written to `--out`, or to stdout without it; with `--out`, stdout gets one line `Packet written to <file>` and the file is created or replaced. Deck weights default to `<data>/weights/deck-tuned.json` (frozen in G-005), not `deck-default.json`; `--top` defaults to 3. The pool, brief, baseline and grades load exactly as `analyze`, `grades` and `pool-grades` load them; unresolved pool lines go to stderr as for the other commands; a missing baseline is a stderr note and no `typical` text; a set with no tag file is not an error. Exit codes as the other commands (0 ok, 1 an error with one line on stderr, 2 a bad command line).
- The packet has exactly these sections, in this order, each beginning with its heading line, a blank line between sections, ending with a newline:
  1. `# Sealed pool review packet`, a blank line, then this text word for word:

     ```
     You are helping a player build a Magic: The Gathering limited deck from their sealed pool. Everything below was worked out by code from the player's own pool: the cards with a grade for each (0 to 5, relative to this set), the pool's numbers beside what a typical pool from this set holds, the pool's fixing, the strongest card-to-card synergies, and the three best decks the deck builder found, with its reasons.

     Please:
     1. Say which of the three decks to register, and why, in a short paragraph.
     2. Go through the pool by colour: where it is deep, where it is thin, and how the removal, the curve and the mana compare with the typical pool.
     3. Name cards left out of the best deck that deserve a second look, and any card in it that you would cut, with the reason.
     4. Say what you are unsure of, and anything in this packet that looks wrong.

     Use only this packet. Quote card names exactly as written here, and take numbers from the packet rather than computing your own.
     ```

  2. `## Pool`: first a line `Set: <code> (<set name from the brief>), <total cards> cards, <distinct> distinct`, then one line per distinct card (grouped by oracle id, copies summed), sorted by name (ordinal): `<count>x <name> | <mana cost, faces joined by " // ", or "-"> | <type line, faces joined by " // "> | <rarity lowercase> | grade <score to 1 decimal> (<letter label>) | <rules text, faces joined by " // ", newlines as " / ">`, with `grade none` for a card with no grade (basic lands). The letter labels are the table in the README (`GradesCommand.LABELS`).
  3. `## Numbers`: one line per entry, `<pointer> = <value> (typical: median <m>, p10 <a>, p90 <b>)`, the parenthesis left out when there is no baseline or no such pointer; a value prints without a decimal point when whole, else with at most 4 decimals and no trailing zero. The entries are those of `MetricFlattener.flatten(metrics)` sorted by pointer (ordinal), except every pointer containing `/curve/` (the decks show the curve).
  4. `## Fixing`: the lines `spa fixing <pool-file> --set <code>` prints for the pool (the fixing cards with quantities and the colour counts line), or `No fixing cards.` if it prints none.
  5. `## Synergy`: when the set has a tag file, up to 20 lines `<score> <name> with <name>` over pairs of distinct pool cards (and `<score> <name> with itself` for a card with two or more copies, its diagonal score) whose pair score is 1 or more, highest first, ties by the two names in order, from the same pair table `spa synergy` uses (with `--tags`/`--otags` as for `synergy-table`); `None.` when no pair scores; `No synergy tags for this set.` when there is no tag file.
  6. `## Decks`: exactly what `spa build <pool-file> --set <code> --weights <the weights> --top <n>` prints to stdout (the ranked decks with their score parts, spells by mana value, lands and sideboard), unchanged.
  7. `## Sources`: the line `Card data from Scryfall (scryfall.com). Card text and images are property of Wizards of the Coast.`
- A pool that cannot build any deck is not an error here: the `## Decks` section says `No deck could be built from this pool.`
- Real numbers for `fixtures/pools/trk-manabox-01.csv` with `--set trk` (from `spa analyze` and `fixtures/baselines/trk.json`, 2026-11-06): `/totalCards` 85 (typical median 85, p10 85, p90 85); `/nonlandCards` 71 (71, 67, 74); `/basicLands` 5 (5, 4, 6); `/removalTotal` 9 (8, 5, 11); `/interactionTotal` 1 (3, 1, 6); `/fixingSources/count` 6 (10, 7, 13); `/pairs/WU/cards` 33 (29, 24, 35); `/pairs/WU/creatures` 19 (15, 11, 20); `/pairs/WU/removal` 2 (2, 1, 4); `/pairs/WU/fixingSources` 4 (10, 7, 13). The brief's set name is `Star Trek`. From the README, `spa grades` gives `He's Dead, Jim` (trk 114) grade 4.0, label `A−`, quantity 1 in this pool; the pool holds 3 Swamp (trk 309), basics with no grade.

## Change note

`spa packet` is `PacketCommand` (arguments, loading, output) plus `PacketText` (the seven sections as pure functions). It reuses the other commands' code: `AnalyzeCommand` (`format`, `loadBrief`, `loadBaseline`), `GradesCommand.gradeFiles`, `FixingCommand.poolLines` (split from the file-reading form), `BuildCommand.top` and `rankedLines` (the ranked-deck lines `build` prints, now shared), widened to `internal` with behaviour unchanged. One addition to `BuildSession.open`: `tagsOptional`, so a set with no tag file builds with no synergy part instead of failing; only `packet` passes it.
Pool grades come from `GradesCommand`'s lookup (win-rate file first, else model file), as the ticket says; the `## Decks` lines use `build`'s own lookup (`<code>.v2.json`, else `<code>.json`). For a set with win rates (hob, msh, fra) the two can differ; for trk they agree. The synergy section builds its own pair table beside the one `build` builds lazily (two reads of the tag file and facts, no behaviour change).
Not unit tested: nothing; every branch is covered through `runCli`. Two test fixes after the red commit: the opening text contains "typical", so the no-baseline test now looks only at the Numbers section, and the Fixing comparison trims the blank line after the heading.
Every section is a heading, a blank line, then its lines (as scenario P2's `sed '1,2d'` assumes).
