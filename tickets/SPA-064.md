- Design this ticket fixes (do not redesign):
  - `interface AnalysisAgent` has exactly: `id` (config key and section key, lowercase letters and hyphens), `title` (the section heading), `fun numbers(input: ReviewInput): NumberTable`, `fun facts(input: ReviewInput): String` (plain text the model may use besides the table; empty string for none), `fun unavailable(input: ReviewInput): String?` (null when the agent can run, else a one-line reason). The agent's own instructions are a resource, `spa/agent/review/<id>-<version>.md`, version from the config. `AnalysisAgents.ALL: List<AnalysisAgent>` is empty in this ticket.
  - **Preamble** (`preamble-v1.md`, the file's text must equal this exactly, ending with one newline):

    ```
    You are one specialist in a team reviewing a Magic: The Gathering limited card pool for a player. You answer one question, set out below. You work only from the pool bundle and the number table you are given. You do not know the other specialists' answers.

    Rules:
    1. Cite cards. Every finding names the pool cards it is about, by their exact names as written in the bundle. A finding with no card, or a card not in the pool, is thrown away.
    2. Quote numbers by key. When a finding rests on a number, give the number's key from the number table and the value the table shows. Do not write a number from memory or compute one yourself; if the table has no number for it, say it in words without a number. A finding whose key or value does not match the table is thrown away.
    3. Compare with the set. The table shows each number beside what a typical pool from this set holds. Say whether the pool is above, below or typical for the set, and do not call a number high or low without that comparison.
    4. Be specific and short. At most 8 findings. Each claim is one or two sentences a player can act on. Prefer the findings that would change what the player builds.
    5. Say how sure you are. `confidence` is 0 to 1 for the whole answer; lower it when the pool or the numbers give you little to go on.
    6. Answer with one JSON object and nothing else, in the schema below.
    ```

  - **Schema text** (`schema-v1.md`, exact, ending with one newline):

    ```
    Answer with one JSON object and nothing else:
    {
      "agent": "<your agent id>",
      "confidence": <number from 0 to 1>,
      "summary": "<two sentences at most>",
      "findings": [
        {
          "claim": "<one or two sentences>",
          "pair": "<two colour letters such as WU, or null>",
          "severity": "info" | "warn" | "key",
          "cards": ["<exact card name>", ...],
          "numbers": [ { "key": "<key from the number table>", "value": <the value the table shows> } ]
        }
      ]
    }
    severity: key = changes what the player should build, warn = a problem or risk, info = a fact worth knowing.
    ```

  - **Request** an agent gets (`AgentRequests.of(agent, input, config)`): `model` and `maxTokens` from the config, `label` = the agent id, `cachedContext` = `PoolBundle.text(input)`, `system` = preamble, a blank line, the agent's prompt file text, a blank line, the schema text (each file's trailing newline trimmed before joining), and `userMessage` = `## Number table` newline, `table.text()`, then, only if `facts` is not empty, a blank line, `## Facts`, newline, the facts, then a blank line and `Answer with the JSON object only.`
  - **Checks** (`AnswerChecker.check(text, agent, pool names, table, maxFindings)`): the answer text is parsed after taking the part from the first `{` to the last `}` (so a code fence or a sentence around the object is tolerated); the schema is strict (an unknown key anywhere, a missing field, a wrong type, `severity` outside the three, `confidence` outside 0 to 1, or `agent` different from the agent's id is a `SchemaError` whose one-line message names the field). A valid answer's findings are then each kept or dropped, first reason that applies: `NO_CARD` (empty `cards`), `UNKNOWN_CARD` (any name that is neither a pool card's full name nor the front face's name of a multi-face pool card, compared exactly; a front-face name becomes the full name), `UNKNOWN_KEY` or `WRONG_VALUE` (via `NumberTable.check`), then `OVER_LIMIT` for findings after the first `maxFindings` kept. A kept finding carries its numbers as the table's values with their `typical` (not the model's digits). The result is the kept findings plus the list of drops, each with its reason and claim.
  - **Runner** (`AgentRunner(client, config, agents)`): `run(input): List<AgentOutcome>` in agent order, each `Answered(agent, answer, dropped)` or `Missing(agent, reason)`. Agents the config switches off are not in the result and send nothing; an agent whose `unavailable` is not null is `Missing(agent, thatReason)` with no call. The first remaining agent is sent alone and answered; then the rest are sent from a pool of at most `parallel` threads. A `SchemaError` is retried up to `retries` times, each time as a new request with label `<id>-retry1` (then `-retry2`) whose `userMessage` is the original plus a blank line and `Your previous answer was rejected: <error message>. Answer again with the JSON object only.`; the last failure is `Missing(agent, "invalid answer: <error message>")`. A `BudgetExceededException` is `Missing(agent, <its message>)` with no retry. A call longer than `callTimeoutSeconds` is cancelled and is `Missing(agent, "timed out after <n>s")`. Any other exception is `Missing(agent, "error: <class simple name>: <first line of message, at most 200 characters>")`. `plan(input): List<PlannedCall>` gives, in order, each enabled agent's request or its unavailable reason, sending nothing.
  - **Config** (`ReviewConfig.parse(text, knownAgentIds)`, strict: an unknown key, wrong type, missing key, duplicate or unknown agent id, a negative or zero number where a count is needed, `retries` over 3, is one `IllegalArgumentException` naming the key): `{ "version": 1, "model": "claude-sonnet-5-5", "maxInputTokens": 300000, "maxOutputTokens": 60000, "callTimeoutSeconds": 120, "parallel": 6, "retries": 1, "maxFindings": 8, "agents": [ { "id", "enabled", "maxTokens", "prompt" } ], "explainer": { "enabled": true, "maxTokens": 6000, "prompt": "v1" } }`. Create `fixtures/agents/review.json` with these values and `"agents": []` (SPA-065 to 067 add their entries), and a short `fixtures/agents/README.md` describing each key.

## Acceptance criteria

1. `preamble-v1.md` and `schema-v1.md` equal the texts above exactly.
2. `AgentRequests.of` for a fake agent gives the request described: every field, with the system joined as specified, the user message with and without facts.
3. `AnswerChecker` accepts a valid answer, also when wrapped in a code fence or a sentence; each schema fault (not JSON, unknown key at the top and inside a finding, missing field, wrong type, bad severity, confidence 1.5, wrong agent id, findings not a list) is a `SchemaError` whose message names the field.
4. A finding with no cards is dropped `NO_CARD`; one with a name not in the pool (also a name differing only in case) `UNKNOWN_CARD`, even when its other cards are in the pool; a front-face name of a multi-face pool card is kept and becomes the full name.
5. A finding with a key outside the table is dropped `UNKNOWN_KEY`; with a wrong value `WRONG_VALUE`; a finding with no numbers is kept; a kept finding's numbers hold the table's values and `typical`.
6. With 10 valid findings and `maxFindings` 8, the first 8 are kept and 2 are dropped `OVER_LIMIT`; a dropped finding does not count towards the 8.
7. The runner sends the first agent's request and has its answer before any other request is sent, and then sends the others concurrently: a fake client for 6 agents that blocks each call until 3 are in flight shows at least 3 at once, never more than `parallel`.
8. Retry: an invalid answer then a valid one is `Answered`, the two requests have the labels and the user message specified; two invalid answers are `Missing("invalid answer: ...")` with `retries` 1; with `retries` 0 there is no second request.
9. `BudgetExceededException` is `Missing` with its message and no retry; a call that blocks past `callTimeoutSeconds` (set to 1 in the test) is `Missing("timed out after 1s")`; an `IllegalStateException("boom\nsecond line")` is `Missing("error: IllegalStateException: boom")`.
10. A switched-off agent is absent and sends nothing; an agent that is `unavailable` is `Missing` with its reason and sends nothing; `plan` lists both cases and sends nothing.
11. No agent's request contains another agent's answer text (a test gives each fake answer a distinct marker string and reads every request sent).
12. A test-only agent added to the list passed to `AgentRunner` gets a request, and an `Answered` outcome, with no other code change.
13. `ReviewConfig.parse` accepts the committed file's shape (the test holds a copy of the text) and each fault above is rejected with the key named.
14. The gate is green: format, lint, compile, unit tests, coverage 80 or more on the touched files, no new dependency.

## Change note

Built the review framework exactly as specified; `AnalysisAgents.ALL` is empty. `AgentOutcome` holds the `AnalysisAgent` itself (not its id) so the printer can read `title`; `PlannedCall` is `Send(agent, request)` or `Skipped(agent, reason)`.
