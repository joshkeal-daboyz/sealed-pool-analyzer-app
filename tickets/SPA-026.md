# SPA-026: Make core's file reads work on Android, without changing core

**Goal.** G-002 deliverable 2: the bundled set data is "loaded on the device through `core`'s existing loaders." On the `spa-test` emulator (Android 16, API 36), tapping "Analyze pool" crashes the app with `java.lang.NoSuchMethodError: No static method readString(Ljava/nio/file/Path;)Ljava/lang/String; in class Ljava/nio/file/Files`, thrown from `spa.core.cards.ScryfallCache.companions(ScryfallCache.kt:66)`, reached through `CardIndex.load` and SPA-015's `SetData.readFresh`. Android's `java.nio.file.Files` has no `readString` or `writeString` at any API level. The JVM has them, so every gate test passed. SPA-013 pinned `minSdk` 33 on the wrong belief that API 33 has them (re-plan in SPA-013's history). The goal allows no `core` change beyond SPA-014's. So this ticket fixes it in the app's build, with Android's core library desugaring, which rewrites missing `java.*` calls inside the APK, `core`'s classes included.

## Change note

- Bounce to the Architect: criterion 1 cannot pass without a `core` change. Desugaring fixes `Files.readString` (`loadsTheBundledSetDataThroughCore` passes on spa-test: 581 trk, 30 sds, kits 2000), but `importsTheManaBoxFixture` then fails in `MetricEngine.compute`: `ExceptionInInitializerError` at `spa.core.text.RulesTagger.tag(RulesTagger.kt:120)`, caused by `java.util.regex.PatternSyntaxException: Syntax error in regexp pattern near index 11` for `\{([^{}]*)}` at `spa.core.text.ManaProduction.<clinit>(ManaProduction.kt:16)`, via `com.android.icu.util.regex.PatternNative.compileImpl`. Android's ICU regex rejects an unescaped `}`; the JVM accepts it. No build setting changes the regex engine.
- Evidence of the fix it needs (a scratch change, reverted, never committed): escaping the closing brace as `\\}` in three patterns, `core/src/main/kotlin/spa/core/text/ManaProduction.kt:16`, `core/src/main/kotlin/spa/core/text/ManaCost.kt:29`, and `core/src/main/kotlin/spa/core/cards/ManaCost.kt:13`, made both on-device tests pass (2 tests, 0 failures). Escaping the `{}` inside the class instead did not help. `git diff origin/main -- core cli` is empty.
- Changed: `app/build.gradle.kts` turns on `isCoreLibraryDesugaringEnabled` with `com.android.tools:desugar_jdk_libs_nio:2.1.5` (the `_nio` flavour, since plain `desugar_jdk_libs` has no `java.nio.file`), adds `AndroidJUnitRunner`, `androidx.test:runner` and `androidx.test:core` 1.7.0 plus the catalog's existing `junit4` and `androidx.test.ext:junit` for `androidTest`, and adds `fixtures/pools` to the test APK's assets. It drops the false "Android has these from API 33" comment; `minSdk` stays 33. `app/src/androidTest/kotlin/spa/app/DeviceSetDataTest.kt` is criterion 1's test. Red on 1dd67c0 (both tests `NoSuchMethodError` for `Files.readString`, at `ScryfallCache.companions(ScryfallCache.kt:66)`).
- SPA-016 should know: with this branch the app gets past set-data loading, but "Analyze pool" will still crash on the regex until `core` is fixed. Run on-device tests with `./gradlew :app:connectedDebugAndroidTest`. Local gate runs before the push: 1, green on 1dafc9c (all seven steps; ui-tests "37 UI tests and 1 snapshot ran"). Branch pushed for the record, with no pull request, because criterion 1 fails on the device.
