# SPA-032: Add spa grade-backtest, the rank correlation between two grade files

**Goal.** G-003 deliverable 5 and criterion 6: the command that scores the Claude grade against win rates. It is built and tested now, before any Claude grade exists, so the live runs in SPA-034 only produce numbers.

## Scope

- Files or modules expected to change:
  - `agent/src/main/kotlin/spa/agent/backtest/**` and tests (new)
  - `cli/src/main/kotlin/spa/cli/`: `spa grade-backtest --set <code> [--model <file>] [--winrates <file>]`, defaulting to `fixtures/grades/<code>.json` and `fixtures/winrates/<code>.json`, wired in `Main.kt` and its help text
  - `README.md`: the command
- Not in scope:
  - The Claude grader, any model call, `core`.
- Dependencies this ticket may add (none unless listed):
  - (none)

## Background the Developer needs

- **Spearman's rho** over the cards graded in both files (matched by set code and collector number): rank each list with average ranks for ties (scores move in steps of 0.5, so ties are common), then take the Pearson correlation of the ranks. Cards are those the win-rate file grades (500 or more games, per SPA-031); a card missing from the model file is listed and counted, not dropped silently.
- Output: one line per group, `all`, then `common`, `uncommon`, `rare`, `mythic`: `rho` to 3 places, and `n`. Then the model file's provenance and the win-rate file's provenance. Exit 0. A group with fewer than 5 cards prints `rho n/a`.
- Work on a local branch named exactly `SPA-032`. This PC runs one Developer at a time.

## Acceptance criteria

1. Spearman's rho matches hand-computed values on pinned cases: identical rankings (1.000), reversed (-1.000), a case with ties whose average-rank result is computed in the test, and a constant list (rho undefined, printed `n/a`).
2. On two small committed grade files, `spa grade-backtest` prints the five group lines with the expected rho and n, lists a card missing from the model file, and exits 0.
3. A missing file prints one line naming it and exits 1.
4. The gate is green.

## Change note

- `spa.agent.backtest`: `Spearman` (average ranks, Pearson of ranks, null when undefined) and `Backtest.run`, which matches the win-rate file's cards to the model file by set code and collector number, groups them by rarity, and formats the report lines. `spa grade-backtest` in `cli` loads both files and the set's Scryfall cache for rarity.
- Added `--data <dir>` to the command (not in the ticket's signature): rarity needs the Scryfall cache and the tests need a data directory; the defaults stay `fixtures/grades/<code>.json` and `fixtures/winrates/<code>.json`.
- Both sides are ranked by `score`, as the Background says; the win-rate file's `gihwr` is not used. All win-rate cards are taken as is (the table already holds only 500+ game cards); a card whose rarity the cache cannot find counts in `all` only. Output order: five group lines, model provenance, win-rate provenance, `missing from model: N card(s)`, one `missing:` line per card.
- Test grade files are `cli/src/test/resources/grades/syn-{model,winrates}.json` (20 syn non-basics, model misses Evolving Wilds); the expected rho values are worked by hand in the test's comment.
