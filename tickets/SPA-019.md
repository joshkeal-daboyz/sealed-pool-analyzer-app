# SPA-019: Build the Pair detail screen with lands, cards, curve, and splash candidates

**Goal.** G-002 deliverable 4, the per-pair part: "for each of the ten color pairs its cards, playables, creatures, curve, splash candidates, and land recommendation, each number beside its typical `trk` value." Per-pair playables are dropped (owner decision). Also goal criterion 4 for Pair detail, and the land-recommendation part of criterion 5.

The design sections this ticket implements: Pair detail screen (every state in its table), Component map ("Pair detail screen"), the Settled item "Mana value 7+", and the accessibility items A1, A2 ("About" and "Back" on Pair detail), A4, A5, A6 ("Lands", "Cards", "Curve", "Splash candidates"), A7, D1, and D2.

## Acceptance criteria

1. Criterion 4 for Pair detail. For each of the 23 `trk` fixtures and each of the ten pairs, `PairDetailUi`'s displayed values have exactly the pointers in the background, each value equal to the golden's `/metrics` plus the pointer, and each typical median, p10, and p90 equal to the baseline's stat. The splash list's names, colours, and reasons equal the golden's `splashCandidates` in order. Every expected value is read from the files.
2. Layout, as the spec gives it. The top bar has a back arrow ("Back"), the title "<pair name>" (such as "White–Blue (WU)"), and the About icon ("About"). Then the reminder line, when the pool has unresolved lines: "This pool has <n> lines not read; these numbers leave them out." Then the sections Lands, Cards, Curve, and Splash candidates, each a semantics heading (A6). Back returns to Results at the same scroll position. Compose UI tests.
3. D1: for `trk-manabox-01.csv` WU, the Lands section shows "6 Plains" and "11 Island", each with its typical value, read from the golden and the baseline. Basic land names come from `BasicLandNames` (W Plains, U Island, B Swamp, R Mountain, G Forest), with a unit test for all five.
4. D2: eight curve rows, "Mana value 0" to "Mana value 6", then "Mana value 7+". Each is one merged node holding its "<n> creatures" and "<n> other" values with typical values. Compose UI test.
5. Splash candidates: "<count> splash candidates, typical ...", then one line per candidate: the name, the colour as a name, and the reason in words ("removal" for `REMOVAL`, "rare or mythic" for `RARE_OR_MYTHIC`, the code otherwise). A test-built pool with no candidates shows "0 splash candidates, typical ..." and "No splash candidates". A test-built empty pair shows 0 in every row, each with its typical value, and "below typical" where 0 is under p10 (A7).
6. Snapshots from the spec's list, with A1, A4, and A5 run on the same state: `pairDetail_WU` and `pairDetail_WU_fontScale200` (`trk-manabox-01.csv`, WU). Baselines committed.
7. On `spa-test`, for `trk-manabox-01.csv` opened with "Open file", each of the ten pairs' detail screen shows the two land counts `spa analyze fixtures/pools/trk-manabox-01.csv --set trk` prints in that pair's `landRecommendation`, and its creature count. The Acceptance Tester records a screenshot of WU and one other pair.
