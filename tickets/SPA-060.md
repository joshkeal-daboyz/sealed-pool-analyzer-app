# SPA-060: Tune the deck weights on msh and hob with spa deck-tune

**Goal.** G-005 criterion 6: "The builder's penalties, bonuses and land rules are tuned on `msh` and `hob` only, then frozen and measured on `fra`." SPA-046 measures a weights file. This ticket adds `spa deck-tune`, a deterministic search over a grid of weights that uses that measurement. The Architect runs it after merge on real data, commits the result as `fixtures/weights/deck-tuned.json`, and records the held-out `fra` numbers in the goal file.

- **Quoted from the goal, criterion 7 (the targets the tuning aims at):** "Over all strong builds: colour agreement 50% or more, top-three rate 80% or more, main-deck overlap 16 or more of the player's nonland cards on average, land count within one 85% or more of the time. On builds with three or more main colours, colour agreement 35% or more. The builder beats the two-colour, set-grades baseline on main-deck overlap overall and on colour agreement for three-colour builds."
- **`spa deck-tune <sealed-file>... --set <code,...> [--limit <n>] [--threads <t>] [--grid <file>] [--start <weights file>] [--rounds <r>] --out <file> [--tags <file>] [--otags <file>] [--data <dir>]`.** One Sealed file per set, in the order of `--set`. `--start` defaults to `fixtures/weights/deck-default.json`, `--grid` to `fixtures/weights/deck-grid.json`, `--rounds` to 3. `--limit` is per set, as in `deck-backtest`.
- **The grid** is a JSON object of knobs. Each knob is a path into the deck weights JSON and the list of values to try, for example `"weights.curve": [0, 0.5, 1, 2]`. The default file holds:

  | Path | Values |
  | --- | --- |
  | `weights.curve`, `weights.creatures`, `weights.removal`, `weights.castability`, `weights.fixing` | 0, 0.5, 1, 2 |
  | `weights.synergy` | 0, 0.05, 0.1, 0.2, 0.4 |
  | `params.creatures.minCreatures` | 12, 13, 14, 15 |
  | `params.removal.cap` | 4, 6, 8 |
  | `lands.lowCurve` | 2.4, 2.6, 2.8 |
  | `lands.highCurve` | 3.2, 3.4, 3.6 |
  | `splash.maxCards` | 2, 3, 4 |
  | `splash.maxPips` | 1, 2 |
  | `configs.fourColour.minFixing` | 2, 4, 6 |

  `weights.grades` stays 1 (it sets the scale). The tuner checks, before any run, that the start file parses as deck weights and that every grid value, put at its path in the start file, still parses; a bad path or value is one line naming it, exit 1.
- **The objective** of a weights file: for each set, `overlap share + colour agreement`, where overlap share is the mean main-deck overlap divided by the mean number of nonland cards the players registered, and colour agreement is the overall rate, both from `deck-backtest`'s builder lines for that set; the objective is the mean over the sets. Higher is better.
- **The search** is coordinate ascent. Start from `--start` and its objective. A round visits the knobs in grid-file order; for each, it tries every other value with the other knobs at their current values, and moves to the value with the best objective if that beats the current by more than 1e-9 (ties keep the current value; among equal better values, the first in grid order). It stops when a round changes nothing or after `--rounds` rounds. It is deterministic. After every move it writes the weights to `--out`, so an interrupted run leaves its best so far. It prints one line per evaluation (`round <r> <path> <value> objective <x>`), then a final block: the start and final objectives, each set's builder lines for the start and the final file, and the number of evaluations and seconds.
- **Speed (measured in SPA-046).** `deck-backtest` on `hob` with the default weights took 578.4 s for 200 builds on 1 thread and 319.4 s on 2 threads, about 3 s per build, almost all of it in ranking about 100 configurations. A tuning run of 100 evaluations over 2 sets at 60 builds each is therefore about 5 hours, so the tuner works on a `--limit`ed sample and the cost of an evaluation matters. A failure inside a worker thread must reach the user as one line and exit 1, not an uncaught exception (SPA-046 left it uncaught).
- **Speed.** One evaluation runs the whole backtest for every set. The tuner must not rebuild what a weights change cannot affect: a test shows that results with any caching are identical to a run without it. The change note records the seconds per evaluation for `--limit 100` on `hob` with 2 threads.
- **Alterable.** The objective is its own small interface in its own file, with the objective above as the only entry, so another objective is one file and one line.

## Acceptance criteria

1. **The search.** With a fake evaluator in place of the backtest, unit tests pin: a knob moves to a strictly better value; a tie keeps the current value; among equal better values the first in grid order wins; the search stops after a round with no change; it stops after `--rounds`; the same inputs always give the same path; `--out` is rewritten after each move and holds a file that parses as deck weights.
2. **The grid.** The default `fixtures/weights/deck-grid.json` has the knobs of the table and its start file check passes. Tests reject a bad path, a value that does not parse, and an unknown top-level key, each as one line naming it.
3. **The objective.** Hand-built backtest results pin the formula: overlap share plus colour agreement, averaged over two sets; a set with no used builds is an error naming it.
4. **The command.** A failure inside a worker thread is one line, exit 1. On `syn` with a hand-built Sealed file and a two-knob grid, `spa deck-tune` runs, prints one line per evaluation and the final block, writes `--out`, and the file loads as deck weights and scores no lower than the start on the same file. `--set fra`, `--set trk`, a missing file, a number of files that differs from the number of sets, and a bad number are each one line, exit 1.
5. **Caching.** A test shows the same objective with and without caching for two weights files that differ in one knob.
6. **The seam, and no change elsewhere.** `git diff 2962b0f -- core/src/main fixtures/golden` lists no file. Every SPA-044, SPA-045 and SPA-046 test passes unchanged. The gate is green.
7. **Real data (Acceptance Tester).** `spa deck-tune` on `hob` with `--limit 20 --rounds 1` and a grid of one knob with two values finishes, writes `--out`, and prints two evaluation lines; `--set fra` is refused.
