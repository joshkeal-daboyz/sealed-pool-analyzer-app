# SPA-006: Compute PoolMetrics and the ten ColorPairMetrics for a pool

**Goal.** G-001 deliverable 5, the card-level half: "`PoolMetrics` and ten `ColorPairMetrics`: cards and playables per color by rarity, mana curve per pair, creature counts, removal and interaction tags from rules-text patterns, fixing sources, splash candidates, hypergeometric land math". The baseline is SPA-008. No model calls; every number is a deterministic function of the pool.

## Scope

- Files or modules expected to change:
  - `core/src/main/kotlin/spa/core/metrics/**` (`ColorPair`, `RarityCounts`, `ColorMetrics`, `Curve`, `ColorPairMetrics`, `PoolMetrics`, `MetricEngine`, `SplashCandidate`, `FixingSource`)
  - `core/src/test/kotlin/spa/core/metrics/**`
  - Reconciliation, because SPA-002 and SPA-004 were built in parallel: delete `core/src/main/kotlin/spa/core/cards/Color.kt` and use `spa.core.text.Color` everywhere in `spa.core.cards`; make the internal `spa.core.cards.ManaCost` delegate its colors and mana value to `spa.core.text.ManaCost` or remove it, keeping `CardNormalizer`'s results unchanged. Every existing `spa.core.cards` test must still pass unmodified, except for import lines.
- Not in scope:
  - The set baseline and any "typical value" (SPA-008). `PoolMetrics` holds the pool's numbers only.
  - Card grading, archetype fit, or anything from the format brief.
  - Parsing pools (SPA-005). Tests build `Pool` objects directly from the `syn` index.

## Definitions (these are the contract; the Test Inspector checks the code against them)

- JDK: if `java -version` does not report 21 in your shell, run `export JAVA_HOME="/c/Program Files/Eclipse Adoptium/jdk-21.0.13.9-hotspot"; export PATH="$JAVA_HOME/bin:$PATH"` first. The gate is `pipeline/gate/run.sh`; see the README's Toolchain section. A new or scratch file must also pass detekt's default rules.
- `Pool` and `PoolEntry` now exist in `spa.core.cards` (from SPA-005). Use them; don't redefine them.
- Counts are by copies: a `PoolEntry` with count 2 contributes 2 everywhere.
- `ColorPair` is the enum of the ten pairs in the order `WU, WB, WR, WG, UB, UR, UG, BR, BG, RG`.
- A nonland card belongs to color `c` when `c` is in `card.colors`. It is multicolor when `card.colors` has two or more colors, colorless when `card.colors` is empty. Lands are counted separately and never as a color.
- A card is castable in a pair when it is not a land and `card.colors` is a subset of the pair's two colors (so colorless cards are castable in every pair).
- A card is "playable" for a single color when `card.colors` is exactly that one color. For the multicolor and colorless buckets, playable equals cards.
- Tags come from `RulesTagger.tag(face.typeLine, face.oracleText)` over every face, unioned. Pips come from `ManaCost.parse` of the front face (for `split`, the cheaper face; for `adventure`, the creature face).
- A fixing source is a card whose tags include `FIXING`, or a land whose `ManaProduction.colors` has two or more colors, with its produced colors attached. A pair's fixing sources are those producing at least one of the pair's colors.
- A splash candidate for a pair is a nonland card with exactly one color outside the pair, exactly 1.0 pips of that color, no pips of any other off-pair color, and either the `REMOVAL` tag or rarity rare or mythic.
- The curve has buckets for mana value 0, 1, 2, 3, 4, 5, 6, and 7 or more, each split into creatures and noncreatures.
- The land recommendation for a pair is `LandMath.recommendLands(pips of castable cards summed per color, 17)`. The cast probability per pair color is `Hypergeometric.atLeast(40, lands of that color + fixing sources producing it, 9, 1)`.

## Acceptance criteria

1. `PoolMetrics` holds `totalCards`, `nonlandCards`, `basicLands`, `nonbasicLands`, `byColor: Map<ColorBucket, ColorMetrics>` for the buckets `W, U, B, R, G, MULTI, COLORLESS`, where `ColorMetrics` has `cards: RarityCounts`, `playables: RarityCounts`, `creatures`, `removal`, `interaction` and `RarityCounts` has `common, uncommon, rare, mythic, total`; plus `fixingSources: List<FixingSource>`, `removalTotal`, `interactionTotal`, and `pairs: Map<ColorPair, ColorPairMetrics>` with all ten keys always present.
2. `ColorPairMetrics` holds `cards`, `creatures`, `noncreatures`, `curve: Curve`, `removal`, `interaction`, `fixingSources` (count), `splashCandidates: List<SplashCandidate>` (card name, off-pair color, reason), `landRecommendation: Map<Color, Int>`, and `castProbability: Map<Color, Double>` rounded to 4 decimals.
3. `MetricEngine.compute(pool): PoolMetrics` is a pure function: the same pool gives an equal result on every call, and a pool with entries in a different order gives an equal result.
4. All metric classes are `@Serializable`, and encoding a `PoolMetrics` gives JSON whose top-level keys are exactly the fields of criterion 1 and whose map keys are the enum names, so later tickets can pin it.
5. A hand-built pool of 12 to 20 `syn` cards, chosen so every bucket, tag, and layout rule is exercised, has every number in `PoolMetrics` and in at least two `ColorPairMetrics` asserted by literal values in the test, with a comment per assertion saying which cards produce it. The Developer computes these expected values by hand from the cards, not by running the engine.
6. Edge cases: an empty pool gives all zeros and ten pairs; a pool of only lands gives zero nonland metrics and the land counts; a card with count 3 contributes 3 to every count it belongs to; a double-faced `syn` card is counted by its front face per SPA-002's rules; a colorless artifact is castable in all ten pairs.
7. The curve buckets for a pair sum to that pair's `cards`, and creatures plus noncreatures equal `cards`, for every pair, checked by a property test over 100 random pools drawn from the `syn` index with a fixed seed.
8. The codebase has one `Color` type, `spa.core.text.Color`, and `spa.core.cards` has no mana-cost parsing of its own beyond delegating to `spa.core.text.ManaCost`. All tests in `core/src/test/kotlin/spa/core/cards/` pass with no change other than imports.
