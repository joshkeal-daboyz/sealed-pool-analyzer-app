# SPA-033: Build the grading packet, the response import, and the grading prompt

**Goal.** G-003 deliverable 3 and criteria 2, 4 and 5, on the subscription route (owner decision 2026-11-04, Decided 5): deterministic code that turns a set into a blind grading packet, and code that turns a grader's responses into a validated grade file. The grading itself is done by Claude Fable 5.1 agents in SPA-034; this ticket makes no model call.

## Scope

- Files or modules expected to change:
  - `agent/src/main/kotlin/spa/agent/grader/**` and tests (new)
  - `agent/src/main/resources/spa/agent/grader/prompt-v1.md` (new): the grading instructions, versioned
  - `cli/src/main/kotlin/spa/cli/`: `spa grade-packet <code> --out <dir> [--data <dir>]` and `spa grade-import <code> --responses <dir> --provenance <text> [--data <dir>]`, wired in `Main.kt` and its help text, with tests
  - `fixtures/grades/README.md` (new): how a grade file is made
  - `README.md`: the two commands
- Not in scope:
  - Any grade file under `fixtures/grades/` for a real set (SPA-034). Any model call or API key. `core`, the app.
  - Reading `fixtures/winrates/` or 17Lands while writing the prompt.
- Dependencies this ticket may add (none unless listed):
  - (none)

## Background the Developer needs

- Read G-003 (deliverable 3, criteria 2, 4, 5, Decided 2 and 5, Architect notes and the dated notes at the end).
- **The packet** (`--out <dir>`, overwritten each run, byte-identical for the same inputs):
  - `instructions.md`: `prompt-v1.md`'s text, then the set's format brief rendered as readable text (mechanics with rules text, the archetypes with plan and signposts, speed and speed notes), then a short description of the files.
  - `cards-NN.json` (`01`, `02`, ...): the sealed pool's cards in collector order, 50 per file, each `{ id, name, manaCost, typeLine, rarity, oracleText, power, toughness }` (faces joined for a double-faced card), where `id` is `<setCode>/<collectorNumber>`. The sealed pool is the set plus its companions, basic lands excluded, one entry per distinct card (a showcase or variant printing of the same card is left out; say in the change note how variants are detected).
  - `response.schema.json`: the schema for one response file, `[{ "id": string, "score": number, "confidence": number }]`.
  - The grader writes `cards-NN.response.json` beside each card file.
- **The prompt** (`prompt-v1.md`): the grader reads every card file first, then grades each card on Decided 2's scale (0.0 to 5.0 in steps of 0.5, relative to this set; 3.0 is a solid playable in this set's Limited), with a confidence from 0 to 1 that reflects how sure it is (lower for cards whose value depends on synergy or on unknown format speed). It is told it is grading a set it has never seen played, to use only the packet, and to use no web or other tool besides reading the packet and writing the response files. It writes exactly one entry per card id, in the given files.
- **The import** reads every `cards-NN.json` and its `cards-NN.response.json`, checks every id graded exactly once, no unknown id, every score on the scale and every confidence in [0, 1], and writes `fixtures/grades/<code>.json` through SPA-029's `GradeFiles` with `source` `MODEL` and the given `--provenance` (for example `claude-fable-5-1 via Claude Code, prompt v1, 2026-11-05`). It names every problem and writes nothing on any problem.
- Use the synthetic set `syn` (its cache and brief exist) for tests.
- Work on a local branch named exactly `SPA-033`. This PC runs one Developer at a time. Never rewrite a pushed branch; keep scratch files out of the repository.

## Acceptance criteria

1. `spa grade-packet syn --out <dir>` writes `instructions.md`, `response.schema.json` and the card files; every card in `syn`'s sealed pool (computed from `CardIndex` in the test) appears exactly once across the card files, 50 per file except the last, and running it twice gives byte-identical files.
2. **Blind:** a test generates the `syn` packet and fails if any file contains `winrate`, `gihwr`, `17lands`, `win rate` (any case), or any field name of `fixtures/winrates/*.json`. `instructions.md` contains the prompt's scale and no-tools instruction and the brief's archetype names.
3. `spa grade-import syn` on a complete, valid set of response files (committed test fixtures) writes a grade file equal to a committed expected file, loadable by `GradeFiles.load`.
4. The import fails, writes nothing, and names the card or file for each of: a missing response file, a card id missing, an id graded twice, an unknown id, a score of 2.3, a confidence of 1.2. Exit code 1, one line per problem.
5. `git grep -nE "sk-ant-"` finds nothing new, and nothing in this ticket reads `ANTHROPIC_API_KEY`. The gate is green.
