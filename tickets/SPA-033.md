# SPA-033: Build the Claude grader and grade msh as the first live run

**Goal.** G-003 deliverable 3 and criteria 2, 4, 5 and 7: the grader that gives every card in a set's sealed pool one blind grade, through the Message Batches API and structured outputs, and its first live run, on `msh`, which measures the cost before any other set is graded.

**Blocked until the owner sets `ANTHROPIC_API_KEY`** (G-003, "Before this goal starts", step 1). Do not dispatch before `test -n "$ANTHROPIC_API_KEY"` succeeds in a fresh shell.

## Scope

- Files or modules expected to change:
  - `agent/src/main/kotlin/spa/agent/grader/**` and tests (new); `agent/src/main/resources/spa/agent/grader/` for the prompt text, versioned (`prompt-v1.md` or similar)
  - `agent/src/test/resources/**`: recorded requests and responses for the replay tests
  - `cli/src/main/kotlin/spa/cli/`: `spa grade-set <code>` writing `fixtures/grades/<code>.json`, wired in `Main.kt` and its help text
  - `fixtures/grades/msh.json` and `fixtures/grades/README.md` (new)
  - `README.md`: the command, the key requirement, and what a run costs
- Not in scope:
  - Grading `hob`, `fra`, or `trk` (SPA-034). Tuning the prompt against `msh`'s win rates: the Developer must not open `fixtures/winrates/` or 17Lands while writing the prompt.
  - `core`, the app.
- Dependencies this ticket may add (none unless listed):
  - (none beyond SPA-029's SDK)

## Background the Developer needs

- Read G-003 (deliverable 3, criteria 2, 4, 5, 7, Constraints, Decided 2 and 5) and its Architect notes: the grader reads card data and the format brief, not the baseline.
- Model `claude-opus-5-5`, adaptive thinking, an explicit effort (`high` unless measurement says otherwise), structured outputs (`output_config.format` with a JSON schema), sent through the Message Batches API. Results come back in any order: key them by `custom_id`. Use the `claude-api` skill's Java docs (`java/claude-api/README.md`, `batches.md`, `tool-use.md` for structured outputs) for every class name; do not guess. Handle `stop_reason` `refusal` and `max_tokens`, and say in the change note how.
- **What the model sees per request:** the set's format brief (mechanics, archetypes, speed), the scale (Decided 2: 0.0 to 5.0 in steps of 0.5, relative to this set; 3.0 is a solid playable here), and a group of cards with name, mana cost, type line, rarity, rules text, and power and toughness. Never a win rate, a 17Lands field, a review, or a grade from another source. Split the pool into groups so every card gets a grade; the brief is the shared prefix (prompt caching).
- **Cost:** print input, output, cache-read and cache-write tokens, and dollars at Opus 5.5's published rates with the batch discount ($4 and $20 per million tokens, halved for batches; cache reads $0.20 per million, also halved). Check the rates against the skill's model table before pinning them.
- Recorded responses: capture the live run's request bodies and responses (with the key header never written) and commit a trimmed set for the replay tests.
- Work on a local branch named exactly `SPA-033`. This PC runs one Developer at a time.

## Acceptance criteria

1. With `ANTHROPIC_API_KEY` unset, `spa grade-set msh` prints exactly `ANTHROPIC_API_KEY is not set` on one line and exits 1, with no stack trace and no network call.
2. A replay test runs the grader end to end on recorded responses for a small group and writes a grade file equal to a committed expected file.
3. **Blind:** a test inspects every recorded request body and fails if one contains `winrate`, `gihwr`, `17lands` (any case), or any field of `fixtures/winrates/*.json`. The Acceptance Tester reads one live request body.
4. A test proves that a batch result missing a card, holding a card twice, or holding a card not in the request makes `grade-set` fail with a message naming the card, rather than write a partial file. A refusal or `max_tokens` result is retried once on its own, then fails the run naming the group.
5. `fixtures/grades/msh.json` from the live run holds exactly one grade for every card in `msh`'s sealed pool (set plus companions, basic lands excluded; the count computed from `CardIndex` in a test), every score on the scale, every confidence in [0, 1], `source` `MODEL`, and `provenance` naming the model, the prompt version and the date. It passes the schema.
6. The live run's printed cost and token counts are in the change note and the ticket history. If `msh` alone costs more than $5, the Developer stops and bounces to the Architect before grading anything else.
7. `git grep -nE "sk-ant-"` finds nothing new. The gate is green and makes no network call.
