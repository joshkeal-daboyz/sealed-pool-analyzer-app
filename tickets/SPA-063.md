# SPA-063: Pool bundle and number tables for the analysis agents

**Goal.** G-006 deliverables 2 and 3: "One deterministic text built by code from the resolved pool: every card with quantity, cost, type line, rarity, rules text and set grade; the set's format brief; the pool's kit warnings. Same input, same bytes (a cache needs that)." "A keyed table of the numbers that agent may quote, each with the pool's value and the set baseline's median, 10th and 90th percentile."

## Scope

- Files or modules expected to change: new package `agent/src/main/kotlin/spa/agent/review/` with `ReviewInput.kt`, `PoolBundle.kt`, `GradeLabels.kt`, `NumberTable.kt`, `NumberTables.kt`; tests in `agent/src/test/kotlin/spa/agent/review/`.
- Not in scope: any model call, any agent, prompts, the CLI, `core`, the README (SPA-069 documents the command), reading `fixtures/` from a test (agent tests build their pools by hand, as `agent/src/test/kotlin/spa/agent/poolgrade/PoolGradeTestCards.kt` does).
- Dependencies this ticket may add: none.

## Background the Developer needs

- Files to read: `core/src/main/kotlin/spa/core/cards/CardModel.kt` (`Printing`, `Card`, `Face`), `cards/Pool.kt`, `brief/FormatBrief.kt`, `metrics/PoolMetrics.kt`, `baseline/MetricFlattener.kt`, `baseline/Baseline.kt`, `baseline/Stat.kt`, `intake/KitValidator.kt` (`KitWarning`), `agent/src/main/kotlin/spa/agent/grade/CardGrade.kt`, `grade/GradeLookup.kt`, and `agent/src/test/kotlin/spa/agent/poolgrade/PoolGradeTestCards.kt` for how tests build cards. JDK 21: set `JAVA_HOME` to `C:\Program Files\Eclipse Adoptium\jdk-21.0.13.9-hotspot` if the gate cannot find it.
- From the goal: the bundle is the first, cached system block of every analyst's request, so "same input, same bytes". It holds "no other agent's output and no deck", and no metric numbers: those reach each agent through its own number table, so the cached prefix stays small. "Every set-specific fact reaches an agent through the bundle."
- From the goal: an agent "states numbers only by key; the review prints the value from the table, never the model's own digits, and a finding that names a key with a value the table does not hold is dropped." Keys are the JSON pointers `MetricFlattener.flatten(metrics)` makes (for example `/pairs/WU/curve/buckets/2/creatures`, `/removalTotal`, `/fixingSources/count`); `Baseline.stats` is keyed by the same pointers and each `Stat` has `median`, `p10`, `p90`, `mean`.
- Grade labels (README, G-003 Decided 2), score 0.0 to 5.0 in half steps: `F, D−, D, C−, C, C+, B, B+, A−, A, A+` (index = score times 2; the minus sign is U+2212). `cli` has its own copy in `GradesCommand`; do not touch it.
- Design this ticket fixes (do not redesign):
  - `ReviewInput(set: String, pool: Pool, metrics: PoolMetrics, baseline: Baseline?, brief: FormatBrief, gradeOf: (Printing) -> Double?, kitWarnings: List<KitWarning>)`, a plain data holder. Later tickets may add optional fields with defaults.
  - `PoolBundle.text(input): String` has exactly this layout, every line ending in `\n`, a blank line between sections (the text ends after the last section's last line):

    ```
    # Pool bundle
    Set: <input.set> (<brief.setName>), format speed: <speed lowercase>, brief version <version>
    Speed notes: <speedNotes>
    Grades are 0.0 to 5.0 in half steps, relative to this set; 5.0 is the best.

    ## Set mechanics
    - <name>: <rulesText>

    ## Designed archetypes
    - <colors> <name>: <plan> Signposts: <a>; <b>. Key commons: <x>; <y>.

    ## Generic archetypes
    - <name>: <description>

    ## Pool: <totalCount> cards, <n> distinct
    <count>x <name> | <mana cost> | <type line> | <rarity lowercase> | grade <score to 1 decimal> (<label>) | <rules text>

    ## Kit warnings
    - <message>
    ```

    "Key commons" and its text are left out when the archetype has none; a section with no entries prints `None.` in place of its list (kit warnings too). The pool section groups entries by `oracleId` (summing counts, so two printings of one card are one line), sorted by name (ordinal), and prints a card with no grade as `grade none`. For a multi-face card the name, cost, type line and rules text are each the faces' joined with ` // `; an empty cost prints `-`; newlines inside rules text print as ` / `. Basic lands are lines like any card.
  - `NumberEntry(key: String, value: Double, typical: Stat?)`; `NumberTable(entries)` has `text()`: one line per entry in order, `<key> = <value>` with ` (typical: median <m>, p10 <a>, p90 <b>)` appended when `typical` is not null; a number prints without a decimal point when it is whole, else with at most 4 decimals and no trailing zero. `NumberTable.check(key, value)` returns a `NumberCheck`: `Ok`, `UnknownKey`, or `WrongValue(expected)`; a value is right when it is within 0.00005 of the entry's.
  - `NumberTables.fromMetrics(input, patterns: List<String>): NumberTable` takes the entries of `MetricFlattener.flatten(input.metrics)` whose pointer matches any pattern, sorted by pointer (ordinal), with `typical` from `input.baseline?.stats` (null when there is no baseline or no such pointer). A pattern matches a pointer when it is equal to it, or ends in `/` and the pointer starts with it, with `*` matching exactly one segment (so `/pairs/*/creatures` matches `/pairs/WU/creatures` and not `/pairs/WU/curve/creatures`).
  - `GradeLabels.of(score): String`.

## Acceptance criteria

1. `PoolBundle.text` equals the layout above exactly for a hand-built input (one test pins the whole text): a pool holding a double-faced card, a basic land, a card with no grade, a card with two printings, and a card whose rules text has a newline; a brief with two mechanics, two archetypes (one without key commons) and one generic archetype; and one kit warning.
2. The same input with no kit warnings, no mechanics and no generic archetypes prints `None.` in each of those three sections; calling `text` twice gives the same bytes.
3. The bundle contains no `/pairs/`, no `typical` and no baseline number: a test passes an input with a baseline and metrics and checks the text is unchanged from the same input without them.
4. `GradeLabels.of` returns the 11 labels above for 0.0, 0.5, ... 5.0; a score off the scale throws `IllegalArgumentException`.
5. `NumberTable.text` prints the lines as specified, for a whole value, a value with 2 decimals, a value with 5 decimals (printed to 4) and an entry with and without `typical`.
6. `NumberTable.check` returns `Ok` for the exact value and for a value 0.00004 away, `WrongValue` for a value 0.0001 away, and `UnknownKey` for a key not in the table.
7. `NumberTables.fromMetrics` on a hand-built pool and baseline: the pattern forms (exact, trailing `/`, `*`) each select the entries described; entries are sorted by pointer; `typical` comes from the baseline when it has the pointer and is null when it has not or when the baseline is null; and the values for `/totalCards`, `/removalTotal` and `/pairs/WU/creatures` equal numbers worked out by hand from the hand-built pool (the test names how).
8. The gate is green: format, lint, compile, unit tests, coverage 80 or more on the touched files, no new dependency.
