The namespace is `spa.app`, and `compileSdk` is 36.
2. `app/build.gradle.kts` depends on `project(":core")`. `./gradlew :core:dependencies --configuration runtimeClasspath` lists no `com.android` or `androidx` coordinate. `git diff 077e588 -- core/src/main cli` is empty, and `git diff 077e588 -- core/build.gradle.kts` is empty or changes only the bytecode target.
3. The APK holds `core`'s classes: `"$ANDROID_HOME"/cmdline-tools/latest/bin/apkanalyzer dex packages app/build/outputs/apk/debug/app-debug.apk` lists `spa.core.metrics.MetricEngine` and `spa.core.intake.PoolParser`. On `spa-test`, after `adb install -r app/build/outputs/apk/debug/app-debug.apk`, `adb shell am start -W -n spa.app/.MainActivity` reports `Status: ok`, the screen shows the text "Sealed Pool Analyzer", and `adb logcat -d` holds no `FATAL EXCEPTION` for `spa.app`.

5. The `ui-tests` step runs the app's JVM Compose UI tests and snapshot verification (Robolectric, no emulator). On a pass, `gate-verdict.json` gives `ui-tests` the result `pass` and a note naming how many UI tests and snapshots ran, never `skipped: no app module`. A failing Compose UI test makes the step `fail` with that test's file and line. A snapshot that differs from its stored baseline makes the step `fail` and names the snapshot. The gate never records or updates a baseline; that is a separate Gradle task, named in `pipeline/gate/README.md`.
6. The placeholder screen has one Compose UI test, which asserts the text "Sealed Pool Analyzer" is displayed, and one snapshot named `shell_placeholder`, rendered at 411 × 914 dp. Its baseline is committed.
7. The same committed `shell_placeholder` baseline verifies in the local Windows gate and in CI on Linux, on the same commit. The change note says how: rendering settings, a comparison tolerance (with its value), or both.
8. Android Lint runs on `:app` inside the `lint` step, and issues in Lint's Accessibility category are errors. A Lint error is a gate failure with file and line. A scratch `app/src/main/res/layout/scratch.xml` holding an `ImageView` with no `contentDescription` fails the `lint` step, naming that file. Remove the scratch file before pushing.
9. A semantics check runs in the gate under Robolectric. A test helper walks the Compose semantics tree (`onAllNodes(hasClickAction())` and the merged tree), and fails, naming the node, when a clickable is smaller than 48 × 48 dp on its touch bounds or has no label (neither text nor a content description). It fails on a test-only composable with a 30 × 30 dp unlabelled clickable, and on one with a 48 × 48 dp unlabelled clickable, each naming the node, and passes on the placeholder screen. Compose's `enableAccessibilityChecks()` (ATF) is not used: it does not evaluate Compose content under Robolectric (bounce of 2026-11-03).
10. The `format` step covers `app/**/*.kt` and `app/build.gradle.kts`, and so does detekt in the `lint` step. A formatting error in a scratch app Kotlin file fails `format`, naming that file.
11. The `coverage` step covers `app/src/main/kotlin`, each touched file against `:app`'s Kover report. A touched app file below the ticket threshold fails the step, naming the file. This ticket's own files meet its threshold of 70.
12. The `dependencies` step audits the catalog entries this ticket adds. An extra unlisted `[libraries]` entry in a scratch commit fails the step, naming the coordinate. The entries listed above pass.
13. The CI workflow gives the gate an Android SDK, either the one preinstalled on `ubuntu-latest` (`$ANDROID_HOME`) or a setup action pinned to a major version, named in the change note. ## Change note

**Bounce to the Architect on criterion 9. Stopped before the gate work. Nothing pushed, 0 of 3 attempts used, no local gate runs.**

- Criterion 9 cannot be met as written. `enableAccessibilityChecks()` (ui-test-junit4-accessibility 1.11.4, ATF 4.1.1, the newest ATF release) runs under Robolectric 4.17, but ATF does not evaluate Compose content there. Run directly, every ATF check returns `NOT_RUN` on the `AndroidComposeView`, with the message "Composable content is not evaluated in this environment". So the 30 × 30 dp unlabelled clickable passes (`AccessibilityChecksTest.smallUnlabelledClickableFailsTheChecks` fails because nothing is thrown), and the placeholder screen passes only because nothing is checked. Enabling Robolectric's accessibility manager (`ShadowAccessibilityManager` enabled, touch exploration on) changes nothing. Building ATF's hierarchy from `AccessibilityNodeInfo` doesn't help either: Robolectric returns Compose's virtual child as an empty node (no class, zero bounds, not visible). Options for a re-plan: run the A4 ATF checks as instrumented tests on `spa-test` (outside the gate); write gate-side checks over the Compose semantics tree (touch bounds of 48 dp or more, a label on every clickable), which are not ATF; or accept the checks as Acceptance Tester work.
- What's on branch `SPA-013` (local commit, not pushed): the `:app` module (AGP 9.5.0 with built-in Kotlin, so no `org.jetbrains.kotlin.android`; Kotlin stays 2.4.21, so criterion 14 holds), the placeholder screen, a Compose UI test, and the `shell_placeholder` snapshot (Roborazzi, recorded on Windows at 411 × 914 dp xxhdpi). `assembleDebug` passes, and `aapt2` and `apkanalyzer` give the values criteria 1, 3 (dex part), and 4 ask for. `core` dexes without a bytecode change. Not started: everything in `build-logic` (format, lint, ui-tests, coverage, and dependencies for `:app`), Android Lint config checks, the CI workflow, and the README.
- The next ticket should know: Compose BOM 2026.08.00 and later (Compose 1.12) need `compileSdk` 37, so the catalog pins BOM 2026.06.01 (Compose 1.11.4) to keep `compileSdk` 36. Robolectric 4.17 on JDK 21 needs `--add-opens=java.base/jdk.internal.access=ALL-UNNAMED` (and `java.io`) on the test JVM. AGP 9.5 deprecates `lint { xmlOutput }`. Snapshot library: Roborazzi, chosen because criterion 9 needs Robolectric anyway; Paparazzi entries were not added. Criterion 7 is not settled: no Linux render has run yet.
