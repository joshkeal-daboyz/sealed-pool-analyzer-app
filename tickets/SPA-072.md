# SPA-072: spa build --export - write each deck as a ManaBox-importable file

**Goal.** G-006, owner's workflow of 2026-11-06 (relayed): "if the agents can create a manabox export for me that's good enough" and "I can import the deck back into manabox". The owner exports the pool from ManaBox as CSV, runs the tool on the PC, and wants the chosen deck written in a form ManaBox can import, so the registered deck is on the phone. `spa build` prints decks and has no export today. Model-free, `cli` only; the deadline is the trk prerelease at 3PM on 2026-11-06, so keep it small.

- Not in scope: `agent/` and `core/` (no change), the packet (SPA-071), a sideboard file, importing anything, a model call, verifying the import in the ManaBox app (it cannot be done here; the owner tries it).
- Dependencies this ticket may add: none.

- Design this ticket fixes (do not redesign): `spa build ... --export <dir>` (works with and without `--colours`, with `--top`). After building, for each deck it prints it also writes two files into `<dir>` (created if missing; existing files of the same name replaced), named `rank-<n>-<colours>` for the ranked form and `deck-<colours>` for `--colours`, where `<colours>` is the configuration text with `/` written `+` (so `WU/R` is `WU+R`), with extensions `.csv` and `.txt`. stdout stays byte for byte what it prints without `--export`; one line per file written, `Wrote <path>`, goes to stderr.
  - **`.csv`**: the header above, then one row per distinct card in the 40: spells and nonbasic lands as the pool printing the builder used (`Printing` found through the `DeckCard` id), then the basic lands in WUBRG order (only colours with a count above 0), each as the set's own basic land: the printing in `index.printings(<set>)` whose card is a basic land of that name with the lowest collector number (Plains, Island, Swamp, Mountain, Forest), falling back to the same rule over the set's companion sets' printings if the set has none. Columns: Name; Set code upper case; Set name = the brief's set name for the main set and empty for another set; Collector number; Foil `normal`; Rarity lowercase; Quantity = copies in the deck; ManaBox ID empty; Scryfall ID the printing's; Purchase price empty; Misprint `false`; Altered `false`; Condition `near_mint`; Language `en`; Purchase date empty; Purchase price currency empty. Rows in this order: spells and nonbasic lands by name (ordinal), then basics. Line endings `\n`; quoting as the owner's file (a field is quoted when it holds a comma or a quote; quotes doubled).
  - **`.txt`**: the same cards, one line each, `<quantity> <name> (<SET CODE>) <collector number>` (for example `2 Island (TRK) 308`), in the same order, no header, no comments, no sideboard.
  - A deck whose file cannot be written is one line on stderr and exit 1.

## Acceptance criteria

1. `spa build fixtures/pools/trk-manabox-01.csv --set trk --weights fixtures/weights/deck-tuned.json --top 3 --export <dir>` exits 0, stdout equals the same command without `--export`, and `<dir>` holds `rank-1-<colours>.csv`, `.txt`, `rank-2-...`, `rank-3-...` (six files) named from the printed `Rank <n>: <colours>` headings.
2. Each `.csv` has the exact header above; its quantities sum to 40; every row's Scryfall ID and set code and collector number agree with the set's cache (`index.byScryfallId`); the basic-land rows are TRK 307 to 311 for the colours the deck plays.
3. Round trip: parsing each `.csv` with the existing `PoolParser` and the ManaBox format against the trk index gives a pool of 40 cards whose copies per oracle id equal the exported deck's spells, nonbasic lands and basics (a test checks the counts for all three decks).
4. Each `.txt` has one line per `.csv` row in the same order, every line matches `^\d+ .+ \([A-Z0-9]+\) \S+$`, and its quantities sum to 40.
5. A card name with a comma (He's Dead, Jim, if the deck plays it, or a hand-built card in the test) is double-quoted in the `.csv`, with a quote inside doubled; a multi-face card is exported under the name the pool printing has.
6. With `--colours WU/R --export <dir>` the files are `deck-WU+R.csv` and `deck-WU+R.txt`; the export directory is created when missing; a second run replaces the files and gives the same bytes; running with an unwritable `--export` path (a file where the directory should be) is one line on stderr and exit 1.
7. `README.md`'s `build` paragraph documents `--export` (file names, columns, the `.txt` fallback, stdout unchanged, the import note: the owner tries the `.csv` in ManaBox, and the `.txt` if that fails); `Main.kt`'s usage text lists the option.
8. The gate is green: format, lint, compile, unit tests, coverage 80 or more on the touched files, no new dependency.

## Change note

`DeckExport` (new, `cli`) builds the rows, `.csv` and `.txt` and writes them; `BuildCommand` ranks, exports each deck, then prints, so stdout is unchanged and a write failure prints nothing on stdout. `--export` loads the set brief for the set name (a missing brief is exit 1, only with `--export`). A card id maps back to its pool printing through `index.byCollectorNumber`; basics use the lowest collector number (`GradingPool.collectorOrder`) among the main set's basic lands, else the companions'. Not done: verifying the import in ManaBox (the owner tries it). Tests added: `DeckExportTest` (criteria 2 to 5) and `BuildExportTest` (criteria 1, 6, help text) rather than additions to `BuildCommandTest`.
