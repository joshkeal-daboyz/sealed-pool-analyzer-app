# SPA-050: Run the owner's synergy checks

**Goal.** G-005 Architect notes (2026-11-05): the owner's example cards are held-out tests of the synergy tags and the pair table, not inputs. This ticket adds `spa synergy-check --set <code>`, which reads `fixtures/synergy-checks/<code>.json` (already committed, with its README) and reports each check as pass or fail, with its numbers.

## Background the Developer needs

- Read `fixtures/synergy-checks/README.md` and `fixtures/synergy-checks/trk.json`, the G-005 Architect notes on the owner's checks, and SPA-048 (`SynergyTable`, the pair score).
- **Check kinds.**
  - **`pair`:** passes when `score(a, b) >= min`. The result prints the score, the axis part and the partner part.
  - **`groups`:** over every pair (a in `groupA`, b in `groupB`, a ≠ b), it counts the pairs with `score >= min` and passes when that count divided by the pair count is greater than `share`. The result prints the pair count, the count meeting `min`, the share to 4 decimals and the mean score to 4 decimals.
  - An unknown kind, or a card id missing from the set's tag file, is one line and exit 1, and no check runs.
- **Output.** One line per check, in file order: `PASS` or `FAIL`, the id, the status (`independent` or `seen`), then the numbers. The last line reads `<passed> of <total> checks pass (<k> independent)`. A failing check is a result, not an error: exit 0 whenever the file and tags read. Missing check file, missing tag file or unknown set: one line, exit 1.
- **Independence.** The command reads the check file only when it runs. A test proves that no tags packet, grade packet or prompt resource contains a check id or the word `synergy-checks`.
- **Alterable.** Each check kind is its own class behind one interface, in a list keyed by `kind`. A new kind is one file.
- **Pinned numbers** come from an independent script (scratchpad `tools/synergy.js` and `tools/checklists.js`, 2026-11-05) over the committed `fixtures/tags/trk.json`.
- Work on a local branch named exactly `SPA-050`. One Developer at a time. Never rewrite a pushed branch; keep scratch files out of the repository. JDK: README, Toolchain section.
