# SPA-024: Make every gate failure's reproduce command run as printed

**Goal.** The gate contract in `pipeline/gate/README.md`: each failure in `gate-verdict.json` carries a `reproduce` command, and "A Developer reads `failures` and nothing else." SPA-013's Acceptance Tester found that a `ui-tests` failure prints `./gradlew :testDebugUnitTest -Proborazzi.test.verify=true --tests ...`, which lacks the `:app` prefix and fails with "task 'testDebugUnitTest' not found in root project". This supports G-002 deliverable 1, and every later app ticket's Developer relies on it.

## Scope

- Files or modules expected to change:
  - `build-logic/src/main/kotlin/spa/gate/**`, where each step builds its failures' `reproduce` string
  - `build-logic/src/test/kotlin/spa/gate/**`
- Not in scope:
  - Which steps the gate runs, their order, what makes them fail, and the verdict's shape. Only the `reproduce` strings change.
  - `pipeline/gate/run.sh`'s fallback verdict (it prints `./gradlew check`, which runs).
  - Any file under `app/`, `core/`, `cli/`, or `.github/`.
- Dependencies this ticket may add (none unless listed):
  - (none)

## Acceptance criteria

1. A `ui-tests` failure for a failing app test prints a `reproduce` command that starts with `./gradlew :app:`, names that test class with `--tests`, and verifies snapshots the way the gate does. A unit test pins the string for a sample JUnit result with a Windows path, and one for a differing snapshot.
2. For each step, a scratch failure's printed `reproduce` command, run from the repository root exactly as printed, runs without a "task not found" or usage error, and fails on the same problem the verdict names: `format` (a misformatted app Kotlin file), `lint` (an Android Lint error in a scratch layout, and a detekt error in a scratch Kotlin file), `compile` (a scratch syntax error in `app`), `unit-tests` (a failing `core` test), `ui-tests` (a failing app UI test, and a changed `shell_placeholder` baseline), `coverage` (an untested app file), and `dependencies` (an unlisted catalog entry).
3. Every existing `build-logic` test still passes. Any test that pinned an old `reproduce` string is updated, and the change note names each one.
