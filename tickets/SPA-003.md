# SPA-003: Define the format brief JSON schema, its loader, and an example brief

**Goal.** G-001 deliverable 3: "A JSON schema for the per-set format brief (mechanics with rules text, the ten designed two-color archetypes with signpost uncommons, the generic archetypes, the kit template, expected format speed) and a loader for it." Goal-level criterion 3 is closed when the human's hand-written `fixtures/briefs/trk.json` loads through this ticket's loader.

  - `core/src/main/kotlin/spa/core/brief/**` (`FormatBrief`, `Mechanic`, `Archetype`, `GenericArchetype`, `KitTemplate`, `BoosterSlot`, `FormatSpeed`, `BriefLoader`, `BriefValidationException`)

## Background the Developer needs

- JDK: if `java -version` does not report 21 in your shell, run `export JAVA_HOME="/c/Program Files/Eclipse Adoptium/jdk-21.0.13.9-hotspot"; export PATH="$JAVA_HOME/bin:$PATH"` first. The gate is `pipeline/gate/run.sh`; see the README's Toolchain section. A new or scratch file must also pass detekt's default rules.
- A prerelease kit for a current set is six Play Boosters plus one dated foil promo rare or mythic. A Play Booster has 14 cards. The published composition the example should model: 6 common slots; 1 common slot that is a bonus-sheet card a small fraction of the time; 3 uncommon slots; 1 rare-or-mythic slot (mythic roughly 1 in 7); 1 non-foil wildcard of any rarity; 1 traditional-foil wildcard of any rarity; 1 land slot that is a basic land most of the time and a common nonbasic land otherwise. The token or art-card slot is not a card and is not modeled.
- The brief is documentation for humans and input for code. Everything is JSON Schema draft 2020-12 with `additionalProperties: false` on every object so typos are errors.

## Acceptance criteria

1. The schema file exists at the path above and is a valid draft 2020-12 schema. It defines an object with required `setCode` (lowercase letters and digits, 3 to 5 characters), `setName`, `version` (positive integer), `speed` (one of `fast`, `medium`, `slow`), `speedNotes` (string), `mechanics`, `archetypes`, `genericArchetypes`, `kitTemplate`, and optional `companionSetCodes` (array of set codes).
2. `mechanics` is a non-empty array of `{ name, rulesText, reminderText? }`. `archetypes` is an array of exactly 10 objects `{ colors, name, plan, signpostUncommons, keyCommons? }` where `colors` is a two-character string of distinct letters from `WUBRG` and `signpostUncommons` is a non-empty array of card names; the loader additionally rejects a brief whose ten `colors` values are not exactly the ten color pairs (order-insensitive, so `WU` and `UW` are the same pair). `genericArchetypes` is an array (may be empty) of `{ name, description, colors? }`.
3. `kitTemplate` is `{ boosters (integer >= 1), cardsPerBooster (integer >= 1), slots, promo, basicLandsSupplied (boolean) }`. `slots` is a non-empty array of `{ name, count (integer >= 1), foil? (boolean), weights }` where `weights` is an object whose keys are drawn from `common`, `uncommon`, `rare`, `mythic`, `basicLand`, `commonLand`, `bonusSheet` and whose values are numbers > 0. `promo` is `null` or `{ weights }` with the same shape. The loader additionally rejects a template whose slot counts do not sum to `cardsPerBooster`.
4. `BriefLoader.load(path)` and `BriefLoader.parse(json)` return a `FormatBrief` for a valid document and throw `BriefValidationException` otherwise. The exception's `errors` lists every violation found by the schema validator plus the semantic checks in criteria 2 and 3, each with a JSON pointer to the offending location and a message; nothing is reported as a bare "invalid".
5. `fixtures/briefs/syn.json` is a complete brief for set `syn` with `version` 1, at least 3 mechanics, all 10 archetypes with made-up but plausible names, at least 2 generic archetypes, and a kit template modeling the Play Booster composition above with `boosters` 6, `cardsPerBooster` 14, a non-null promo, and `basicLandsSupplied` true. It loads.
6. Invalid examples under `core/src/test/resources/briefs/` each fail with the expected pointer: a missing required field, an unknown property, a duplicate color pair, a `colors` value with a repeated letter, slot counts not summing to `cardsPerBooster`, a weight of 0, and an `archetypes` array of 9.
7. `FormatBrief` and its parts are `@Serializable` Kotlin data classes; round-tripping `syn.json` through `parse` then `encodeToString` then `parse` gives an equal object.
8. `fixtures/briefs/README.md` tells the human how to write `trk.json`: copy `syn.json`, which fields to change, and that the kit template section can be kept as is.
