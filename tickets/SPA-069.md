- Design this ticket fixes (do not redesign):
  - `DeckSummary(rank, colours: String, sameAs: List<String>, score: Double, spells: List<NameCount>, landCount: Int, lands: List<NameCount>, why: String)`, `NameCount(name, count)`. `DeckSummary.of(rank, ranked: RankedDeck)`: `colours` is `ranked.config.toString()` (as `Rank <n>: <colours>` prints in `spa build`), `sameAs` the other configurations' strings, `score` the scored total, `spells` the deck's distinct spell names with copy counts sorted by name, `lands` the nonbasic lands played then the basics (`Plains`, `Island`, `Swamp`, `Mountain`, `Forest` for W, U, B, R, G, as `BuildLines` names them, only colours with a count above 0, in WUBRG order), and `why` the two parts with the largest absolute value (ties in part order) that have a reason, each `<key> <+ or - and 2 decimals>: <reason>`, joined by `; `. `text()` is the deck's block in the review, exactly these lines (no blank line inside): `Rank <rank>: <colours>` plus ` (same cards as <a>, <b>)` when `sameAs` is not empty, then two spaces and `score <2 decimals>`; `  Spells (<n spells>): <count>x <name>, ...`; `  Lands (<landCount>): <count>x <name>, ...`; `  Why: <why>` (the line is left out when `why` is empty).
  - `ReviewHeader(set, setName, totalCards, distinct, unresolved, kitWarnings: List<String>)`. `Review(header, decks: List<DeckSummary>, verdict: ExplainerOutcome, sections: List<AgentOutcome>, usage: UsageTotals, model: String)` with derived `disagreements` (the Explainer's, or empty) and `missing: List<MissingEntry(id, reason)>` (every `Missing` analyst in agent order, then the Explainer if it is `Missing`).
  - `ReviewRun(client, usage: () -> UsageTotals, config, agents).run(input, decks, header): Review`: runs `AgentRunner`, then (only after every analyst has finished) `Explainer.run` with `decksText` = the decks' `text()` blocks joined by a newline, the deck ranks, and the outcomes; with no decks the Explainer is `Missing("no deck could be built")` with no call, analysts still run. `usage()` is read after the last call.
  - `ReviewText.render(review): String` ends with a newline and has these blocks in this order, one blank line between blocks:
    1. `Review: <set> (<setName>)`, `Pool: <totalCards> cards, <distinct> distinct, <unresolved> unresolved lines`, and a line `Kit warning: <message>` per warning.
    2. `Decks`, then each deck's `text()`, or `No deck could be built from this pool.`
    3. `Verdict`, then the verdict, then a line `Rank <r>: <note> (cards: <names joined by ", ">)` per kept deck note in rank order, then `Dropped notes: <n> (<reason words>)` when any were dropped; or `Not available (<reason>).` when the Explainer is `Missing`.
    4. One block per `Answered` analyst, in `sections` order: `<title>  (confidence <0.00>)`, the summary, one line per kept finding `- [<severity>] <pair, only when not null>: <claim> (cards: <names, ", ">)` followed, when it has numbers, by ` (numbers: <key> = <value> (typical <median>, range <p10> to <p90>); ...)` (the typical part only when present; numbers formatted as `NumberTable` formats them), `No findings kept.` when none, and `Dropped findings: <n> (<reason words>)` when any were dropped. Reason words: `no card`, `unknown card`, `unknown number key`, `wrong number value`, `over the limit` (analysts); `unknown rank`, `duplicate rank`, `unknown agent`, `too few agents`, `no card` and `unknown card` (Explainer notes; `TOO_FEW_AGENTS` is a drop reason SPA-068 added, with a `DroppedItem` kind of DECK or DISAGREEMENT); reasons listed in enum order as `<words> <count>`, separated by `, `.
    5. `Disagreements`, then `- <topic> [<id>, <id>]: <note> (cards: <names>)` per kept disagreement, or `None.`
    6. `Missing: none` or `Missing: <id> (<reason>); <id> (<reason>)`.
    7. `Usage: <calls> calls, input <n>, output <n>, cache read <n>, cache write <n> (model <model>)`.
    8. The attribution line.
  - `ReviewJson.render(review): String`: pretty-printed JSON ending in a newline with these top-level keys in this order: `set`, `setName`, `pool` (`totalCards`, `distinct`, `unresolved`, `kitWarnings`), `decks` (rank, colours, sameAs, score, spells, landCount, lands, why), `verdict` (`status` `explained` or `missing`; `text`, `confidence`, `deckNotes`, `dropped` when explained; `reason` when missing), `agents` (one object per analyst in order: `id`, `title`, `status` `answered` or `missing`; `confidence`, `summary`, `findings` (severity, pair, claim, cards, numbers with key, value and a `typical` object or null), `dropped` (reason, claim) when answered; `reason` when missing), `disagreements`, `missing` (id, reason), `usage` (calls, input, output, cacheRead, cacheWrite), `model`, `attribution`.
  - The text and JSON depend only on the `Review`: the same review gives the same bytes.

## Acceptance criteria

1. `DeckSummary.of` on a deck built in a test (two parts with reasons, one off with no reason): colours, `sameAs`, score, spells counted and sorted by name, lands (a nonbasic land, then basics in WUBRG order, none for a colour with 0), landCount, and `why` from the two largest absolute parts (and from one part only, and empty, when fewer have reasons).
2. `DeckSummary.text()` equals the specified lines, with and without `sameAs`, with and without `why`.
3. `ReviewText.render` equals the whole specified text for one hand-built review holding: two kit warnings, two decks, an explained verdict with a deck note and two dropped notes, an answered analyst with a finding that has numbers (one with a `typical`, one without) and dropped findings of two reasons, an answered analyst with no kept finding, a missing analyst, one disagreement, and usage (one test pins the whole text).
4. `ReviewText.render` for a review with a missing Explainer (`Verdict` then `Not available (<reason>).`), no decks, no kit warnings, no disagreements and nothing missing equals the specified text.
5. `ReviewJson.render` parses as JSON, has the top-level keys in the order given, and its values equal the review's (a test pins the whole JSON for the criterion 3 review); the same review gives the same bytes twice.
6. `ReviewRun` with a fake client answering every agent and the Explainer: the `Review` holds the sections in agent order, the Explainer's request is sent only after every analyst's call has returned, its `decksText` is the decks' blocks joined as specified and its user message holds every kept finding's claim, `usage` equals the client's totals, and `missing` is empty.
7. `ReviewRun` with every analyst failing (invalid answers twice): no Explainer call is made, `missing` lists every analyst in order then `explainer (no findings to explain)`, and `ReviewText.render` still prints the header, the decks, `Not available (no findings to explain).`, `None.`, the `Missing:` line, the usage line and the attribution.
8. `ReviewRun` with an empty deck list: analysts run, the Explainer is `Missing("no deck could be built")` with no call, and the text prints `No deck could be built from this pool.`
9. The gate is green: format, lint, compile, unit tests, coverage 80 or more on the touched files, no new dependency.
