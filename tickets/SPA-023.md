## Acceptance criteria

1. "Toolchain" names the Android SDK requirement: the command-line tools, `ANDROID_HOME` set and visible in Git Bash, the `platform-tools`, `emulator`, and `system-images;android-36;google_apis;x86_64` packages, and accepting the licenses yourself with `sdkmanager --licenses`. It also says that a terminal opened before the install does not see the new variables.
2. "Android app" holds exactly these promises, each runnable as written from a fresh clone on a machine with the prerequisites:
   - The build command `./gradlew :app:assembleDebug` and the output path `app/build/outputs/apk/debug/app-debug.apk`.
   - The command that runs the app's JVM tests (the task name from SPA-013), and that the gate runs them too.
   - Install route one, copying the APK to the phone and allowing "Install unknown apps" for the app that opens it.
   - Install route two, `adb install -r app/build/outputs/apk/debug/app-debug.apk` after enabling USB debugging.
   - That the app needs no account, no key, and no network permission. The last can be checked with `aapt2 dump permissions` on the APK.
3. The Acceptance Tester follows the README literally from a fresh clone: the build command writes the APK at the stated path, the test command runs and passes, `adb install -r` with the stated path installs on `spa-test`, and the permissions check shows no `android.permission.INTERNET`. Route one is checked by reading, against the goal's step 8.
4. `git diff 077e588 -- README.md` changes nothing in the "Card data" section, and adds no claim beyond criteria 1 and 2.
