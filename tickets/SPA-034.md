# SPA-034: Grade msh, hob, fra and trk with Fable, run the backtest, and add spa grades

**Goal.** G-003 deliverables 3, 5 and 6 and criteria 4, 6, 7 and 9: the Claude grades for the three backtest sets and `trk`, the backtest on all three, and `spa grades` for a pool.

## How the grading runs (before the Developer starts)

The Architect does the grading, as a pipeline step, with no API key (Decided 5):

1. On `main`, `spa grade-packet <code> --out <scratchpad>/grading/<code>` for `msh`, `hob`, `fra` and `trk`.
2. One fresh Claude Fable 5.1 agent per set (Agent tool, model `fable`), told to read only `instructions.md` and the card files in its packet folder, use no web or other tool, and write the response files there. Its prompt names only the folder; it gets no repository path, no win-rate file, no other set.
3. The Architect records each run's token count and the weekly Fable plan percentage before and after in this ticket's History, and checks each response folder with `spa grade-import <code> --responses <folder> --provenance ... --data fixtures` into a scratch copy. A run that fails the import is re-run once with the import's problem list; a second failure is a bounce to the Architect.
4. The response folders are handed to the Developer by path.

The prompt is SPA-033's `prompt-v1.md`, unchanged: the backtest measures that prompt, and changing it after seeing results would fit the test sets.
