# SPA-043: Pluggable card adjustment parts, with tag synergy as one of them

**Goal.** G-005 Constraints ("easy to change how cards and decks are scored"). G-004's `PoolGrader` hard-codes three adjustments: a sealed `Part` interface and a fixed `Weights` class of four keys. This ticket makes each adjustment its own pluggable part, with weights read from a file by key. It adds SPA-048's tag synergy as a fourth part, and every existing output stays byte-identical. SPA-044's deck builder reads the adjusted grades through this list.

## Scope

- Files or modules expected to change:
  - `agent/src/main/kotlin/spa/agent/poolgrade/**` and tests
  - `agent/src/main/kotlin/spa/agent/deckpick/**`: only where it constructs weights or the grader
  - `cli/src/main/kotlin/spa/cli/`:
    - `pool-grades` gains `--tags <file>`, as SPA-053 did for the synergy commands;
    - `PoolGradeLines` prints each part's own reason;

  - `README.md`
- Not in scope:
  - Tuning any weight (SPA-046). Changing `default.json` or `tuned.json`. `core`. Any tag, grade, check or baseline file.
- Dependencies this ticket may add (none unless listed):
  - (none)

## Background the Developer needs

- Read G-005's Constraints and SPA-038 (the three rules and their reason lines), SPA-039 (`deck-pick`, `Tuning`, `TunedWeights`), SPA-048 (`TagSynergy`) and SPA-053 (`--tags`, the frozen `fixtures/tags/v1/`).
- **The part interface.** `CardPart` has:
  - `key`, its name in the weights file;
  - a function giving, for one candidate card in one pool and pair, its weighted value and its one reason line, or no line when the value is 0.

  `CardParts.ALL` lists, in this order: `synergy` (G-004's counted synergy, unchanged), `curve`, `colour`, `tagSynergy`. `PoolGrader` sums the parts in list order, applies `cap`, and clamps to 0 to 5, exactly as now. `PoolGradeLines` prints each nonzero part's reason line in list order. The first three parts' reason text is unchanged.
- **Weights by key.** A weights file is a JSON object of numbers:
  - `cap`, plus one key per part, each finite and 0 or more;
  - a part missing from the file has weight 0;
  - an unknown key is an error naming it;
  - `default.json` and `tuned.json` parse unchanged.

  `TunedWeights.encode` writes `synergy`, `curve`, `colour` and `cap` as today, and adds `tagSynergy` (before `cap`) only when it is above 0 (ruling, History). The tuning grid in `Tuning` stays the old three keys (synergy, curve, colour), with `tagSynergy` 0, so `deck-pick --tune` output is unchanged. Adding `tagSynergy` to the grid is SPA-046's.
- **The tag synergy part.** Its value is SPA-048's part for that card and pair (`weight × clamp((syn − e) / max(e, 1), −1, 1)`), with the weight read from the `tagSynergy` key. The tag file comes from `--tags <file>`, or from `<data>/tags/<code>.json` by default. It is read only when `tagSynergy` is above 0. Its reason line has the form `tag synergy +0.13: 26 with the pool, 20.69 typical (Starfleet Spanner Jockey, Hemmer, Fixing What Is Broken, Cetacean Ops)`, naming SPA-048's three top partners.
- **Alterable.** A test adds a test-only part to the list, reads its weight from a file, and sees its value and reason line, with no other code change.
- **Pinned values** are SPA-038's and SPA-048's, unchanged; nothing new is scripted.
- Work on a local branch named exactly `SPA-043`. One Developer at a time. Never rewrite a pushed branch; keep scratch files out of the repository. JDK: README, Toolchain section. On Windows Git Bash, pass `C:/...` paths to the JVM.
