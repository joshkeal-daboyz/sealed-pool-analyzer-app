# SPA-051: Card facts, axis supply and tags prompt v2

**Goal.** The owner approved this on 2026-11-05 (G-005 Architect notes): "There should be tags associated with the cards that assist in identifying synergy." Three parts:
- **Card facts:** a tag layer made by code from card data.
- **Axis supply:** a set's axes name which facts supply them, so a land supplies landfall and a legendary permanent supplies legendary payoffs without Fable tagging each card.
- **Tags prompt v2:** asks for that supply, with the axis cap raised from 15 to 20.

The four sets are retagged with v2 by the Architect after merge.

## Background the Developer needs

- Read G-005's Architect notes from "Owner approved ('Yes do it')", SPA-047 (packets, import, check list) and SPA-048 (`PairTerm`, `SynergyTable`). Keyword data comes from `fixtures/scryfall/<code>/cards.json` by oracle id, as SPA-035's themes read it; `core` keeps no keywords.
- **Card facts.** Each sealed-pool card (`GradingPool`) gets a set of facts. Rules, using the front face's type line and text with reminder text removed:
  - **Card types:** `land`, `creature`, `artifact`, `enchantment`, `planeswalker`, `instant`, `sorcery` and `battle`, for each that the front face's types include.
  - **`legendary`:** the front face is Legendary.
  - **`type:<subtype>`:** for each creature subtype of a creature front face, lowercased, non-letters and non-digits turned into hyphens (`type:human`, `type:klingon`).
  - **`kw:<keyword>`:** for each entry of the card's Scryfall `keywords`, slugged the same way (`kw:deathtouch`, `kw:basic-landcycling`).
  - **Self-granted `kw:<keyword>`** (owner, 2026-11-05: "Moopsy should have a reach tag as well"): the front face says "this creature", its full name or its short name, then "gains" or "has", then one of flying, reach, deathtouch, lifelink, first strike, double strike, trample, vigilance, haste, menace, hexproof or indestructible. Only the words before any "until", "as long as" or "if" count. Moopsy's "{2}: This creature gains reach until end of turn." gives `kw:reach`.
  - **`cheap`:** not a land, and mana value 2 or less.
  - **`enters-trigger`:** the front face has its own enters trigger. That is `When` or `Whenever`, followed by "this creature", "this permanent", "this artifact", "this enchantment", "this land", "this Spacecraft", "this Vehicle", the card's full name or its name before the first comma, followed by "enters".
  - **`dies-trigger`:** the same pattern with "this creature", the full name or the short name, followed by "dies".
  - **`makes-token`:** any face says "create" or "creates", followed later in the same sentence by "token" or "tokens".
- **Alterable.** Each fact family is its own `FactRule` in its own file, in a list; a new fact is one file.
- **Prompt v2.**
  - **Pass 1:** the packet adds `facts.json` (card id to its facts) and a "Card facts" section in `instructions.md` listing each fact with its count in the set, most common first, then by name. The card files stay byte-identical to the grade packet's.
  - **Pass 1 response:** each axis carries `suppliedBy: [ { "fact", "strength": 1 to 3 } ]`, which may be empty. Every fact must be one that at least one card in the set has.
  - **Axis count:** 3 to 20. The cap of 15 stays for v1.
  - **Pass 2:** the instructions show each axis's `suppliedBy`. The tag file stores `suppliedBy` on each axis and the prompt version in its provenance. Prompt v1 packets, axes files and tag files work exactly as before.
- **The prompts** are the Architect's; copy them into the resource files word for word.
  - `tags-axes-v2.md` is `tags-axes-v1.md`'s text with "between 3 and 15 axes" changed to "between 3 and 20 axes", and this paragraph inserted before "Use only the files in this folder.":
    > Each card also has facts, listed with their counts under "Card facts" below and per card in `facts.json`: what it is (a card type, legendary, its creature types), its keywords (`kw:`), whether it is cheap (mana value 2 or less), and whether it has its own enters trigger, dies trigger or makes tokens. For each axis, list under `suppliedBy` the facts that supply it just by a card having them, each with a strength from 1 to 3: a fact supplies an axis when every card with that fact feeds the axis by being played normally, such as every land feeding an axis about lands entering, or every creature feeding an axis about creatures dying. Leave `suppliedBy` empty when no fact supplies the axis on its own; cards that supply it in other ways are tagged in the next pass.
  - `tags-roles-v2.md` is `tags-roles-v1.md`'s text with this sentence added after the enabler and payoff definitions:
    > Each axis's `suppliedBy` facts already count as supply for every card that has them, so tag a card as an enabler only when it supplies the axis beyond its facts, or more strongly than they do.
- **Import checks added:**
  - every `suppliedBy` fact exists in the set;
  - strength is 1, 2 or 3;
  - no fact appears twice on one axis.

  These are three new check classes in the list.
- **Supply in scoring.** For card c and axis x, `F(c, x)` is the largest `suppliedBy` strength on x among c's facts, or 0. Its effective enabler strength is `Ê(c, x) = max(E(c, x), F(c, x))`. The new `FactSupplyTerm` adds, for each axis, `(Ê(a,x) − E(a,x))·P(b,x) + (Ê(b,x) − E(b,x))·P(a,x)`. With SPA-048's axis term, the total is then `Σ Ê(a,x)·P(b,x) + Ê(b,x)·P(a,x)`. The diagonal uses the same formula. A tag file with no `suppliedBy` scores exactly as before.
- **`spa facts --set <code> [--card <name or id>]`** prints each fact with its count, most common first, then by name. The last line gives the pool size and the number of distinct facts. With `--card`, it prints that card's facts, sorted.
- **Pinned numbers** come from an independent script (scratchpad `tools/facts.js`, 2026-11-05).
- Work on a local branch named exactly `SPA-051`. One Developer at a time. Never rewrite a pushed branch; keep scratch files out of the repository. JDK: README, Toolchain section.

## Change note

- **Facts.** `agent/.../facts/`: one `FactRule` per family in its own file, in `FactRules.ALL`; `CardFacts` unions them over the pool, with keywords read as `PoolThemes` reads them. `spa facts` matched every pin on the first run. **Supply.** `Axis.suppliedBy` is optional and absent from v1 files. `FactSupplyTerm` is in `PairTerms.ALL`. A new `PairTerm.forTable` default lets a term bind the table's facts, or return null when no axis has a `suppliedBy` fact; that keeps v1 output byte-identical (`SynergyV1UnchangedTest` pins SHA-256 digests of the ed11e4c outputs).
