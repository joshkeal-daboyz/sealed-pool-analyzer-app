# SPA-037: Commit prompt v2 and the v2 grade files

**Goal.** G-004 deliverable 2 and criterion 4: the prompt the Architect picked from its candidate runs, committed as `prompt-v2.md`, and the v2 grade files for `msh`, `hob`, `fra` and `trk` (with `sds`), imported unchanged from Fable's responses. `trk.v2.json` must be committed before 17Lands publishes any `trk` data.

## How the grading runs (before the Developer starts)

The Architect, as in SPA-034: builds packets with `spa grade-packet <code> --themes --prompt <candidate>`, grades each with one fresh Claude Fable 5.1 agent per set (packet folder only, no other tool), imports into scratch, and runs `spa grade-backtest` for `msh`, `hob`, `fra`. At most three candidates; the one with the best mean `all` rho becomes v2. Then `trk` is graded with v2. Usage before and after each run goes in History.

## Scope

- Files or modules expected to change:
  - `agent/src/main/resources/spa/agent/grader/prompt-v2.md` (new; the Architect's chosen text, verbatim)
  - `fixtures/grades/msh.v2.json`, `hob.v2.json`, `fra.v2.json`, `trk.v2.json` (new), written by `spa grade-import` from the Architect's response folders with provenance naming prompt v2
  - `cli`: `spa grade-backtest --model` already takes a path; add a test that runs it on each v2 file
  - `fixtures/grades/README.md`
- Not in scope:
  - Changing the v1 files, any response file, or the prompt text.

## Acceptance criteria

1. `prompt-v2.md` equals the Architect's chosen candidate byte for byte.
2. Each v2 grade file holds one schema-valid grade per pool card, source `MODEL`, provenance naming prompt v2, and equals a re-import from the Architect's response folder except `createdAt`.
3. `trk.v2.json`'s `createdAt` and the commit date precede the `Last-Modified` of the first 17Lands `trk` game data file (none exists when the ticket is written; the Acceptance Tester checks with `curl -I`).
4. The change note holds `spa grade-backtest` for each of `msh`, `hob`, `fra` with the v2 files. The gate is green.
