# SPA-017: Complete the Pool screen with the file picker, format chooser, and error cards

**Goal.** G-002 deliverable 3, first and third bullets: "Open a CSV with the system file picker" and "Paste text into a box ... The format is detected the way `spa analyze` detects it, with a manual override for the three formats." Also the error half of goal criterion 8 ("An empty file, a file that is not a pool, and a file the app cannot read each show the error state the design spec gives them, and the app does not crash"), and the Pool screen's part of criteria 5 and 7.

The design sections this ticket implements: Pool screen (every state in its table, except "Error: saved pool unreadable", which is SPA-022's), the classification rules under it, Component map ("Pool screen"), and the accessibility items A1, A4, A5, and A6 ("Add your pool") for the Pool states, plus P1 to P4.

## Acceptance criteria

1. Empty state, as the spec gives it. The heading "Add your pool" is a semantics heading (A6), with the line "Open a ManaBox CSV, or paste a list.", the "Open file" button, the "or" divider, the paste box with its hint "ManaBox CSV, a list with counts, or collector numbers", the chooser on "Auto", no detected-format line, and "Analyze pool" disabled. Compose UI test.
2. Detection. With "Auto" selected, pasting a fixture's text shows "Detected: <format name>" for the format its golden's `/pool/format` gives. A test runs every `trk` text and collector fixture and three ManaBox fixtures (`-01`, `-06`, `-wrong-set-01`), reading the expected format from each golden.
3. Manual override. P2: the chips are "Auto", "ManaBox CSV", "List with counts", and "Collector numbers", single choice, each exposing its selected state. Choosing "List with counts" shows "Reading as List with counts (chosen)" and hides the detected line. Analyzing then uses that format: for `trk-collector-01.txt` read as "List with counts", the ViewModel receives format `TEXT`. Tapping "Auto" restores detection. Compose UI tests.
4. The error cards, each above the inputs, with the spec's title and body copy, announced politely (P4, `LiveRegionMode.Polite`):
   - **Empty**: a 0-byte file named `empty.csv` shows "This file is empty" and "empty.csv has no cards in it."
   - **Not a pool**: ten pasted prose lines show "This doesn't look like a pool" and "None of the 10 lines in the pasted text is a trk card." The first 3 lines follow, each with line number, text, and reason words, then "Show all 10 lines", which expands to all 10.
   - **Not a pool, with no lines**: SPA-015 gives `NOT_A_POOL` with no unresolved lines when a ManaBox header lacks a required column. The card then shows "This doesn't look like a pool" and the body "<source> isn't a ManaBox CSV, a list with counts, or a collector-number list.", with no line list and no "Show all" button. The Architect added this copy; the spec states the case only for n of 1 or more.
   - **Wrong set**: the wrong-set CSV built from the fixture shows "This pool is from another set", the spec's body with the file name, and its 2 lines.
   - **Can't read**: a document whose bytes are not UTF-8, or whose stream throws, shows "Couldn't read this file" and its body.
   - **Card data missing**: on `DataMissing`, "Card data is missing", its body, and every input disabled.

   One Compose UI test per card, driven through the ViewModel with the inputs built in the test.
5. After a failed paste import, the pasted text and the chosen format are still in place. After a failed file import, a remembered or current pool is untouched, and back from "New pool" still returns to it (decision 5). A cancelled picker leaves the screen exactly as it was. Compose UI and ViewModel tests.
6. The picker result sets the source to the document's display name, imports through `PoolImporter.importStream`, and logs `import-confirmed`. A Robolectric test with a content URI for `trk-manabox-01.csv` lands on Results with "trk-manabox-01.csv", "Read as ManaBox CSV", and the golden's card and entry counts.
7. Snapshots from the spec's list, each with A1, A4, and A5 run on the same state: `pool_empty`, `pool_empty_fontScale200`, `pool_pasteDetected` (`trk-collector-01.txt` pasted, Auto), and `pool_errorNotAPool` (the ten prose lines). Baselines committed.
8. On `spa-test`, after `adb push fixtures/pools/trk-manabox-01.csv /sdcard/Download/`, "Open file" opens the system picker, and choosing the file shows Results headed "trk-manabox-01.csv", "Read as ManaBox CSV", with the total cards and entries `spa analyze fixtures/pools/trk-manabox-01.csv --set trk` prints. Then, each pushed to `/sdcard/Download/` and opened the same way: a 0-byte `empty.csv`, a `prose.csv` of ten prose lines, and a `binary.csv` holding the bytes of any PNG file. Each shows its error card from criterion 4, and `adb logcat -d` holds no `FATAL EXCEPTION` for `spa.app`. Pasting `trk-collector-01.txt` and choosing "List with counts" shows the result `spa analyze fixtures/pools/trk-collector-01.txt --set trk --format text` gives (header and unread-line count).

## Change note

- Changed: the Pool screen is complete in `app/.../pool/` (`OpenFileButton`, `FormatChooser` with `DetectedFormatLine`, `ImportErrorCard` and `DataMissingCard`, and `ContentFileImporter`, which reads the display name and goes through `PoolImporter.importStream`). `PoolViewModel` adds `analyzeFile`, `chosenFormat`, and `currentPool`, the last successful pool, which a failed import never changes. Four snapshot baselines are recorded, and only those four (`results_loading` is untouched).
- Outside `scope`, because the criteria need the wiring: `nav/SpaNavHost.kt` (the picker route; after a failed import with a current pool, Pool is pushed on top of Results so back returns to it, per criterion 5 and decision 5), and `SpaApplication.kt` and `MainActivity.kt` (they build and pass the `FileImporter`). `SpaTiming` gets a doc line only. `PoolEntryScreen` keeps SPA-016's five-parameter overload, so `A11yChecksTest` is unchanged.
- Choices: the hint is the field's supporting text under the box. A value-based `OutlinedTextField` shows its placeholder only when focused, and `labelPosition` exists only on the state-based field. Reason words for the error card's lines live in `strings_pool.xml` for now; SPA-018's `ReasonText` should replace them. "None of the 1 lines" is not pluralised, because the spec gives one sentence.
- Tests: A1 and A4 run on a `w411dp-h4000dp` surface, because `A11yChecks` measures clipped `boundsInRoot`, which is 0 for nodes scrolled below the 914 dp fold. Captures stay 411 x 914. The picker is faked with an `ActivityResultRegistry`, and documents come from a Robolectric `ContentProvider` (`PoolTestKit.kt`). The test plan had no Order column, so every criterion was read as tests-first, as the template says.
- Not done: criterion 8 (device) is the Acceptance Tester's. I did not run the emulator.
