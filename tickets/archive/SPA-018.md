# SPA-018: Complete the Results screen with problems, metrics, pairs, colours, and fixing, beside the baseline

**Goal.** G-002 deliverable 4: "For the pool: the totals, cards per color, removal and interaction, fixing sources, and for each of the ten color pairs its cards ... each number beside its typical `trk` value from the baseline (median, and the p10 to p90 range). Unresolved lines ... and kit warnings ... are shown before the numbers, never hidden." Per-pair playables are dropped (owner decision, G-002 Architect notes); playables are shown per colour. Also goal criterion 4 for the Results screen, the Results half of criterion 8, and criterion 12's results snapshot at 200 percent.

The design sections this ticket implements: Decisions 2, 3, and 4, Results screen (every section and every state in its table, except "Clear pool dialog open" and the Clear pool button, which are SPA-022's), the reason-words and kit-warning-title tables, Component map ("Results screen", except `ClearPoolDialog`, and the shared names `PairNames`, `ColorNames`, `ReasonText`), and the accessibility items A1, A4, A5, A6, A7, A8, and R1 to R6.

## Acceptance criteria

1. Criterion 4 for Results. For each of the 23 `trk` fixtures (the test asserts the count from the manifest), importing the file through SPA-015's `PoolImporter` and building `ResultsUi` gives displayed values whose pointers are exactly the list in the background (with each pair and colour), each value equal to the golden's value at `/metrics` plus the pointer, and each typical median, p10, and p90 equal to `fixtures/baselines/trk.json`'s `stats` at the pointer. Every expected value is read from the files.
2. Rendering. For `trk-manabox-01.csv`, every displayed value in `ResultsUi` appears on the screen. A Compose UI test walks the model and finds each value's row text, scrolling as needed. R2: the Removal row is one merged semantics node whose text holds "Removal", the value, and "typical <median> (<p10>–<p90>)", read from the files.
3. Problems. Clean pool: the one line "Every line read. Kit check passed." With unresolved lines: "<n> lines not read. The numbers below leave them out.", then each line as "Line <line>", the full text in Atkinson Hyperlegible Mono (never cut), and the reason in words with the code, as in the spec's table. With kit warnings: the title from the spec's table, "<actual>, expected <min> to <max>", and the engine's message verbatim. With at least one `wrong-set` line and some entries resolved: the extra line "Some cards are from another set. This app reads trk and its sds bonus sheet only." With more than 5 items: a "Skip to numbers" button that scrolls to Pool at a glance (a test-built pool with 6 misspelled lines). Compose UI tests on `trk-manabox-01.csv`, `trk-text-misspelled-01.txt`, `trk-manabox-wrong-set-01.csv`, and `trk-collector-bad-number-01.txt`, with the expected lines read from the goldens.
4. R1: for `trk-text-misspelled-01.txt`, every unresolved-line and kit-warning node comes before the first `MetricRow` node in the semantics tree's traversal order.
5. Legend: "Typical: the median of 2000 simulated trk pools, with the middle 80% (10th to 90th percentile).", with 2000 read from the baseline's `kits`. A7: every value outside its p10 to p90 range has "below typical" or "above typical" in its merged node. For `trk-manabox-01.csv`, Fixing sources is below typical and Blue cards above, as computed from the files in the test.
6. Pairs. R3: ten pair rows, sorted as the spec says, under "Sorted by cards in the pair". Each row is one button whose text holds the pair name (such as "White–Blue (WU)"), its cards line, and its creatures line, each with its typical value. Tapping a row navigates to `pair/<pair>`. The test checks `trk-manabox-01.csv`'s order against the order computed from its golden.
7. Colours. R4: seven rows in the order White, Blue, Black, Red, Green, Multicolour, Colourless. Collapsed, a row shows "Cards <total>, typical ..." and "Playables <total>, typical ...", with state description "Collapsed". After a tap, "Expanded", and it adds creatures, removal, interaction, and cards and playables by rarity, each with its typical value.
8. Fixing sources: one line per source, with the name, its colours as names, and the count only when above 1, or "No fixing sources" when the list is empty (a test-built pool).
9. A6: "Problems", "Pool at a glance", "Colour pairs", "Cards per colour", and "Fixing sources" are semantics headings. R6: at font scale 2.0 with `trk-manabox-wrong-set-01.csv`, each unresolved line's full text is present and no text reports visual overflow.
10. Snapshots from the spec's list, with A1, A4, and A5 run on the same state: `results_clean` (`trk-manabox-01.csv`), `results_clean_fontScale200`, `results_problems` (`trk-text-misspelled-01.txt`), `results_problems_fontScale200`, and `results_wrongSetLines` (`trk-manabox-wrong-set-01.csv`). Whole scrollable content where the library allows; the change note says which. Baselines committed.
11. On `spa-test`, for `trk-manabox-01.csv`, `trk-manabox-06.csv`, and `trk-manabox-10.csv`, pushed to `/sdcard/Download/` and opened with "Open file", Results shows the total cards, entries, unresolved count, removal total, interaction total, and each pair's creature count that `spa analyze <file> --set trk` prints. For pasted `trk-text-misspelled-01.txt` and `trk-collector-bad-number-01.txt`, and the opened `trk-manabox-wrong-set-01.csv`, every unresolved line `spa analyze` prints appears with its line number, text, and reason before any metric. A8: with TalkBack on, swiping through Results for the pasted `trk-text-misspelled-01.txt` reads the problem summary before any metric, and reads each metric row as one item.
