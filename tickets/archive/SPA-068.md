# SPA-068: The Explainer - prompt, answer schema, checks, runner

**Goal.** G-006 deliverable 7: "The Explainer. One call that reads every surviving finding and the builder's top three decks and writes the verdict, a short note per deck, and a list of disagreements between agents (each naming at least two agents and at least one card), validated the same way. The Judge's ranking is the builder's deck score; the Explainer restates it and does not reorder it."

- Files or modules expected to change: new `agent/src/main/kotlin/spa/agent/review/` files `Explainer.kt`, `ExplainerAnswer.kt`, `ExplainerChecker.kt`; a shared helper extracted from `AgentRunner.kt` (see below); resources `agent/src/main/resources/spa/agent/review/explainer-v1.md` and `explainer-schema-v1.md`; tests in `agent/src/test/kotlin/spa/agent/review/`.
- Not in scope: building the deck summaries or the review (SPA-069), the CLI (SPA-070), the analysts, `core`, `fixtures/agents/review.json` (its `explainer` entry exists from SPA-064).
- Dependencies this ticket may add: none.

- Design this ticket fixes (do not redesign):
  - **Prompt** (`explainer-v1.md`, the file's text must equal this exactly, ending with one newline):

    ```
    You are the Explainer for a team of specialists who reviewed a Magic: The Gathering limited card pool for a player. You are given the three best decks that code built from the pool, ranked by code, and the specialists' findings. Write the review's summary for the player.

    Rules:
    1. Do not change the ranking. The decks are ranked by a score that code computed. Explain it; do not reorder or replace a deck.
    2. Restate, do not invent. Every claim you make rests on a finding you were given or on the decks as printed. Do not add numbers; if you quote one, copy it from a finding.
    3. Cite cards. Every note names the pool cards it is about, by their exact names. A note with no card, or a card not in the pool, is thrown away.
    4. The verdict is for a player at a table: say which deck to register and why, in at most four sentences, then the one or two things to watch.
    5. Report disagreements. When two specialists' findings pull against each other (one wants a color, another says it is thin), list the disagreement with both agents' ids, the cards involved and what decides it. Do not average them away. If there is no disagreement, return an empty list.
    6. Answer with one JSON object and nothing else, in the schema below.
    ```

  - **Schema text** (`explainer-schema-v1.md`, exact, ending with one newline):

    ```
    Answer with one JSON object and nothing else:
    {
      "confidence": <number from 0 to 1>,
      "verdict": "<at most four sentences>",
      "decks": [ { "rank": <1, 2 or 3>, "note": "<one or two sentences>", "cards": ["<exact card name>", ...] } ],
      "disagreements": [ { "topic": "<short>", "agents": ["<agent id>", "<agent id>"], "cards": ["<exact card name>", ...], "note": "<one or two sentences>" } ]
    }
    ```

  - **Request** (`Explainer.request(input, decksText, outcomes, config)`): `model` from the config, `maxTokens` = `explainer.maxTokens`, `label` `explainer`, `cachedContext` = the bundle text, `system` = the prompt file text, a blank line, the schema text (trailing newlines trimmed before joining), and `userMessage` = `## Decks` newline, `decksText` (given, plain text, the decks as the review will print them), a blank line, `## Findings`, then for each `Answered` outcome in order a blank line and `### <title> (<id>, confidence <0.00>)`, its summary, and one line per kept finding: `- [<severity>] <pair or ->: <claim> | cards: <names joined by "; "> | numbers: <key>=<value> (typical median <m>)` (the `numbers:` part and each `(typical ...)` only when present; values as `NumberTable` prints them), then a blank line and `Answer with the JSON object only.` An agent with no kept finding prints its heading and summary and `- no findings kept`. `Missing` outcomes are not mentioned.
  - **Checks** (`ExplainerChecker.check(text, pool names, deck ranks, answered agent ids)`): same tolerance and strictness as `AnswerChecker` (outermost braces, no unknown key, no missing field, wrong type or `confidence` outside 0 to 1 is a `SchemaError` naming the field); an empty `verdict` is a `SchemaError`. Item rules, which drop the item and count it with a reason instead of failing the answer: a deck note is dropped when its `rank` is not one of `deck ranks` (`UNKNOWN_RANK`), repeats an earlier rank (`DUPLICATE_RANK`), has no card (`NO_CARD`) or a card not in the pool (`UNKNOWN_CARD`); a disagreement is dropped when it names fewer than two distinct agents, or an agent id not in `answered agent ids` (`UNKNOWN_AGENT`), or has no card (`NO_CARD`), or a card not in the pool (`UNKNOWN_CARD`). Card names are matched as in `AnswerChecker` (full name or front-face name, exact).
  - **Runner** (`Explainer.run(client, config, input, decksText, outcomes, deckRanks)`): returns `ExplainerOutcome`: `Explained(result, dropped)` or `Missing(reason)`. It does not call the model, and returns `Missing("no findings to explain")`, when no outcome is `Answered` with at least one kept finding; it returns `Missing("switched off in the config")` when `explainer.enabled` is false. Otherwise it has the same retry (labels `explainer-retry1`, ...), `BudgetExceededException`, timeout and error rules as `AgentRunner`, with `Missing` reasons worded the same. Extract the shared call, retry, timeout and error code from `AgentRunner` into one internal helper both use; behaviour and every SPA-064 test stay unchanged.

## Acceptance criteria

1. `explainer-v1.md` and `explainer-schema-v1.md` equal the texts above exactly.
2. `Explainer.request` gives the request described, for outcomes holding an answered agent with two findings (one with a `typical`, one without numbers), an answered agent with no kept finding, and a missing agent (not mentioned).
3. `ExplainerChecker` accepts a valid answer, also inside a code fence; each schema fault (not JSON, unknown key, missing field, wrong type, confidence 1.5, empty verdict) is a `SchemaError` naming the field.
4. Each item drop reason fires on its own case and is counted, and a kept item is unchanged; a deck note with a front-face name of a multi-face pool card is kept and becomes the full name.
5. The runner returns `Missing("no findings to explain")` with no call when every analyst is `Missing` or has no kept finding, and `Missing("switched off in the config")` with no call when disabled.
6. Retry, budget, timeout and error cases give the same `Missing` wording as `AgentRunner`'s (`invalid answer: ...`, the budget message, `timed out after <n>s`, `error: ...`), and the retry request has the label `explainer-retry1` and the rejection sentence of SPA-064.
7. The Explainer's request has the same `cachedContext` as an analyst's for the same input.
8. Every SPA-064 test passes unchanged.
9. The gate is green: format, lint, compile, unit tests, coverage 80 or more on the touched files, no new dependency.

## Change note

Added `Explainer` (request, run), `ExplainerChecker`, `ExplainerAnswer` (result, drop and outcome types) and the two prompt resources; all criteria are tests-first except 8 and 9. The call, retry, timeout and error code of `AgentRunner` moved unchanged into the internal `ModelCalls`, which both runners use; `AgentRunnerTest` is untouched and green.

Outside the listed files, minimally: `AnswerChecker`'s private name matcher became the internal `PoolNames` (shared), `NumberTable`'s `format` and `AgentRequests.resource` became `internal`. No behaviour changed.
Everything is unit tested; nothing needs a device, the network or a model.
