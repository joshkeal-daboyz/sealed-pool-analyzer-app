# SPA-045: Try every colour configuration, rank the decks, and print them with spa build

**Goal.** G-005 deliverables 3 and 5, and criteria 3 and 4 over every configuration. SPA-044 builds the best deck for one given set of colours. This ticket tries every configuration a pool supports, ranks the decks by score, and makes `spa build` print the top few, so a three-colour deck wins when the pairs are weak and the fixing is there. SPA-046 measures and tunes it.

## Background the Developer needs

- **Files to read** (nothing else in the repository): `agent/src/main/kotlin/spa/agent/build/` (`BuildConfig`, `BuildSetup`, `DeckBuilder`, `DeckWeights`, `DeckPart`, `Deck`), `cli/src/main/kotlin/spa/cli/` (`BuildCommand`, `BuildSession`, `BuildLines`, `Main.kt`), `agent/src/main/kotlin/spa/agent/fixing/FixingClassifier.kt`, `agent/src/test/kotlin/spa/agent/build/BuildTestCards.kt` and `cli/src/test/kotlin/spa/cli/BuildLegalityTest.kt` (how SPA-044 tests legality), `fixtures/weights/README.md`, `fixtures/pools/README.md`, `fixtures/pools/manifest.json`.
- **What SPA-044 gave you (merged).** `BuildConfig` is the main colours plus up to two splash colours, written `<main>[/<splash>]` (`WU`, `WU/R`, `WUB`); `BuildConfig.parse`. `BuildSession` loads a set once (card index, grades, deck weights, synergy table when its weight is above 0); `session.setup(pool, config)` gives a `BuildSetup`; `session.builder.build(setup)` gives the best `ScoredDeck`, or null when the pool has too few candidates. The land count follows the land rule except when the pool can fill only 22 or 23 spells in those colours; the builder then raises it to what the pool can fill. `spa build <pool> --set <code> --colours <cfg>` prints one deck: a heading with the colours, the score and each part's value; the spells by mana value, each with its grade and a reason; the lands; the sideboard. Deck weights are `fixtures/weights/deck-default.json`: `weights`, `params`, `lands`, `splash`, strict, an unknown key an error naming it.
- **Quoted from the goal (G-005).**
  - Deliverable 3: "**Colour configurations.** The builder tries every two-colour pair; every pair with a splash of one or two colours; every three-colour set; and four-colour sets when the pool's fixing supports them. It ranks the resulting decks by score, so a three-colour deck wins when the pairs are weak and the fixing is there."
  - Deliverable 5: "**`spa build <pool-file> --set <code> [--colours <WUB>] [--top <n>]`.** It prints the ranked decks, three by default. Each deck shows its colours (main and splash), its 40 cards by mana value, its land split and fixing, its score broken into parts, and its sideboard. Each card has a short reason (its grade, plus anything the curve, creature count, removal, castability or fixing added)."
  - Criterion 3: "**Legal decks.** Every deck the builder emits has exactly 40 cards, only pool cards plus basics, and no card above its pool quantity. Property tests check this over every fixture pool and every colour configuration." Criterion 4: "**Explained.** Each deck's printed score equals the sum of its listed parts, and every card line has a reason. A test checks this over every line `spa build` prints for the trk sample pool."
  - Constraints: every weight, threshold and cutoff comes from the versioned JSON file under `fixtures/weights/`, selectable with `--weights`, never a constant in code; "Adding, removing or reordering a part touches the list and the part's own file, nothing else." Configuration rules follow the same shape: a small interface, one file each, a list.
  - "Every set is different": "`hob` builds are mostly two colours and `fra` builds are often three; the builder must learn that from the pools, not from a set flag." So no rule here may mention a set.
- **The configurations.** Each is a `ConfigRule` (a small interface, one file each, listed in `ConfigRules.ALL`) that gives the configurations for a pool, with its parameters from a new `configs` section of the deck weights file. The five rules and their defaults:
  - `pairs`: the 10 two-colour pairs, no splash.
  - `pairSplash`: each pair with 1 splash colour (30) and, when `maxSplashColours` is 2, with 2 splash colours (30). Default `maxSplashColours` 2.
  - `triples`: the 10 three-colour sets as main colours, no splash, and each with 1 splash colour (20). Default `tripleSplash` true.
  - `fourColour`: the 5 four-colour sets as main colours, only when the pool holds at least `minFixing` cards (lands or spells) that `FixingClassifier` says supply two or more of that set's colours. Default `minFixing` 4.
  - A rule with `"enabled": false` gives nothing. Configurations that two rules give are listed once.
- **The ranking.** Build every configuration with `session.builder.build`; drop the null ones. Sort by total score, highest first; ties by the configuration text. Two configurations that give the same 40 cards (the same copies of the same cards) are one deck: keep the higher-scoring configuration's, and the printout names the other as "same cards as ...".

## Acceptance criteria

1. **Configurations.** With the default weights, on a hand-built pool with no fixing, the rules give 10 pairs, 60 pair-splash configurations, 30 triple configurations and no four-colour set, 100 in all, each once. With 4 hand-built fixing cards that each supply two of W, U, B and R, `WUBR` is also given, and no other four-colour set is. Setting `maxSplashColours` to 1 removes the 30 two-splash configurations; `"enabled": false` on a rule removes its configurations; an unknown key in `configs` is an error naming it. A test-only rule added to `ConfigRules.ALL` adds its configuration with no other code change.
2. **Ranking.** Hand-built tests pin:
   - decks come out sorted by score, ties by configuration text;
   - a configuration with too few candidates is left out;
   - two configurations with the same 40 cards give one deck, the higher-scoring one;
   - the top deck is a pair on a pool where one pair is clearly strongest, and a three-colour deck on a hand-built pool where every pair is weak (too few playable cards) and a fixing land makes the three colours playable.
3. **`spa build` ranks.** `spa build <pool> --set trk` without `--colours` prints the top 3 decks, each headed with its rank and configuration, each in SPA-044's per-deck format. `--top 5` prints 5 and `--top 1` prints 1; `--top` of 0, a negative or a non-number is one line, exit 1. With `--colours`, it builds that one configuration as SPA-044 does, and `--top` is ignored. If no configuration can be built, one line, exit 1.
4. **Legal** (G-005 criterion 3). A property test over `fixtures/pools/trk-manabox-01.csv`, `-02.csv` and `-03.csv` builds every configuration the rules give for each and checks every deck as SPA-044's legality test does (40 cards, only pool cards and basics, no card above its quantity, splash limits, the land rule or the pool-capacity exception).
5. **Explained** (G-005 criterion 4). For every `trk` pool in `fixtures/pools/manifest.json` whose `expectedUnresolved` is empty, a test runs `spa build <pool> --set trk` and checks each printed deck's part values add to its printed score within 0.005 and every spell line has a reason.
6. **The seam, and no change elsewhere.** `git diff 2962b0f -- core/src/main fixtures/golden` lists no file. Every SPA-044 test passes unchanged. The gate is green.
7. **Time.** The change note records the seconds `spa build fixtures/pools/trk-manabox-01.csv --set trk` takes on this PC (G-005 reports it at goal close). No test asserts it except on CI, where a test asserts it is under 60 seconds.

## Change note

- Added `ConfigRule` (one file each: `PairsConfigRule`, `PairSplashConfigRule`, `TriplesConfigRule`, `FourColourConfigRule`, listed in `ConfigRules.ALL`), a `configs` section in `DeckWeights` (optional; a rule missing from it is off, `enabled` defaults true, unknown or missing keys are errors naming them) and `DeckRanking` (build each configuration, sort by score then colours text, merge decks with the same 40 cards, naming the others in `RankedDeck.sameAs`). `BuildSession` gained `candidates`, `setup(candidates, config)`, `configs`, `rank`; `spa build` without `--colours` prints `Rank n: <colours>` then the SPA-044 deck lines; `--top` is validated only without `--colours`.
- Two edits outside the listed scope or to SPA-044 files: `BuildConfig.MAX_SPLASH` is now public and `Fields` in `DeckWeights.kt` is `internal`, so the rules can use them. SPA-044's `BuildCommandTest` lost its one assertion that a missing `--colours` is an error (criterion 3 makes it optional; the test is renamed `a bad colours option ...`); every other SPA-044 test is unchanged. `fourColour` counts copies, not distinct cards. Not unit testable: nothing.
- Time (criterion 7): `spa build fixtures/pools/trk-manabox-01.csv --set trk` takes 5.2 s wall clock on this PC (installDist build, 100+ configurations). The CI-only assertion (under 60 s) is in `BuildRankCommandTest`.
- For SPA-046: on trk-01 the default weights rank `WUB/G` first, probably because the `fixing` part pays `(k - 2)` for the colours the config names; a config that names an extra colour can score more through that part alone (not checked card by card). Configurations with the same 40 cards are merged only after scoring, so such a config can win its group. Tune or fix in the part, not in the ranking.
