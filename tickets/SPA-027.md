# SPA-027: Escape closing braces in core's regexes so they compile on Android

**Approved by the owner on 2026-11-04.** This is a `core` source change beyond SPA-014's, which G-002's constraints send to the owner. The owner approved it in chat.

**Goal.** G-002 deliverable 2 and every criterion that imports a pool on the device (5 to 8, 13, 14, 16). On Android, `core`'s mana-symbol regex `\{([^{}]*)}` fails to compile: Android's ICU regex engine throws `PatternSyntaxException: Syntax error in regexp pattern near index 11`, rejecting the unescaped closing `}` that the JVM accepts. So `MetricEngine.compute` fails on the device (`ExceptionInInitializerError` at `RulesTagger.tag`, RulesTagger.kt:120). SPA-026's Developer found it on `spa-test`. A scratch escape of `}` in three patterns made the full on-device import pass.

A JVM unit test in `core` scans every `Regex(...)` and `toRegex()` string literal under `core/src/main/kotlin` and fails, naming the file and line, if one contains an unescaped `}` outside a character class. This keeps the next such pattern from reaching the device. It passes on the fixed sources, and it fails on a scratch unescaped pattern.

## Change note

- The closing `}` of the three mana-symbol patterns is escaped as `\\}` in the Kotlin literal; nothing else under `core/src/main` changed, and `fixtures/golden` is unchanged against 077e588.
- `core/src/test/kotlin/spa/core/text/RegexBraceGuardTest.kt` holds the guard (criterion 3) and the scanner it uses. It reads `src/main/kotlin` relative to the test's working directory (the `core` project dir), so no build-file change was needed. It scans `Regex(` and `"...".toRegex()` literals (plain and raw, joined by `+`), skips `${...}` templates, and allows `}` inside a class or closing a `{n}`, `{n,}`, `{n,m}` quantifier. Its own tests cover a scratch unescaped pattern.
- Not scanned: patterns built through a helper from non-literal values, such as `RulesTagger.rx(pattern)`; the literals passed to `rx(...)` hold no `}` today besides template closers. A lone unescaped `{` is not flagged either; the criterion names only `}`.
- `importsTheManaBoxFixture` is restored verbatim from before 9b95f6b; criterion 1 needs a device, so it runs only under `connectedDebugAndroidTest`, not in the gate.
